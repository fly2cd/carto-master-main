## 一、为什么必须拆分

当前 U-P2 同时包含：协议补齐、地图表达目录、模板草稿创建、模板验证与发布、地图规划、真实 MapLibre 渲染、受控浏览器、候选预览和实例冻结。若一次实现，会同时改变 Schema、工作流、仓库事务、渲染环境和审批边界，难以定位失败，也会导致未验证能力被过早开放。

因此 U-P2 拆成八个串行子阶段：

```text
U-P2.0 范围冻结
  → U-P2.1 协议与资源目录
  → U-P2.2 MapScenario 草稿创建
  → U-P2.3 确定性渲染底座
  → U-P2.4 模板校验与发布
  → U-P2.5 地图规划与候选编译
  → U-P2.6 候选预览与实例冻结
  → U-P2.7 集成收口与阶段验收
```

### 实施纪律

1. 一次只实现一个子阶段，前一阶段验收通过后才能进入下一阶段。
2. 每个子阶段独立提交，不能把后续阶段代码顺带放入当前提交。
3. 可以定义下一阶段所需的窄接口，但不能写伪成功实现、临时绕过门禁或自动降级分支。
4. 新协议必须同时提供合法样例、非法样例和自动测试，未知字段默认拒绝。
5. 每个阶段结束都运行全量回归；不能仅运行新增测试。
6. 任何真实浏览器、字体、WebGL 或导出环境未验证时，对应阶段保持未完成，不能用 mock 冒充真实通过。
7. 本计划不修改 `skills/ppt-master/`，不在仓库根目录创建第二套代码或测试目录。

## 二、U-P2 固定范围

### 2.1 本阶段开放范围

- 模板 kind 保持四种：`map-brand`、`map-style`、`map-layout`、`map-scenario`。
- 业务创建只开放首个 `map-scenario` 作者策略。
- Brand、Style、Layout 在 U-P2 只完成协议、所有权和组合边界测试，业务路由仍返回明确的能力未开放错误。
- 首个场景使用合成洪涝风险数据和合成避难场所数据，不使用真实应急敏感坐标。
- 首个地图表达必须包括：
  - `choropleth/sequential`：风险面顺序分级设色；
  - `proportional-symbol/count`：避难场所容量的面积比例符号。
- `point-symbol/shelter` 是符号资源，不是独立地图表达，也不是模板类型。
- 点密度、分级符号、流向、等值线、热力图等可以保留协议扩展位，但不实现、不注册为 U-P2 正式能力。
- 输出到不可变 `MapSpecLock` 为止；正式成品检查、G3、交付事务和三场景扩展属于后续阶段。

### 2.2 地图表达目录的定位

`map-types/`、`symbols/`、`standards/` 可以物理位于模板资源根下，但逻辑上不是第五种模板。地图表达目录项由 Scenario 的 `portrayal` 契约按精确版本引用。

表达目录项只允许声明：

- 适用条件与禁用条件；
- 所需数据角色、几何和字段语义；
- 参数 Schema；
- 数据到视觉变量的映射；
- 图例、缺失值、异常值和边界规则；
- 检查器引用与合成 Fixture。

表达目录项不得包含任意 Python、Shell、SQL、浏览器脚本或动态表达式执行代码。算法实现在受信代码中，目录项只选择版本化能力和参数。

### 2.3 首个数据与输出边界

U-P2.0 已冻结实际来源格式：请求和元数据使用安全解析的 YAML/JSON，业务数据使用 GeoJSON 和 UTF-8 CSV。GeoPackage、QGIS 工程及其他 GIS/文档格式不进入 U-P2；它们不能仅因出现在通用 Schema 枚举中就被声明为已支持。

首个输出为 420 × 297 mm 的 A3 横版工程预览，派生 SVG、PDF 和 PNG。地图主体允许以确定性栅格图像嵌入 SVG，页面 overlay 可保持矢量；PDF 只声明工程预览，不宣称全矢量 PDF。

## 八、U-P2.5：地图规划与候选编译

### 目标

实现地图生成从请求接入到确定性候选，不执行预览、不冻结。

### 工作项

1. 复用 IntentResolver 完成 intake，生成制图简报与模板候选。
2. G1 只批准本次业务简报、数据访问、模板版本和允许能力。
3. 将已发布模板安装到项目私有目录并固定全部摘要。
4. 绑定风险区域和避难场所数据角色，产出 PreparedDataBundle。
5. MapPlanner 组织模板、数据、知识、空间和交付决定。
6. MapComposer 只提交类型化图面参数修订，不成为第二个编译器。
7. compiler 一次解析六契约、地图表达引用和项目决定。
8. 输出 `MapPlan`、`ResolvedMap` 与 `RenderScene`。
9. 实际范围、分类断点、数据摘要和环境要求只进入候选，不回写模板。

## 九、U-P2.6：候选预览与实例冻结

### 目标

渲染候选、完成独立检查和精确 G2，并由编译器生成不可变 MapSpecLock。

### 工作项

1. 提交候选 RenderScene，保存预览产物与 RenderReceipt。
2. 执行数据语义、空间范围、表达、图例、布局容量、资源和环境检查。
3. 按修复所有者退回模板、数据、计划或适配器层，校验器不得静默改语义。
4. G2 绑定 candidate digest、execution digest、preview evidence、项目、作用域和环境。
5. compiler 根据已批准候选构造 MapSpecLock；模型不能直接写锁。
6. 锁采用 create-once 语义；模板、数据、断点、目标或环境变化产生新候选和新锁。
7. 冻结后不再调用模型选择事实或设计参数。

### 退出门槛

- [x] 地图生成从接入到冻结使用合成数据全链路运行。
- [x] 预览与锁绑定同一 execution digest。
- [x] G2 上下文任一变化均拒绝冻结。
- [x] MapSpecLock 与候选 execution snapshot 完全一致。
- [x] 旧锁不可修改。
- [x] 本阶段没有 G3、正式交付或外部发布。

### 建议提交

`U-P2.6: 实现候选预览与实例冻结`

## 十二、U-P2 与后续阶段边界

U-P2 结束时允许声明：

- 首个合成洪涝 MapScenario 可以创建、验证并发布；
- 合成项目数据可以生成候选预览并冻结实例锁；
- 受控 MapLibre Web 渲染环境可以产生可验证回执。

U-P2 结束时仍不得声明：

- 已具备真实洪涝研判或指挥决策能力；
- 三类业务场景已经覆盖；
- 点密度、流向、等值线等地图表达已经可用；
- 已支持完整 QGIS/ArcGIS 工程；
- 已支持矢量 PDF、公开 Web 发布、正式交付或原生 GIS 编辑；
- Brand、Style、Layout 的业务创建路由已经开放。

U-P3 才负责基于 U-P2 锁定产物完成首个纵向工程闭环、正式成品检查、交付、恢复和修复边界验证。
