## 0. 文档定位与证据约定

本文站在**目标视角（点/线/面全要素制图）**，对照三个业务场景（标准专题图 / 海报地图 / 领导调研用图）的目标，列举当前实现的缺口，并给出按"共享底座优先"排序的补齐路线图。

**证据分级**（全文标注）：

- 【源码事实】：以 `skills/carto-agent/` 下代码、Schema、策略为据，标注文件与行号。
- 【目标设计】：以 `doc/` 下设计文档为据（三份场景说明、总体流程、ADR-001、design-principles、map-style、map-expression-and-symbol-design）。
- 【设计推断】：基于上述两者的排序、依赖与杠杆判断，可证伪。

**两条基准**（贯穿全文）：

1. **目标视角，不以当前代码能力为门槛**：点/线/面全要素都是要支持的能力。
2. **只补制图能力，不补空间分析**：判据取自 [`data-preparation-policy.yaml`](../skills/carto-agent/policies/data-preparation-policy.yaml) 的 `allowed_operations: [read, filter, join, reproject, aggregate, classify]`。凡需派生新几何或空间运算（buffer/KDE/等值线/cartogram/流向OD/地形/栅格代数/overlay/dasymetric/栅格矢量化/点密度）一律排除，不在本路线图范围。

## 1. 坐标系对齐

【源码事实】主流程 CLI 链完整存在（[`cli.py` L151-199](../skills/carto-agent/scripts/carto_core/cli.py)）：

```
intake → brief →〔G1〕→ compile → preview →〔G2〕→ freeze
       → render → check → review →〔G3〕→ deliver
       （+ revise / revision-brief / retry / status / receipts / delivery-status）
```

【源码事实】但**业务场景只准入 1 个**：`general_thematic_mapping` 的受限分类栅格链（[`scenario-capabilities.yaml`](../skills/carto-agent/policies/scenario-capabilities.yaml)，`production_enabled: false`）。海报、领导调研两场景**目标已设计、执行层未准入**（领导调研说明 L329、海报说明 L634 均自述"当前不是已完成的三场景系统"）。

因此缺口分两类：**流程骨架的机制缺口**（三场景共享）+ **场景能力面缺口**（各自专属）。

## 2. 统一正交维度框架

【设计推断，对齐四轴分解原则】为避免"三场景各用一套维度、横向不可比"的方法论缺陷，全文采用一套贯穿三场景的正交维度：

- **M 流程机制层（编排）**：M1 设计迭代循环 / M2 增量修订·失效传播 / M3 审图·审查强制绑定 / M4 无模板·项目内设计路径 / M5 自动模板检索 / M6 受约束优化·自动布局求解

- **G 治理层**：G1 外部服务准入 / G2 安全与披露

## 6. 最小可验证纵切

【设计推断】**W1 → W2 → W3**：三步即把"标准专题图"从受限栅格升级为具备线/注记的多候选可迭代场景，同时为海报/调研铺好共享底座。每步都可在现有准入链上独立验收，不需等待场景专属能力。

---

## 7. 边界红线

1. **外部服务（求路/地理编码）不由制图执行层补齐**：属网络分析/外部 GIS 服务，走 G1 独立准入；制图侧只渲染已核验的路线几何（走 E1a 线要素），不实现路径计算。
2. **空间分析排除**：点密度/KDE/等值线/cartogram/流向OD/地形/栅格代数/overlay/dasymetric/栅格矢量化不在本路线图（见 §0 基准 2）。
3. **不通过文档扩张能力**：不新增顶层路由、场景专用锁、审批旁路；不把矢量候选代码/表达目录存在解释为正式准入；不改生产标志绕过门禁。
