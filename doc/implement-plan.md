本计划将架构文档的 A–E 落地顺序、模板创建 TRD 的 P0–P8 阶段和地图生成 TRD 的 GM-P0 至 GM-P6 阶段合并为统一的实施路线。实施时以最新版 TRD 为准；本文不建立第二套执行规范。

## 一、实施总览

### 1.1 核心原则

1. **协议先行，代码后行**：Schema、契约格式、状态模型和审批协议在编码前对齐，不并行两套运行协议。
2. **共享内核，独立路由**：两条主路由共享五模块内核，各自拥有独立作业、审批和产物生命周期。
3. **纵向打通优先**：先以洪涝场景完成一条最小但完整的创建、生成、冻结、检查和交付链路，再扩展作者策略、来源格式与三类业务场景；协议完整不等于首个切片必须实现全部宽度。
4. **模型建议，程序执行**：模型输出是有证据的候选决定，数值统计、空间计算和门禁由确定性程序控制。
5. **借鉴 PPT Master 成熟模式**：分段所有权、惰性加载、确认门机制和模板生命周期管理复用 PPT Master 已验证的设计模式，但不照搬 PPT 特有的执行自由度。
6. **不预先建设全套微服务**：以模块和接口隔离变化，按实际瓶颈扩容。
7. **演示证据与生产证据分离**：合成数据负责可重复边界测试，真实或经批准脱敏的业务数据负责生产适用性验收；演示闭环不能被表述为生产能力已通过。

### 1.2 统一阶段映射

| 统一阶段 | 名称 | 架构文档 | 模板创建 TRD | 地图生成 TRD | 核心目标 |
|---|---|---|---|---|---|
| U-P0 | 规范收敛与安全底座 | A（前半） | P0 | GM-P0 | 对齐 Schema、契约、命名和审批协议 |
| U-P1 | 内核骨架与协议层 | A（后半） | P1 | GM-P1 | 五模块骨架、状态机、工具网关和知识服务 |
| U-P2 | 首个模板与生成最小内核 | B（前半） | P2–P3 | GM-P2–GM-P3 | 围绕首个场景完成编译器、校验器、QGIS 预览和冻结 |
| U-P3 | 首个纵向工程闭环 | B（后半） | P4–P6（部分） | GM-P4（部分） | 洪涝演示场景从创建到交付全链路打通并可恢复 |
| U-P4 | 三场景业务与生产闭环 | C | P4–P6（续） | GM-P4 | 政务、应急、调研三场景验收 |
| U-P5 | 复杂数据、连接器与共享部署 | D | P7（部分） | GM-P5（部分） | 按独立触发条件推进数据子智能体、企业连接器和共享部署 |
| U-P6 | 新媒介与新路由 | E | P7–P8 | GM-P5–GM-P6 | 图册、Web、移动端、编辑和目录治理 |

阶段顺序可按业务数据和部署目标调整：如果首期数据只能通过企业 MCP 获取，则必要连接器属于 U-P4 或更早；如果首期即为多人企业共享服务，则共享部署底座必须在 U-P4 上线门槛前完成。数据子智能体只有在固定流程确实不足且评估证明有收益时启用，不作为共享部署或企业连接器的前置条件。

## 二、U-P0：规范收敛与安全底座

### 2.1 目标

统一三份设计文档的 Schema、命名、契约格式和审批协议，建立安全底座和仓库治理规则，确保后续编码不产生并行旧模型。

### 2.2 前置依赖

- 三份设计文档（架构、模板创建 TRD、地图生成 TRD）已定稿。
- 仓库治理规则已确认 Carto 入口和测试位置。

### 2.3 工作内容

#### 2.3.1 规范对齐

| 任务 | 说明 |
|---|---|
| 四类模板命名对齐 | `map-brand`/`map-style`/`map-layout`/`map-scenario`；中文固定为"地图身份模板"/"制图表达规范"/"地图版式模板"/"制图场景方案" |
| 六契约对齐 | `scenario.yaml`/`data.schema.yaml`/`spatial-behavior.yaml`/`portrayal.yaml`/`delivery.yaml`/`quality-gates.yaml`；共九种业务契约文件类型 |
| 规则标签对齐 | `hard_rule`/`forbidden`/`mandatory`/`binding`/`default`/`reference` 六种语义，不作为数值优先级 |
| 结果严重度对齐 | `blocker`/`error`/`warning`/`info` 四种，与规则标签正交 |
| 状态模型对齐 | 作业状态 `pending/running/waiting_approval/failed/succeeded/cancelled`；包生命周期 `draft/validated/published` |
| 目录结构对齐 | 模板库 `templates/<kind-dir>/<id>/<version>/`；项目 `projects/<project-id>/carto/` |
| 旧稿迁移规则 | 旧 `map_lock.yaml`、八契约清单、规则优先级和动态加载图以 TRD 为准，不并行支持 |

#### 2.3.2 共享 Schema 定义

编写以下 Schema 草案（目录 `schemas/`）：

```
manifest.schema.json          # 模板包清单
identity.schema.json          # MapBrand 契约
cartography.schema.json      # MapStyle 契约
layout.schema.json            # MapLayout 契约
scenario.schema.json         # MapScenario 场景合同
data-role.schema.json        # 数据角色
  spatial-behavior.schema.json # 空间行为
portrayal.schema.json        # 图层与表达
delivery.schema.json         # 交付配置
quality-gates.schema.json    # 质量门禁
map-spec-lock.schema.json    # 实例锁（共享，不创建第二个版本）
map-plan.schema.json         # 地图计划
map-intent.schema.json       # 意图
map-brief.schema.json        # 简报
generate-request.schema.json # 生成请求
delivery-manifest.schema.json# 交付清单
```

Schema 文件创建只表示协议草案落盘，不表示协议已经验收。每个 Schema 必须同时具备合法样例、非法样例、引用解析和跨对象一致性测试；候选快照与实例锁的公共执行分段应共享定义或由等价的一致性测试证明，不能依靠人工同步两个近似结构。

#### 2.3.3 安全底座

| 任务 | 说明 |
|---|---|
| 入口治理 | CLI/API 统一入口，参数类型及路径校验 |
| 路径安全 | 路径规范化、允许根验证、拒绝路径穿越和越界符号链接 |
| 审批协议 | 审批回执绑定身份、动作、对象摘要、政策、时间和防重放 ID |
| 权限模型 | RBAC、资源级授权、项目命名空间隔离 |
| 敏感数据 | 行程和应急地点不默认发送到公网地理编码服务 |

#### 2.3.4 仓库治理

- 确认 `skills/carto-agent/` 独立目录，不写入 `skills/ppt-master/`。
- 确认测试位置规则，不在文档任务中绕过既有测试目录限制。
- 确认 Carto CLI 入口和依赖管理规则。

#### 2.3.5 首期范围与部署基线

在进入 U-P1 前形成版本化范围基线，至少明确：

| 项目 | 必须形成的决定 |
|---|---|
| 首期部署形态 | 受控单机或企业共享；身份、存储、隔离和恢复能力按所选形态进入生产门槛 |
| 首个纵向切片 | 一个 MapScenario、必要来源格式、两种必要表达、A3 PDF/PNG；不以四类作者策略全部实现为前提 |
| 正式能力声明 | 三类业务场景中首期承诺的任务、输入格式、数据规模和明确未开放能力 |
| 模型运行边界 | 模型宿主、可进入上下文的数据、角色配置版本、调用预算和日志脱敏原则 |
| 验收责任 | 每个工作包的负责人、验收人、证据位置、工作量区间和决策截止点 |

### 2.4 退出标准

- [x] 三份文档无并行旧模型，命名和契约数量一致。
- [x] 核心 Schema 草案已创建（13 个 Schema 文件覆盖 manifest、map-spec-lock、map-plan、map-intent、map-brief、generate-request、delivery-manifest、data-role、quality-gates、resolved-map、prepared-data-bundle、knowledge-evidence、tool-binding）；此项仅表示文件存在，不表示协议验收完成。
- [x] 安全底座策略文件完成（tool-bindings、data-preparation-policy、knowledge-sources 含授权边界、凭据隔离和路径安全规则）。

- [ ] Schema 通过 JSON Schema 结构校验测试。

## 三、U-P1：内核骨架与协议层

### 3.1 目标

建立五模块骨架、状态推进、回执、工具网关、知识服务和审批协调，形成可运行的协议层。本阶段不包含业务候选渲染流程，也不实现生产级 QGIS/API/MCP 适配器；仅保留适配器接口、授权边界和结构化环境探测骨架。

### 3.2 前置依赖

- U-P0 完成。

### 3.3 工作内容

#### 3.3.1 五模块骨架

| 模块 | 首要任务 | 拟实现文件 |
|---|---|---|
| `workflow` | 路由分发、作业状态机、步骤回执、审批协调 | `carto_core/workflow/` |
| `compiler` | Schema 校验、固定依赖解析、所有权解析、候选快照构造 | `carto_core/compiler/` |
| `validation` | 注册检查器骨架、检查计划生成、报告格式 | `carto_core/validation/` |
| `adapters` | ToolGateway、授权边界、能力探测及本地/API/MCP 接口骨架；生产连接器延期 | `carto_core/adapters/` |
| `repository` | 模板发现索引、不可变版本存储、知识证据存储 | `carto_core/repository/` |

#### 3.3.2 状态与回执

- 实现共享作业状态字段：`status`/`step`/`attempt`/`run_id`/`input_fingerprint`/`last_receipt`。
- 实现步骤回执：输入指纹、产物哈希、工具版本、起止时间、结果。
- 实现恢复逻辑：复查指纹，只有全部前提仍成立才复用。

#### 3.3.3 工具网关（ToolGateway）

```text
invoke(capability_id, typed_input, execution_context) -> ToolResult
```

- 能力注册表：版本化能力 ID、输入输出 Schema、授权策略、效果类别。
- 调用链：能力查表 → 身份与范围校验 → 输入校验 → 预算检查 → 调用 → 输出语义校验 → 固定产物 → 回执登记。
- MCP 适配：弱耦合协议，发现不等于授权。
- U-P1 只实现网关和适配协议，不接入生产 QGIS、企业 API 或 MCP 服务；真实连接器由后续场景切片按需实现。

#### 3.3.4 领域知识服务（DomainKnowledgeService）

```text
lookup_or_search(query, applicability, access_context) -> KnowledgeEvidence[]
```

- 首期采用结构化字典 + 带元数据的文档检索 + 受控实体查询。
- 知识与事实数据分开：指标含义可查字典，具体数值必须来自业务数据。
- 来源核验：发布机构、版本、条款位置、许可和权威级别。

#### 3.3.5 意图解析与任务分派

- `IntentResolver`：大模型结构化提取 + 版本化场景目录 + 程序规则校验。
- `TaskDispatcher`：根据批准任务查固定策略表。
- 场景意图目录 `intent-profiles.yaml`：三场景 ID、任务词汇、阶段必填信息。
- `MapIntent` 持久化协议：`intent_status`/`readiness_status` 独立。

#### 3.3.6 智能体运行与评测骨架

| 项目 | 实现要求 |
|---|---|
| 宿主接口 | 明确智能体宿主与 Carto 应用的边界；模型只能提交类型化候选，不直接执行 SQL、Shell、动态 Python 或 GIS 表达式 |
| 角色上下文 | MapPlanner 与 MapComposer 分阶段加载各自必需材料，保留角色、提示配置、模型配置及输入摘要版本 |
| 结构化反馈 | Schema 校验失败、工具失败和越权提案返回类型化错误；同一修订下只允许有限次数修复 |
| 运行预算 | 配置模型调用、工具调用、候选修订、上下文大小、总耗时和成本上限，耗尽时明确阻断 |
| 敏感信息 | 行程、应急位置、业务数据和内部路径按分类决定是否可进入模型上下文、日志或外部模型服务 |
| 回归评测 | 建立三场景正例、缺项、歧义、越界和拒识集；按项目或措辞来源隔离评测，避免样例泄漏 |

#### 3.3.7 审批门禁骨架

| 门禁 | 绑定内容 |
|---|---|
| G1 制图合同 | 意图、简报摘要、任务集合、数据获取范围、路线形态、模板选择与委托范围 |
| G2 实例冻结 | 候选参数、数据包、已采用知识/工具证据、预览摘要与剩余风险 |
| G3 成果交付 | 成果摘要、目的地、权限、许可和合规 |

- 审批回执验证签发方、签名或服务端记录、授权范围、有效期及防重放标识。
- 模型无权签发审批回执。

#### 3.3.8 数据准备服务骨架

```text
prepare_data(approved_requirements, execution_context) -> PreparedDataBundle
```

- 固定流程（`deterministic`）为默认模式。
- 数据准备策略 `data-preparation-policy.yaml`：允许方式及触发条件。
- 输出 `PreparedDataBundle`：快照、元数据、处理链、工具回执、质量报告、未决项。

#### 3.3.9 QGIS 环境探测骨架

- 输出符合 Schema 的环境指纹，区分工具可发现、不可用和探测失败，并提供稳定错误码。
- 当前探测不承担 QGIS 安装目录自动发现、CRS 转换、A3 PDF/PNG 导出或无界面工作进程验证。
- 生产 QGIS 适配器与真实环境冒烟延期到需要首个候选渲染的阶段，并在进入 U-P2 的 QGIS 预览前完成。

#### 3.3.10 当前实施状态（2026-09-15）

- 五模块骨架、状态机、步骤回执、意图解析、任务分派、智能体类型化提交、审批协调、固定数据准备、工具网关、MCP 授权边界、知识服务、编译器骨架和校验器骨架已实现。
- 新增 `step-receipt`、`tool-result`、`validation-report`、`environment-fingerprint` 四项协议，并为全部实例 Schema 提供合法/非法 Fixture。
- 本机存在 QGIS 安装目录的人工发现记录，但当前探测骨架不将其声明为可执行生产能力；根据当前实施决策，不在 U-P1 继续实现或验证生产 QGIS 适配器。
- 调整后的 U-P1 内核范围已完成；生产适配器及真实 CRS/A3 PDF/PNG 冒烟作为显式延期项，不计入本阶段完成判定。

### 3.4 退出标准

- [x] 五模块骨架可接收类型化输入并返回结构化结果。
- [x] 状态推进和步骤回执可追踪。
- [x] 工具网关可拒绝未注册能力和越权调用。
- [x] 知识服务可查询获准术语并返回带版本证据。
- [x] 意图解析可识别三场景并区分意图歧义与缺数据。
- [x] G1/G2/G3 审批可验证回执并阻断不满足条件的请求。
- [x] 固定流程数据准备可交付带验收报告的 `PreparedDataBundle`。
- [x] Planner/Composer 类型化输出、有限修复、预算终止、配置版本和敏感信息边界可验证。
- [x] 三场景最小评测集能够区分正确识别、缺项、歧义、拒识和越权提案。
- [ ] 延期：生产 QGIS 适配器及真实 CRS 转换、A3 PDF/PNG、中文字体和无界面进程冒烟验证；该项不阻断调整后的 U-P1 内核范围完成。

## 四、U-P2：首个模板与地图生成最小内核

### 4.1 目标

围绕首个洪涝场景实现两条主路由的最小完整核心：模板创建的 `analyze → brief → author → validate → publish` 和地图生成的 `intake → brief → plan → preview → freeze`。本阶段固定四类模板和四种作者策略的协议边界，但只要求首个 MapScenario 作者策略、必要来源格式及必要表达具备端到端实现。

### 4.2 前置依赖

- U-P1 完成。

### 4.3 工作内容

#### 4.3.1 模板创建路由（对应 P2–P3）

| 步骤 | 实现 | 退出条件 |
|---|---|---|
| 来源分析 | 来源登记、格式分析器（QGIS 子集、SVG/PDF/PNG、CSV、文档）、事实/决策/建议/推导标记 | 输出来源清单和可提取事实 |
| 简报确认 | 简报生成、模板简报审批 | 有权主体批准的模板简报；不复用地图生成 G1 |
| 模板编写 | 首个 MapScenario 作者策略、Manifest、六契约、原型、固定依赖、checksums | 暂存模板包结构完整 |
| 统一校验 | Schema → 依赖完整性 → 所有权 → 数据/空间/表达 → 目标能力 → Fixture 渲染 → 视觉/产物检查 | `blocker/error` 为零 |
| 发布 | 模板发布审批、单一 `publish` 事务、不可变版本、发现索引 | 审批绑定当前包与验证证据，精确版本可发现 |

关键实现点：

- **分段所有权**：MapBrand 拥有身份，MapStyle 拥有表达，MapLayout 拥有版面，MapScenario 拥有场景合同。整段替换，不逐字段拼接。
- **四种作者策略边界**：`create-map-brand`/`create-map-style`/`create-map-layout`/`create-map-scenario` 复用同一流程；首个纵向切片只要求 `create-map-scenario` 端到端实现，其他策略先完成协议、所有权和组合测试，按正式需求逐步开放。
- **有限来源范围**：首个切片只实现洪涝样例实际需要且已声明支持的来源格式，不以一次覆盖 QGIS、SVG/PDF/PNG、CSV 和全部文档解析器作为退出前提。
- **创建模式**：`standard`（正式支持）/`fidelity`（受支持子集）/`mirror`（延后）。
- **四级加载边界**：L0 发现 → L1 候选 Manifest → L2 确认后解析 → L3 按需加载资产和引擎。
- **不使用动态加载图**：固定依赖解析在构建和安装时完成。

#### 4.3.2 地图生成路由核心（对应 GM-P2–GM-P3）

| 步骤 | 实现 | 退出条件 |
|---|---|---|
| 规划（plan） | MapPlanner 组织模板安装、数据准备、知识采用和空间/表达语义决定；MapComposer 细化图面；compiler 生成候选 | `PreparedDataBundle`、`MapPlan` 修订、`ResolvedSnapshot` |
| 预览（preview） | 适配器渲染候选，独立检查真实数据与图面；按责任退回修订 | 预览和验证证据 |
| 冻结（freeze） | 验证 G2，由 compiler 构造 `MapSpecLock` | 不可变执行输入 |

关键实现点：

- **MapPlanner/MapComposer 分责**：同一主智能体分阶段承担，不新增路由或独立智能体。
- **MapComposer 不是第二个编译器**：提出图面参数修订；compiler 负责解析、校验和生成完整候选。
- **候选预览与 G2 绑定同一 `execution_digest`**：冻结后不再重新推理或重算断点。
- **三类场景规划策略**：政务专题、应急测绘、领导调研各有差异文件，不复制生成步骤和门禁。

#### 4.3.3 编译器实现

```text
校验选定包和固定依赖 → 一次解析全部小型契约 → 按固定所有权表选择分段
→ 确定目标、地域、数据角色和标准适用性 → 合并约束检查冲突
→ 对未决字段应用默认 → 输出规范化对象与冲突清单
```

- 不使用通用约束求解器。
- 不接受模型直接写入执行锁。

#### 4.3.4 校验器实现

- 注册检查器注册表：ID、版本、参数 Schema、适用条件、阶段、约束标签、失败严重度、修复所有者。
- 四级检查：数据接入 → 计划编译 → 候选预览 → 冻结/正式成品。
- 模板和模型不能把必需错误降为警告。

#### 4.3.5 QGIS 适配器与预览

- 能力接口：`capabilities()` / `compile()` / `render()`。
- 首期最小能力：矢量图层、顺序分级设色、容量比例符号、CRS 转换、A3 印刷布局、PDF/PNG 导出。
- 独立工作进程：超时、内存、CPU、临时磁盘限制。
- 可重放：固定环境、字体、随机种子和排序。

### 4.4 退出标准

- [ ] MapScenario 模板创建从来源分析到发布全链路可运行（Fixture 数据），其他模板种类的协议和所有权测试通过。
- [ ] 地图生成从接入到冻结全链路可运行（Fixture 数据）。
- [ ] 编译器可解析六契约并生成无未决参数的候选快照。
- [ ] 校验器可执行注册检查并返回结构化报告。
- [ ] QGIS 预览可渲染候选并输出 PDF/PNG。
- [ ] `MapSpecLock` 不可变且与候选执行摘要一致。
- [ ] 冻结后变更触发新候选和新锁，旧锁不可修改。

```text
  ├→ validation（校验/检查）
  ├→ adapters（工具网关/QGIS/Renderer）
  └→ repository（模板/证据/成果存储）
```

- `workflow` 编排其他模块；`compiler` 面向已准备输入保持纯计算；`validation` 通过明确接口请求渲染检查；`adapters` 不反向调用业务规划。
- 共享领域类型与 Schema 不引用具体工作流，避免循环依赖。

### 9.2 两条路由的共享与独立

| 内容 | 共享 | 独立 |
|---|---|---|
| Schema 和类型定义 | 全部共享 | — |
| 编译器、所有权和检查器 | 全部共享 | — |
| 适配器接口与工作进程 | 全部共享 | — |
| 审批验签、身份与权限 | 全部共享 | — |
| 作业、请求和审批对象 | — | 各自独立命名空间 |
| 状态、步骤和产物 | — | 各自独立步骤集合 |
| 模板发布 / 地图交付 | — | 不同操作和权限 |

### 9.3 角色职责映射

| 阶段 | 职责对象 | 所在模块 |
|---|---|---|
| 意图解析 | IntentResolver | workflow |
| 任务分派 | TaskDispatcher | workflow |
| 制图规划 | MapPlanner | workflow |

## 十、测试矩阵

### 10.1 测试分层

| 层级 | 必测内容 |
|---|---|
| 类型与组合 | 四类模板、六契约、所有权替换、引用与循环检测、未知字段和版本拒绝 |
| 业务理解 | 三场景正反例、缺数据与意图歧义区分、跨主题任务、未支持需求拒识 |
| 计算正确性 | CRS/单位、统计口径、Join、分类断点、空间叠加、访问顺序与路线形态 |
| 规划—实现边界 | 同一计划不同候选保持事实与语义；越权提案被拒绝 |
| 冻结与职责切换 | 未决图面参数不能冻结；变更使旧候选证据失效；锁后不能调用模型重新设计 |
| 模板/工具/知识集成 | 包完整性、MCP 绑定变更、知识冲突与撤销、数据子智能体验收及越权拒绝 |
| 智能体运行 | Planner/Composer 上下文边界、结构化输出、有限修复、模型/提示配置版本、预算耗尽和敏感信息泄露防护 |
| 视觉与交付 | 标签和图例、布局容量、字体与裁切、多目标必需性、交付清单 |
| 故障与安全 | 进程崩溃、超时、重试、取消与晚到结果、并发写入、路径攻击、提示注入、审批伪造 |
| 恢复与复现 | 候选/锁不一致拒绝、旧版本重放、环境变更重新冻结、备份恢复与不可见半发布 |

### 10.2 验收原则

- 语义断言与数值容差是质量基线，视觉回归是补充。
- 像素差异不能独自证明地图正确；同时需要单位、分类、路线、数据时点等业务断言。
- 评测集按项目/措辞来源划分训练与评测，防止仅靠重复模板得高分。
- 不使用模型自报置信度作为合格标准。

### 10.3 阶段验收记录

每个阶段进入实施前建立可追踪的工作包清单，至少记录：

| 字段 | 含义 |
|---|---|
| Owner / Approver | 实施负责人和独立验收人 |
| Dependency | 前置产物、外部数据、审批和决策截止点 |
| Deliverable | 代码、Schema、策略、Fixture、报告、部署材料或运行产物 |
| Acceptance | 可执行测试、业务断言、容量阈值和安全拒绝条件 |
| Evidence | 报告、摘要、运行回执和批准记录的位置 |
| Estimate | 工作量区间、目标日期和主要风险；未知项先做 timebox 验证，不伪造精确排期 |

生产阈值在 U-P0 基线或对应工作包启动时批准。至少量化意图正确处理率、应澄清请求处理率、未支持需求拒识、业务数值/空间语义正确性、首轮成图通过率、人工修订次数、固定规模下的耗时与峰值资源、并发、恢复时间和可接受数据损失。安全禁止项和业务硬条件按逐项通过/拒绝证据验收，不用平均分掩盖单项失败。

## 十一、生产完成定义

### 11.1 首次企业生产发布必须满足

1. 两条已详设路由具有独立生命周期、审批、不可变产物及恢复闭环。
2. 三类业务场景具有声明范围内的正向样例、缺项澄清、拒识与失败恢复证据。
3. 所有强制检查、权限、隔离、审计、备份和恢复能力已实际验证。
4. 模板、工具、知识及适用专业基线有明确版本与维护责任。
5. 安装与部署材料明确支持能力、数据规模、外部依赖和未开放特性。

### 11.2 单次地图生成完成定义

1. MapIntent 的主场景、任务与证据一致，阶段缺项已解决，简报与模板选择有有效授权。
2. 真实数据或明确模拟数据的来源、语义、版本和访问范围可证明。
3. 计划无未决硬条件，全部字段、空间、表达、地点/路线和交付约束成立。
4. 所有必需视图完成预览验证，G2 有效，实例锁不可变。
5. 正式渲染使用同一执行摘要和固定环境，成品检查通过。
6. 所有必需目标和格式齐全，缺失的可选目标已披露。
7. 无 `blocker/error`，警告有处置，必需人工/法定审查完成。
8. 成果包、说明、许可和限制符合目的地要求，G3 通过。
9. 交付记录已原子提交，回执可查询，失败重试不产生覆盖或重复副作用。
10. 审计链、恢复资料和保留策略满足生产要求。

### 11.3 模板完成定义

- kind 唯一，MapScenario 恰好六份业务契约。
- 固定依赖、全部包文件及运行时清单完整且摘要匹配。
- 人读说明与机器规则无已知矛盾，所有可执行参数有唯一来源。
- 适用硬约束通过，`blocker/error` 为零，警告有处置记录。
- 每个正式目标及原型具备所需 Fixture 覆盖，没有未验证的正式能力声明。
- 许可、安全和所需专业审批通过。
- 证据绑定当前包与环境，发布审批绑定同一内容。
- 发布事务完成，精确版本可发现或以项目私有来源安装。

## 十二、待决项与风险

### 12.1 待决项

| 项目 | 影响 | 负责方 |
|---|---|---|
| 政务另外三个方向 | 首期覆盖范围 | 业务方 |

| 实际道路服务与行程保密等级 | 调研路线能力声明 | 业务方/安全 |
| 适用专业审核流程 | 法定审查和合规 | 业务方/法务 |
| 生产环境和容量 SLA | 部署配置和验收范围 | 运维 |
| 首期部署形态与租户边界 | 决定 U-P4 前是否必须完成共享部署能力 | 产品/平台/安全 |
| 模型宿主、数据出域和配置版本策略 | 决定智能体上下文、安全和回归评测 | AI 平台/安全 |
| 各场景正式能力阈值和验收人 | 决定是否允许对外声明生产支持 | 产品/业务方/质量 |

### 12.2 风险与控制

| 风险 | 控制措施 |
|---|---|
| 模型编造数值或坐标 | 所有数值和坐标来自注册工具和可验证来源，模型输出不直接拼接为执行命令 |
| 模板正文提前泄露 | G1 前只读索引和 Manifest，不读契约正文 |
| 审批伪造 | 审批回执验证签发方、授权范围和防重放标识，模型无权签发 |
| 路径穿越和恶意归档 | 路径规范化、允许根验证、归档限制和 XML 外部实体拒绝 |
| 敏感行程泄露 | 行程和应急地点不默认发送到公网服务，最小化查询 |
| 渲染器自行修改图面 | Renderer 只消费锁中的固定结果，不重新选择事实或设计参数 |
| 并发写入覆盖 | 项目锁和修订号比较，不同项目可并行 |
| 模型或提示配置漂移 | 固定运行配置版本，变更触发回归评测；实例锁后不重新调用模型设计 |
| QGIS/字体/PROJ 环境漂移 | 在生产 QGIS 适配器接入时执行环境冒烟并形成指纹；候选与锁绑定执行环境，变化时重新验证或冻结 |
