## 1. 实施结论

建议沿现有模板创建流程增加独立 Style／Layout 作者策略，先打通确定性的契约编写、合成预览和验证，再接入图片分析与模型提炼，最终接通发布和地图使用。无需先实现完整 Scenario 图片提取，也无需先建设通用图像理解平台。

目标链路为：

```text
单张专题图 + 希望复用的内容 + 目标媒介
  → 来源登记、图片规范化
  → 模型识别元素 + 程序测量与证据记录
  → 按 kind 形成简报、处理必要缺口
  → T1 确认
  → 受信作者将候选转换为完整机器契约
  → 静态检查 + 合成内容渲染 + 复用测试
  → TP 批准精确版本
  → 分别发布 MapStyle / MapLayout
  → 未来地图任务绑定兼容 Scenario、数据和空间输入
```

“独立”指两类模板可以分别创建、验证和发布，不要求先有某个具体 Scenario。模板仍须明确所需内容、字体资源、表达兼容性和渲染能力。

**完成定义分为两层：**

- 完成 I-SL6：图片能够进入正式创建链路，生成可独立验证、发布、发现的两类模板。
- 完成 I-SL7：已发布模板被至少一个兼容地图生成链路真实消费，修改其参数能够改变最终结果，并通过现有冻结和成品检查。

只输出描述文件、截图或未经验证的 YAML，不算完成模板创建能力；只发布但未接入地图消费，也不宣称已经完成实际制图复用。

## 2. 首期范围与排除项

### 2.1 首期支持范围

| 维度 | 首期范围 | 处理原则 |
|---|---|---|
| 图片 | 本地 PNG、JPEG，单张、完整页面、可辨认文字与图例 | JPEG 需要补充来源类型；解码能力以新增依赖和测试为准 |
| 地图复杂度 | 一个主图区，允许一个区位图容器，常规标题、图例、页脚及整饰 | 区位图首先提取容器；不声称已恢复其地理关系 |
| Style | 离散配色、常规面／线／点外观、文字角色、图例外观和视觉层级 | 首批以类别面专题图为主；不由颜色自动推定统计含义 |
| Layout | 单页固定画布、矩形 Frame、Slot、对齐、边距、明确重叠和有限溢出策略 | 固定一组目标尺寸；不承诺任意画幅自适应 |
| 创建方式 | `standard`，以及限定于已确认可见特征的 `fidelity` | 图片来源不开放工程级 `mirror` |
| 预览 | SVG、PNG；PDF 在对应适配器检查通过后开放 | 目标格式按能力声明检查，不默认开放所有格式 |
| 模型 | 宿主提供图片理解能力，返回类型化候选 | 不在核心库绑定单一模型厂商；运行记录保留模型及提示版本 |
| 验证数据 | 固定种子的合成图形、文字、图例和视图样例 | 不需要原图数据；合成预览不能冒充原图复现 |

同一张图片既可以只提取 Style，也可以只提取 Layout。图例含义不清楚时，可以完成 Layout，Style 则缩小为经验证的通用视觉配置或停留在候选，不能连带阻塞无关组件。

### 2.2 首期不实现

- 从图片反演真实边界、数值、原始类别编码、投影参数或 GIS 工程。
- 自动完成完整 MapScenario、MapBrand 提炼。
- 分类栅格处理、多地图联动、真实 CRS 转换等完整地理复现能力。
- 由模型临时生成任意 Python、JavaScript、SQL 并在制图时直接执行。
- 通用约束求解器、全类型图表库、多页图集、复杂变形地图、自动字体精确识别。
- 新增第五类模板、独立表达服务或四套重复工作流。

上述能力可后续扩展，但不能作为首期提取视觉与页面结构的必要前提。

## 3. 当前代码能够复用什么，还缺什么

以下结论来自本次静态代码核对，未以本次文档工作重新运行运行时验收。

| 层次 | 当前事实 | 本专项改动 |
|---|---|---|
| 顶层编排 | `template_workflow.py` 已有 analyze → brief → author → validate → publish，具备状态、回执和恢复机制 | 保留公共流程，按来源选择分析器、按 kind 选择作者与校验配置 |
| 请求协议 | `template-create-request.schema.json` 仍绑定洪涝模板 ID、profile、数据角色和 CRS | 增加 Style／Layout 请求分支，移除这些分支对洪涝字段的要求 |
| 来源分析 | `ControlledSourceAnalyzer` 仅接受受控合成 GeoJSON／CSV，拒绝非 Scenario | 新增图片分析器；不能仅扩大枚举即宣称支持图片 |
| 来源声明 | `source-manifest` 已有 `png` 等枚举，但 `data_profile` 是合成地理数据约束 | 增加图片专属来源信息；不得把参考图片伪标记成 synthetic 数据集 |
| 分析与简报 | 来源摘要要求至少两份数据，Brief 固定 `map-scenario`、风险面和避难点 | 摘要按来源类型分支；Brief 按 kind 规定必要字段，一张图即可合法输入 |
| 作者 | `MapScenarioAuthor` 只生成固定洪涝包 | 新增 `MapStyleAuthor`、`MapLayoutAuthor`，共用经过改造的包写入器 |
| Style 协议 | `cartography.schema.json` 有视觉语言、符号目录和少量默认值 | 补齐可实际执行的颜色、符号、文字、图例配置及兼容约束 |

## 4. 核心设计决定

### 4.1 一次图片分析，两个独立创建任务

一个请求仍对应一个 kind、一个包和一个版本。用户同时选择两类模板时，宿主可发起两个创建任务，引用同一份不可变图片观察结果。

- 不把 `kind` 改成数组，不把 Style 和 Layout 塞进一个新模板类型。
- 两个任务各自有 Brief、T1、验证报告、TP 和发布记录。
- 可以合并展示给用户，但审批仍绑定各自对象摘要。
- 分析结果按图片摘要、预处理配置、分析器／模型／提示版本固定；请求相关的 TemplateAnalysis 再分别绑定各自请求摘要。
- 一个任务失败不使另一任务已通过的结果失效。首期不引入跨包原子发布事务。

### 4.2 分开保存观测、解释和设计决定

建议新增 `image-observation` 类型化中间产物，供 Style／Layout 两个作者共同使用。它不是模板，不新增模板目录类别。

| 信息 | 例子 | 可信边界 |
|---|---|---|
| 文件事实 | 图片宽高、格式、内容摘要 | 程序解码及摘要计算可验证 |
| 可见观测 | 某区域出现颜色块、文字和边界 | 保留原图区域、测量方法与质量信息 |
| 模型解释 | 该区域可能是图例，某文字可能是类别名称 | 候选解释；置信度不等于通过验证 |
| 设计决定 | 选用授权字体，目标画布设为明确逻辑 px | 用户决定或系统建议，经 Brief 确认 |
| 未知项 | 源 CRS、原始编码、未显示的无数据规则 | 不以默认值冒充事实；按影响范围处理 |

继续利用现有 `value_origin` 的 `source_fact / user_decision / system_suggestion / derived` 含义。模型输出的 OCR 文字或元素角色，不能仅因模型置信度高就标为已核实事实。独立增加观测类型、确认状态、区域引用等字段，避免混淆“来自哪里”和“是否已经核实”。

中间产物至少描述：

| 字段组 | 建议内容 |
|---|---|
| 来源绑定 | `source_id`、原文件摘要、规范化图片摘要、尺寸与方向 |
| 处理过程 | 解码／缩放／裁剪参数、区域变换、工具版本 |
| 元素 | 稳定元素 ID、候选角色、区域框、可见文字、样式样本 |
| 关系 | 包含、对齐、邻接、显式重叠；保留推断依据 |
| 证据 | 指向规范化图及原图区域的引用、方法、确认状态 |
| 模型调用 | 模型／提示版本、调用标识、输入摘要、预算与响应摘要 |
| 缺口 | 影响 kind、是否阻塞、原因、可接受处理方式 |

候选节点和关系必须有类型和数量上限，未知字段默认拒绝，不接受模型返回任意 HTML、SVG 或可执行表达式作为协议。

### 4.3 坐标先归一化，再转换为明确页面单位

图片分析可以使用左上角原点的归一化坐标，范围为 0～1。若规范化图片宽高为 W、H：

```text
u = x / W, v = y / H, uw = width / W, vh = height / H
```

写入 Layout 时转换到已确认的目标画布。例如目标尺寸为 CW、CH：

```text
page_x = u × CW, page_y = v × CH
page_width = uw × CW, page_height = vh × CH
```

必须明确图片是否包含截图边框、裁剪和旋转；保留所有坐标变换。目标宽高比改变时，不能机械非等比拉伸，应选择已支持布局变体或返回修订。

首期允许将明确指定的逻辑 px 作为目标单位。原始像素尺寸只说明图片大小，不能证明原图使用 A3 或某个 DPI；选择 A3 属于新设计决定。归一化坐标仅用于分析中间态，不悄悄改变现有 Layout 对 `mm / px` 的定义。

### 4.4 Style 的两种提炼结果

**通用视觉配置：** 记录有序色板、文字角色、线宽层级和通用符号配置，不宣称知道每个颜色代表的业务类别。此时缺少的语义映射明确留给未来兼容表达与任务绑定。

**类别兼容样式：** 图例可辨认且标签含义得到确认时，记录“类别语义键 → 配色／符号”。这些语义键不是原始数据编码，未来必须由 Scenario／任务建立映射。

两者使用同一个 MapStyle 协议中的显式绑定模式，不新增模板种类。通用配置必须在已声明的基础表达能力上可以执行和验证，不能仅存一张配色图片就称为完整 Style。

本例中 `Builtup/Other` 应保留完整标签和含义边界，不能自动缩成“建设用地”；看不清的类别可以标记待确认。类别颜色不代表数值递增，不能据此编造顺序分级方法。

### 4.5 Layout 只提炼页面结构，地理整饰保留接口

- 主图和区位图成为接受地图视图的容器，不从图片反推边界和投影。
- 标题、图例、页脚和辅助信息成为有内容类型的 Slot。
- 比例尺、指北针可以提取外观和位置；实际数值与方向绑定未来视图计算。
- 没有视图的组件预览使用明确标识的占位内容；要检验地理绑定时，使用另行声明 CRS 的合成视图，不能称其为源图 CRS。
- 容量通过实际字体测量、长内容测试确定，不把原图“恰好六项图例”直接写成通用上限。

Style 配置外观，Layout 配置容器与几何约束。字号、线宽等视觉属性从 Style 角色解析；Layout 可以限制最小可读尺寸，但不偷偷复制成另一套样式来源。

### 4.6 模型提供候选，受信代码编译与验证

模型负责识别元素、提出对应关系、选择已有能力、补充设计建议和解释修订。程序负责像素测量、单位换算、契约生成、字体测量、包摘要、检查和渲染。

受信作者只接受已通过结构校验并绑定 Brief 的候选。模型不能自报“验证通过”，也不能随模板附带执行代码。后续新增绘图代码可以由模型辅助编写，但须走项目开发、测试和能力登记流程。

不要求每次模型推理得到完全相同的输出。可复现对象是已经冻结的观察结果、确认决定、契约、依赖与渲染环境；重试不能静默覆盖旧的模型结果。

## 5. 协议与文件改造清单

以下为拟实现改动，具体字段应在 I-SL1 冻结。所有新增协议使用 JSON Schema Draft 2020-12，并同时提供合法样例、非法样例和自动测试。

| 文件／位置 | 改动内容 |
|---|---|
| `schemas/template-create-request.schema.json` | 按 kind 区分 Scenario 与图片 Style／Layout；后者要求目标媒介、来源引用和提取范围，不要求源数据和 CRS |
| `schemas/source-manifest.schema.json` | 增加 JPEG 和图片元数据、用途、来源及使用范围；区分参考图片和 synthetic Fixture |
| `schemas/image-observation.schema.json`（新增） | 定义图片测量、候选元素、坐标空间、证据、模型运行和缺口 |
| `schemas/template-analysis.schema.json` | 来源摘要按图片／数据分支，支持单张图；引用不可变观察结果 |
| `schemas/template-brief.schema.json` | 按 kind 定义必要条件、范围、设计决定、阻塞项与观察摘要 |
| `schemas/cartography.schema.json` | 补齐有限视觉 Token、符号、文字、图例配置、绑定模式与兼容能力 |
| `schemas/layout.schema.json` | 补齐 Slot、内容绑定、显式重叠、单位和有限溢出规则 |
| `schemas/manifest.schema.json` | 独立组件契约入口和质量入口；保留 Scenario 六契约规则 |
| `schemas/quality-gates.schema.json`、`policies/checker-registry.yaml` | 按 kind、预览 profile 和适用条件选择检查器，不套用洪涝专属检查 |
| `schemas/render-scene.schema.json` | 类型化区分地图场景与页面／组件预览场景，后者不要求地图相机和 CRS |
| 渲染回执、环境指纹、模板验证证据 Schema | 支持新 profile 的真实引擎、字体、测量器和资源摘要，消除对 MapLibre 的普遍必填假设 |
| `policies/scope-baseline.yaml` | 单独声明图片来源、可创建 kind、可用预览与未开放生产能力 |
| `workflows/create-template/` | 增加 Style／Layout 策略说明；继续使用唯一 create-template 路由 |

Manifest 中，Style 的机器入口为 `contracts/cartography.yaml`，Layout 为 `contracts/layout.yaml`，独立组件的质量入口为包根 `quality-gates.yaml`。不能将 Scenario 的六份业务契约复制到两类组件中凑齐格式。

协议变更须同步核对 `$id`、`schema_version`、SchemaRegistry 引用和摘要规则。当前公共 `schemaVersion` 固定为 1，不能在样例中单独填写 2 就认为完成升级。可兼容的分支扩展保留原有合法合同；确有破坏性变化时显式升级并更新受影响调用和测试，不建立旧命名、旧锁格式的平行兼容实现，不修改已发布不可变版本。

## 6. 分阶段实施路径

### I-SL0：冻结首期能力和验收样例

**工作：**

1. 选定单张图片、允许的元素类型、字体资源、目标画布和输出格式。
2. 以 `doc/sample/Athi_River_LULC_map-2023.png` 为人工核对样例，核实使用范围；该文件只作为设计参考，不由运行时扫描 `doc/` 获取。
3. 准备可随测试发布的合成参考图、标注和故意含糊的反例；实际输入通过 SourceManifest 显式传入。
4. 对主图、标题、图例、区位图等标注区域，区分“已知元素”和“无法确认语义”。
5. 确定图片大小／解码预算、模型调用预算、合成测试集合和版本化质量阈值。
6. 明确 scope-baseline 变化；真正开放新能力时按现有策略取得对应范围批准，本文编写不触发发布或审批操作。

**产物：** 范围清单、图片标注、质量基线、协议差异表、测试矩阵。

**退出条件：** “无原始数据、无源 CRS”是合法验收场景；两类模板各自的必要条件已明确。

### I-SL1：拆开请求、分析和简报的 Scenario 绑定

**工作：**

1. 完成第 5 节协议及注册变更，按 kind 使用严格分支。
2. SourceManifest 能区分参考图片与合成验证数据，不把所有 source 都要求为 synthetic。
3. Brief 对 Style 要求视觉范围、兼容表达及资源约束；对 Layout 要求目标 Canvas、内容槽位与排版边界。
4. 将缺口分类为“当前 kind 阻塞”“可采用已确认设计决定”“未来任务绑定”“不适用”。
5. 校验路径、文件摘要、kind 与协议一致性；拒绝跨 kind 字段和不可执行表达式。
6. 保持目前已支持的洪涝 Scenario 合同合法，未开放 kind 继续明确返回能力错误。

**产物：** 可校验的 Style／Layout 请求、观察结果、分析、Brief、机器契约及 Manifest 样例。

**退出条件：** 一张图、不提供数据角色和 CRS 的 Style／Layout 请求通过；故意混入洪涝字段或未知字段被拒绝。仅通过协议不开放业务路由。

### I-SL2：独立作者与静态校验先形成闭环

**工作：**

1. 为 `TemplateCreationWorkflow` 增加明确、静态登记的 kind 策略分派；不允许请求选择任意类名或模块路径。
2. 增加 `MapStyleAuthor`、`MapLayoutAuthor`；先将 `StagingPackageWriter` 的六契约和洪涝原型校验改为按 kind 分派，再复用其写入事务。
3. 先使用人工标注的观察结果和已确认决定驱动作者，验证数据契约与作者职责。
4. Style 编译颜色、符号、字体角色、文字层级、图例及兼容配置；Layout 编译 Canvas、Frame、Slot 与有限约束。
5. 将公共包校验和 kind 专属语义检查拆开，检查入口、所有权、依赖、单位、引用和完整性。
6. 保留作者确定性与 `verify_existing` 恢复能力，不让模型在恢复中重新生成内容。
7. 首期优先使用受信外部字体依赖；如需将字体或 PNG 随包发布，须扩展包写入器当前仅处理文档／字符串的序列化能力，受控复制字节并验证摘要与文件闭包。

**产物：** 两类完整 draft 包及静态校验报告。

**退出条件：** 相同冻结输入生成相同契约和包内容；不需要伪造 Scenario；缺字体资源、缺必需绑定、非法单位或越权配置不能通过。

本阶段用于验证底层结构。人工输入观察结果不能作为“已经完成自动图片分析”的验收证据。

### I-SL3：无源数据的组件预览与独立验证

**工作：**

1. 增加页面／组件预览 Scene，复用受控浏览器进程、资源加载、字体固定和导出机制。
2. 扩展 `SvgCompositor` 的页面绘制能力，使其不必接收真实地图截图；仅使用经过类型校验的受信图元。
3. Style Fixture 显示点、线、面、文字和图例，真实消费模板中的视觉配置。
4. Layout Fixture 使用短／长标题、不同数量图例、页脚声明和合成主图区内容。
5. 增加字体加载确认、文本实际包围盒、槽位越界、未声明重叠、图例遗漏和裁剪检查。
6. 增加内容变化测试：更换标题、配色、标签数量，验证输出确实响应相应契约。
7. 为页面预览记录真实 renderer profile；不能填虚构 MapLibre 版本、假 WebGL 能力或假 CRS。
8. 更新发布证据复核逻辑，使其按实际 profile 核对回执和环境，不能继续硬编码唯一地图 profile。

**产物：** 合成 Fixture、SVG／PNG 预览、测量结果、ValidationReport 和 RenderReceipt。

**退出条件：** Style 和 Layout 各有真实浏览器验证通过及失败的样例；修改字体、模板或 Fixture 后旧证据失效。原图整体贴进页面不能代替模板渲染。

建议先完成最小 Layout 预览，再完成 Style 图元预览；两者共用页面合成底座，不各建一套渲染服务。

### I-SL4：接入图片分析和宿主模型

**工作：**

1. 新增受控解码与规范化：格式签名、尺寸上限、方向、色彩处理、透明背景和内容摘要。
2. 图片解码库等依赖选定后同时登记于根 `pyproject.toml` 和 Skill `requirements.txt`；OCR 引擎按实测需要再引入，不先接入多套服务。
3. 宿主调用图片理解能力，返回元素、文字、区域关系和不确定项；核心库只接收类型化结果及来源绑定。
4. 颜色、区域尺寸、相对位置由程序在明确坐标下复核；优先在图例色块等较稳定区域取样，记录取样区域和处理方法。
5. OCR 可以先复用模型识别，并对关键类别提供核对；文字含糊时不得自动承诺类别语义。
6. 对完整图、必要局部裁剪分别记录输入摘要与裁剪变换；图片中的文本仅作为输入内容，不能改变工具权限或执行流程。
7. 模型调用失败或响应非法时保留失败证据，并按预算进行有限重试；不得自动用硬编码洪涝结果替代。

**产物：** `image-observation`、元素标注预览、候选 Style／Layout 信息和缺口清单。

**退出条件：** 至少一次真实宿主模型调用完成图片到类型化观察结果的链路；缓存回放测试同时通过。仅导入预制 JSON 不满足本阶段“自动分析”验收。

这里不新增聊天模型 SDK 平台。宿主负责模型访问、权限和预算，核心负责协议、摘要及确定性后处理；缺少宿主能力时明确返回未开放／不可用状态。

### I-SL5：从观察结果生成可确认、可修订的模板

**工作：**

1. 将图中实例内容与模板变量分开：地点、年份、当前数值进入示例内容；稳定视觉规则和容器进入契约。
2. 支持仅 Style、仅 Layout 或两个独立任务；复用图片观察结果而不复用审批对象。
3. 输出原图标注、候选预览、差异说明和必要决定，供 T1 确认。
4. 模型可在已支持参数范围内选择／组合设计；未知尺寸、字体替代、溢出处理作为设计决定记录。
5. 当类别含义不充分时，允许缩小 Style 范围，但不得自动删除用户要求的类别语义后声称任务完成。
6. 用户纠正元素框、角色或标签后，形成新观察版本与请求，重新生成受影响候选和 Brief；不原地覆盖不可变产物。
7. 首期选择新 run 承载修订：新请求记录前一 run／观察版本的引用，从 analyze／brief 重新进入流程；原 run 保留审计记录。引用字段在 I-SL1 定义。现有 `retry` 只处理失败重试，不能冒充改需求；不额外实现同 run 内任意回退。
8. 新 run 按现有绑定要求取得自己的 T1；同 run 在未改变已批准 Brief 的失败重试中可按现有恢复条件继续。发布对象始终使用最新精确包与验证摘要，不跨 run 复用审批。

**产物：** 从真实图片提炼的 Style／Layout draft 包、证据和修订记录。

**退出条件：** 用户只提供图片和目标媒介也能走到可审核候选；必要缺口明确；非必要的源 CRS 未知不会阻塞。两类模板可以分别完成。

### I-SL6：发布、发现与恢复收口

**工作：**

1. 在 publish 前重新验证对应 kind 的包闭合、依赖、检查器、Fixture、预览、回执与环境绑定。
2. 复用 TP、不可变仓库、权威索引和幂等事务，不另设安装／注册对外命令。
3. 两个模板分别获得精确引用；同版本不得覆盖，分析复用不意味着版本或审批复用。
4. 对字体替换、预览漂移、源图／观察结果变更、包文件变更执行失效检查。
5. 验证进程中断、nonce 已消费、重复发布和状态恢复行为，沿用已有证据机制。
6. 在创建端全部验收后更新 Skill、路由和能力声明；明确这是图片模板创建能力，不等于真实地理数据制图已开放。

**产物：** 两类已发布包、PublicationReceipt、可发现的索引记录和阶段验收报告。

**退出条件：** 图片到两个独立模板的创建闭环完成；未通过检查或未获得精确 TP 的包无法进入权威索引。

### I-SL7：接通至少一条真实模板消费链路

**工作：**

1. 在 `generate-map` 请求、规划和依赖解析中接收已发布 Style／Layout 精确引用；将 `TemplateInstaller` 的 `business_contracts` 固定读取改为按 Manifest 的 kind 与入口解析。
2. 沿用 Scenario 的 `replaceable_segments` 与 `OwnershipResolver`，兼容后整段替换，保持每段单一执行来源。
3. 让 `map_candidate.py` 实际消费解析后的 cartography 和 layout，移除该路径上的固定配色和固定 overlay 坐标。
4. 扩展候选、RenderScene 和 MapSpecLock 所需绑定，固定外部模板、字体、布局测量和渲染依赖。
5. 用另一个兼容 Scenario／合成任务验证复用，不能为了让测试通过而强行将土地覆盖类别映射到洪涝风险等级。
6. 对土地覆盖类别样式，可先增加经验证的类别面表达和合成面样例；无需先支持真实遥感栅格。该能力仍须有表达规则、实现和检查器。同步改造 `MapScenarioAuthor._expression_refs()` 对目录“必须恰好两个条目”的检查，使其按本场景需要精确选择，避免增加目录项破坏洪涝回归。
7. Layout 的区位图槽位必须由支持该视图的适配器填充；不支持时明确拒绝或选择已批准的不含区位图变体，不能静默丢弃。
8. 复用 G1／G2／正式渲染／成品检查／G3；输出目标超出当前 A3 等固定能力时，同时补对应检查 profile，不能绕过成品检查。

**产物：** 精确模板引用、实例编译结果、预览、冻结证据及适用的最终地图成果。

**退出条件：** 替换 Style 会实际改变相应外观，替换 Layout 会实际改变版面；不兼容组合被拒绝；图例、数据语义和空间处理仍由各自所有者保证。

Style 不强制创建 MapBrand：可以引用已获准并锁定的字体资源或已有身份基线。字体角色最终必须解析到实际可用资源，不能依赖操作系统静默替换。

## 9. 验收矩阵与质量指标

### 9.1 必须覆盖的用例

| 编号 | 用例 | 预期 |
|---|---|---|
| A01 | 单张图，无原始数据和源 CRS，只提取 Layout | 合法进入创建链路，不要求伪造地理信息 |
| A02 | 同图只提取 Style，图例标签清晰 | 形成经确认的标签／语义键与外观配置，不编造源编码 |
| A03 | 同图同时提取两类 | 共享观察证据，两个独立包和审批对象 |
| A04 | 图例模糊、主图区和标题清晰 | Layout 可继续；Style 缩小范围需明确确认，或保留候选 |
| A05 | 原图纸张尺寸与字体未知 | 明确采用的目标画布和替代字体，不声称恢复原值 |
| A06 | 长标题、多行图例、缺少可选 Logo | 按有限策略处理；超过必需内容容量明确失败 |
| A07 | 原图含比例尺数字、指北针、区位图 | 提取容器和接口；不将原数字／角度写成通用地理真值 |
| A08 | 图片改动、裁剪变化、旋转或分析结果修订 | 证据摘要及坐标映射相应更新，旧审批／验证不被误用 |
| A09 | 图片格式伪装、超限图片、非法模型结构 | 在对应输入边界拒绝，不产生成功包 |
| A10 | 模型低置信度、自报通过、返回执行代码 | 记录候选或拒绝；不能绕过程序检查 |
| A11 | Font 缺失、字体替换、输出缺字 | 验证失败或显式修订，不静默成功 |
| A12 | 改变配色、标题位置或线宽 | 实际图形和测量结果改变，证明 renderer 消费了契约 |
| A13 | 包／依赖／Fixture／预览被改动 | 发布前复核失败 |
| A14 | 重试、并发修改、审批消费中断、重复发布 | 符合现有状态锁、CAS、回执和幂等规则 |
| A15 | 外部组件不兼容或 Scenario 不允许替换 | 编译拒绝，不深合并或静默回退 |
| A16 | 另一个兼容任务使用已发布模板 | 数据语义保持正确，外观和版面按模板执行 |

### 9.2 指标如何使用

| 层面 | 指标与判定 |
|---|---|
| 协议正确性 | 合法／非法样例全部符合预期；不存在通过宽松未知字段绕过协议 |
| 元素识别 | 在人工标注集测主图、标题、图例等关键元素识别率及区域误差；关键缺失必须进入缺口 |
| 几何提取 | 可用区域 IoU 和边界偏差评估；作为提取质量，不替代最终内容排版检查 |
| 配色提取 | 依据指定颜色空间、原图区域和容差核对；保留抗锯齿、透明及压缩影响，不保证恢复原始设计色值 |
| 排版质量 | 必需文本完整显示；无未声明遮挡、越界和截断；不低于明确最小字号 |
| 规则复用 | 使用新标题、新类别数和兼容视觉配置后仍符合所声明范围 |
| 复现能力 | 冻结输入可重建同一契约；同环境输出满足固定容差；不要求模型重新推理字节一致 |
| 审批与发布 | 对象摘要精确绑定；任一必要证据失效即不能发布 |

识别率、IoU、颜色差和性能阈值须在 I-SL0 通过代表样例标定，并在批量测试前写入版本化策略。本文不虚构已达到的准确率。参考图视觉相似度只作辅助指标，不能代替模板适用性和执行正确性。

至少使用三组样例：土地覆盖类别图、不同布局的简单专题图、含模糊图例或拥挤标题的反例；另外保留未用于调整提示和阈值的测试图片，检查是否仅适配单个样例。

### 9.3 检查执行

- 每项实现运行对应协议、作者、渲染或恢复测试；渲染阶段至少有一次真实受控浏览器运行，模型阶段至少有一次真实宿主调用。
- 纯算法测试与固定候选回放用于日常回归，不能替代实际模型、字体和浏览器联调。
- 阶段验收运行受影响集成检查；共用协议／编排／渲染修改合入和最终开放前，运行现有全量回归并记录环境。
- 沿用 `python -m unittest discover -s skills/carto-agent/scripts/tests -v`，新增测试不进入第二套根目录 `tests/`。

## 10. Athi River 参考图的具体落地结果

原图可以作为两类模板的共同来源，但两者只声明实际提取和验证过的范围。

| 项目 | MapStyle | MapLayout |
|---|---|---|
| 建议 ID | `landcover-muted-context` | `landscape-map-with-locator` |

| 保留未知 | 类别源编码、隐藏尺度规则、未显示的无数据行为 | 原纸张尺寸、源 CRS、区位高亮对象的真实语义 |
