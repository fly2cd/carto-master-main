## 一、先确定智能体的边界

### 1. “单幅”理解为一个最终出版版面

一个项目输出一张专题版面，可以包括一幅主地图、若干辅助地图/图表、短文、名单、图例和来源。暂不支持连续分页、跨页文字流、书刊目录、批量地图集和印前拼版。

如果目标只是“一张纯专题地图”，可以关闭辅助模块；主地图、图例、标题、来源和验证链仍然保留。

### 2. 第一版产品承诺

输入：

- 自然语言任务：主题、地域、数据时间、读者、用途。
- 用户确认的输出条件：成品尺寸或屏幕展示规格、页面方向、字体与样式要求。
- 数据与材料：先支持已整理统计表及可追溯文本，再逐步支持复杂截图、网页归档和文档。
- 经过确认的地理数据或受控底图工程，以及可选参考版面。

输出：

- 可检查的内容方案与数据缺口清单。
- 至少两个有结构差异的候选布局；不存在第二个可行方案时如实说明。
- 真实内容试排稿、问题定位与修改记录。
- 人工确认后的单版输出文件、可编辑工程及其依赖、来源清单和版本记录。

**不承诺从任意截图自动恢复准确GIS底图，不承诺缺失数据自动补齐，不承诺无需人工专业审核即可直接出版。**

### 3. 核心架构选择

推荐：**一个总控智能体＋显式工作流状态＋一组确定性工具＋人工确认点。**

第一版不要把内容统筹、制图、版式、审校全部做成彼此自由对话的独立智能体。先实现具有明确输入输出的能力模块，由总控调度；后续确有独立任务和收益再考虑拆分。

最关键的区分：

- 模型负责理解、提议、解释和处理非结构化材料。
- 程序负责计算、数据绑定、实际测量、渲染、约束校验和版本管理。
- 人负责核心取舍、争议确认以及发布授权。

不是让模型一次生成完整SVG、长脚本或一张图片后就认定制作完成。

## 二、为什么这不是一个“提示词＋生图”项目

需要将前面人工流程里的决策转成软件对象：

| 人工流程 | 智能体内的对象或工具 | 可验证结果 |
|---|---|---|
| 明确定位 | `ProjectBrief` | 地域、时间、用途、单页输出约束是否明确 |
| 素材盘点 | `SourceRegistry` | 文件和原始证据能否追溯 |
| 数据核验 | `DatasetManifest`、核验工具 | 年份/单位/地区关联/缺失值是否有明确状态 |
| 组织内容 | `ContentPlan`、`ModuleSpec` | 每块回答什么、优先级和必保内容是什么 |
| 选择表达 | `MapSpec`、`ChartSpec` | 数据字段对应什么图形通道 |
| 估算空间 | `ModuleProfile`、实际测量工具 | 某内容版本在某尺寸下是否可行 |
| 提出构图 | `LayoutIntent`、模板规则 | 谁与谁成组、主图在哪个大区 |
| 求解位置 | `LayoutSolution`、约束求解器 | 坐标是否满足已确认约束 |
| 真实试排 | 渲染器、`RenderReport` | 文字、注记、图例是否确实装得下 |
| 审校修改 | `Issue`、`ChangeRequest` | 问题有责任、动作、状态和复测结果 |
| 定稿归档 | `Approval`、`ArtifactManifest` | 批准的到底是哪一组数据和输出 |

**真正需要工程化的是“需求—约束—渲染—反馈”循环，而不只是把七个步骤改成七段提示词。**

## 三、建议的系统组成

### 1. 交互工作台

第一版可以只做轻量页面，或者先做命令行与本地报告。图形工作台建议包括：

- 项目区：主题、范围、数据年、输出条件和当前状态。
- 素材区：材料、数据缺口、来源和确认状态。
- 模块区：内容优先级、是否必保、数据绑定、表示形式。
- 画布区：同一最终渲染器输出的预览，以及可选布局边框和问题覆盖层。
- 决策区：为什么放这里、另一方案的取舍、待确认修改。
- 审校区：点击问题定位到模块，查看前后对照。

用户拖动或锁定模块时，应生成有版本的布局约束，不要只改变浏览器中一个临时坐标。

### 2. 工作流控制器

负责：状态转换、任务队列、权限、预算、重试、缓存、运行日志、人工确认与恢复。它不能让模型绕过确认点修改已批准内容。

第一版用简单显式状态机即可。是否引入专门智能体框架，是后续部署选择，不是制作闭环成立的前提。

### 3. 内容与规划层

使用模型完成：

- 从用户要求形成任务书草案。
- 从材料提取有证据定位的候选事实。
- 形成模块清单、主题组与阅读层级。
- 选择允许范围内的图形表达候选。
- 从候选布局中解释收益与代价。
- 对真实问题报告提出结构化修改建议。

所有数字性事实应关联证据记录；最终文本中的数值优先由数据绑定替换，避免模型在总结或改写中重复生成数值。

### 4. 工具执行层

建议使用Python作为第一版业务与数据工具的实现语言；GIS部分采用独立的QGIS/PyQGIS工作进程；图表采用可控SVG组件；布局先模板参数化，再按需接约束求解器。

QGIS的打印布局能够组织地图视图、标签、图例、表格等元素，适合作为这类复合地图版面的渲染基础。[R1]

需要自行实现：模块协议、空间测量、布局规划、问题检查、来源绑定和人工确认。不能因为选用了QGIS，就假设这些智能体能力已经具备。

### 5. 项目存储层

第一版可采用项目目录＋JSON＋轻量任务数据库，不必从复杂分布式架构起步。

保存：输入快照、文件哈希、来源记录、结构化数据、内容版本、布局候选、试排、问题、批准记录、软件与字体清单。

大文件通过工件ID传递，不要每一轮都把所有图片和数据塞入模型上下文。

## 四、先定义共享数据协议

### 1. `ProjectBrief`：统一解释项目边界

示例仅为结构说明，未确认的尺寸保留空值：

```json
{
  "schema_version": "1.0",
  "project_id": "zhejiang_economy_2025",
  "title": "浙江经济发展",
  "publication_type": "single_sheet",
  "page_count": 1,
  "geography": {
    "region_name": "浙江省",
    "primary_level": "prefecture_city",
    "boundary_dataset_id": null
  },
  "data_period": "2025",
  "publication_date": null,
  "output": {
    "medium": "print",
    "size_unit": "mm",
    "width": null,
    "height": null,
    "status": "needs_confirmation"
  },
  "status": "draft"
}
```

无尺寸时可以生成比例型草图，但不能进入正式物理尺寸验证。数据年份、资料发布日期和出版落款应分别保存，不能混成一个`year`字段。

### 2. `FactRecord`：保留证据，不只保留数字

建议字段：

- `fact_id`、指标编码、值、单位、统计期。
- 地理层级、地区编码、地区名称。
- 指标定义、名义/不变价等口径说明。
- 来源文件ID和文件哈希。
- 原文定位：页码、表格行列、段落或截图框。
- 原始文字与抽取结果。
- 状态：`extracted`、`machine_checked`、`human_confirmed`、`conflicted`、`missing`。
- 核验规则与人工确认记录。

`machine_checked`只能表示通过已实现的机器规则，不能自动等同于正式事实审定。模型置信度不是证据，也不是批准。

### 3. `ModuleSpec`：从文字模块清单变为可执行需求

```json
{
  "module_id": "M09",
  "kind": "ranked_table",
  "group_id": "private_economy",
  "question": "浙江有哪些上榜头部民营企业？",
  "priority": "supporting",
  "required": true,
  "content_ref": "enterprise_top100_zj",
  "content_status": "needs_source",
  "attached_elements": ["title", "ranking", "names", "scope_note"],
  "allowed_variants": ["one_column", "two_columns"],
  "size_profile_ref": null,
  "adjacency_preferences": ["M08", "M10"],
  "edits_requiring_approval": ["remove_rows", "abbreviate_names", "change_scope"],
  "layout_lock": {
    "position": false,
    "size": false
  }
}
```

这里`required: true`表示当前内容方案要求保留该模块，不代表其数据已经齐备。缺来源时只能做显著标识的占位草图，正式绘制应阻断。

模块最小宽高不让模型编造，放在工具测得的`ModuleProfile`中。

### 4. `MapSpec`和`ChartSpec`：表达规则与数据分开

地图至少包含：

- 地理数据ID、层名、版本、坐标参考系。
- 地区匹配键、统计层级、数据表ID。
- 数据字段与颜色、符号面积、扇区、标注的对应。
- 分类断点、边界归属和缺失值表现。
- 必保地理范围、图例绑定、必要注记。
- 是否允许比例变化、重新标注、局部详图。

图表至少包含：轴字段、类别顺序、单位、年份、系列、强调项、图例、缺值策略。

同一个市级人均GDP值不能因底图有县界就被当成每个县的独立观测值；相关验证属于数据—表达绑定检查，而非美化检查。

### 5. `LayoutIntent`、`LayoutSolution`不要混为一个对象

- `LayoutIntent`是模型提议的关系：主图靠左、民营内容成组、名单位于指标下方。
- `LayoutSolution`是工具计算的结果：已选模板、内容变体、x/y/w/h、对齐线、求解状态和测量版本。

对齐、邻近、上下关系都要区分硬约束和软偏好。每个约束有ID、来源、解释与批准状态。

### 6. `Issue`和`Approval`

问题包括：模块ID、问题类型、严重程度、检测方式、位置、证据工件、建议动作、复测结果。

批准包括：操作者、批准范围、时间、工件哈希、内容与布局版本。不能只保存一个脱离版本的`approved=true`。

## 五、资料与数据处理：模型抽取，程序核验，人工裁决

建议分层接入：

1. **优先支持**：已整理CSV/JSON、明确字段的统计表、已确认底图。
2. **第二批支持**：文本型Word、HTML、网页归档。
3. **后续支持**：扫描件、截图、复杂跨页表格、图片中的图表数值。

流程：

- 登记文件与版本，原始材料只读。
- 抽取文字和表格，保留结构定位；图片识别结果标为待核。
- 提议字段映射和地区匹配。
- 检查年份、单位、数据类型、重复键、缺失值和异常值。
- 检查地区表与GIS边界关联覆盖；名称近似匹配只作为候选。
- 对来源冲突出具并列证据，让人确认。
- 输出经过规则校验的数据集与仍待处理项。

不要统一将空值填0；不要将不可比年份拼进同一排名；不要用“看起来接近”代替口径一致。

跨表加总检查允许有明确记录的四舍五入误差，也要考虑统计口径差异。检验规则与容差应绑定具体指标，不能对所有数据机械套同一公式。

对于现有浙江案例，可以利用已有台账、JSON摘录、文案和样件作为开发输入，但不能把它们的“案例摘录”状态自动提升为正式审定状态。

## 六、布局引擎是核心：采用分层求解，而不是模型直接输出全部坐标

### 1. 模块先实现统一协议

建议每种模块提供：

```text
validate_content(module, datasets) -> ContentReport
measure(module, width, variant, style, context) -> ModuleProfile
render(module, box, context) -> RenderArtifact + RenderMetrics
check(artifact, module, context) -> Issue[]
```

以上是自定义接口，不是第三方库现成API。

`measure`至少返回：所需高度、是否溢出、真实行数、最小文字尺寸、图例尺寸、关键图符范围、所用内容/字体/渲染器版本。

地图可先用低分辨率布局试渲染测量占用与注记问题，再在目标输出条件下复核；低分辨率结果不能作为最终可读性证据。

### 2. 用有限变体表达“内容形态”，避免无限搜索

示例：

- 总览：文字与环图左右并列／上下组合。
- 名单：单列／双列。
- 民营概况：短文／经确认的指标条。
- 历史图：已确认的双轴图／经确认的上下对齐小图。
- 主地图：若允许，调整图例位置、标注方案和图符方案。

同一模块在不同宽度和变体下，可能有不同高度。预先测量一组候选宽度，形成可查表的尺寸配置；不要以字数除以一个常数估计所有文本。

涉及内容删减或指标含义改变的变体，只有经过确认才可加入自动选择集合。

### 3. 第一层：选择语义分组和整版骨架

模型根据必保模块和关系，提出2—3种结构级候选，例如：

- `left_anchor_three_zones`：左侧主图，中部解释，右侧辅图。
- `overview_band_two_zones`：上方总览带，下方主图与辅助区。
- `center_anchor_side_panels`：中央主图，两侧说明。

模板是“区域及关系规则”，不是只能填一个固定截图的坐标模板。内容超出模板容量时，应拒绝、换模板或请求调整，不能无条件缩小字体。

对于模块少的MVP，应优先选简化的两区结构，不必复刻11模块的三栏密度。

### 4. 第二层：计算模块宽高与位置

第一版可以枚举少量栏宽和模块变体，再进行边界、非重叠、顺序及容量检查。复杂度和交互锁定需求增长后，可接OR-Tools CP-SAT。

CP-SAT使用整数变量与约束，提供可行、最优、不可行及未知等求解状态；Python API有二维非重叠约束。将这些用于专题版面布局是本方案的建模选择，并不是OR-Tools自带地图排版器。[R2][R3]

建议变量：

- `x_i, y_i, w_i, h_i`：模块外框。
- `variant_i`：经允许的表达/排布变体。
- `zone_i`：模板中允许落入的区域。
- `present_i`：仅对已允许省略的模块使用。

物理尺寸可按约定离散成整数，例如1个求解单位表示0.1毫米。这是可配置的工程精度示例，不是印刷标准，也不是文字大小限制。

硬约束包括：

- 在版心内、不覆盖全局保留区。
- 同层顶级模块不重叠；局部图例等嵌套元素在所属模块内部校验。
- 不低于当前内容变体的实测空间需求。
- 必保模块存在，人工锁定条件保留。
- 已确认的上下和分组关系满足。
- 图例和说明包含在模块容量中。

矩形求解只负责模块外框，地图内部注记、引线、图符仍由制图与细部检查负责。自然海域留白不等于可以任意穿插其他模块；MVP先采取保守的外框策略。

### 5. 第三层：在可行方案中比较质量

先筛除违反硬约束的方案，再比较：

- 核心主题的视觉优先级是否充分。
- 语义相邻代价：同一主题是否过度分散。
- 关键模块相对最低尺寸的余量。
- 对齐、间距、留白与密度的稳定性。
- 相比人工已确认布局的改动幅度。

可以采用分层排序或校准后的加权目标，但不能让“审美分高”抵消图例遗漏、文字溢出或必保内容缺失。

不要以“最大化地图面积”作为唯一目标；也不要以“空白越少越好”为目标。最终权重与阅读阈值需要在项目样本和用户确认中校准，而非模型临时拍定。

候选多样性应来自不同区域骨架或主题分配，不是同一方案向左移动几个像素。

### 6. 第四层：真实渲染后再回调

所有候选必须装入真实内容，生成整版与关键局部。将实际结果返回：

- 哪个框溢出多少。
- 哪些名称换行。
- 哪些必保标签缺失或遮挡。
- 哪些图例单位或分类与图件不一致。
- 哪些读序关系需要人工检查。

模型只提出结构化修复请求，例如：扩大M09、切换已许可的名单双列变体、改用另一模板。程序执行权限检查、重新测量和重新求解。

第一版可设2—3轮自动回调上限，具体可配置；超过预算、无实质改善、出现内容取舍或无可行解时，转入`needs_review`，不要循环到生成一张“看似完成”的图。

### 7. 不可行与超时需要分开处理

- 输入无效：报告字段或约束错误。
- 当前模型被证明不可行：输出已识别冲突及可讨论的修改。
- 超时或状态未知：说明尚未找到/证明结果，不宣称不存在方案。
- 找到可行但未证明最优：可以作为候选，明确状态。

冲突解释来自带ID的约束、测量结果及必要的可控松弛测试。不要仅让模型凭空声称“最小冲突集已找到”。

## 七、制图和组版执行：建议先用一个最终渲染基准

### 1. 建议的第一版路径

- 统计数据和GIS底图按地区键绑定。
- 根据`MapSpec`构建主辅地图。
- 根据`ChartSpec`生成可控SVG图表组件。
- 根据`LayoutSolution`将地图、文字、图例和图表置入QGIS打印布局。
- 从同一个布局生成预览和最终输出。

QGIS官方文档列出了布局的图像、SVG、PDF导出能力。[R4]

建议把QGIS工程及外部依赖作为主要可编辑交付，PDF用于最终审阅/交付，PNG用于预览，独立SVG用于图表部件。导出SVG是否保留需要的文本和矢量结构、特殊样式是否被栅格化，应使用目标工程实测，不能承诺所有元素都能无损转为通用设计软件的原生编辑对象。

### 2. 避免“两套渲染器各说各话”

如果浏览器用一种字体度量排版，而最终输出使用另一套字体与渲染规则，就可能出现预览合适、导出溢出。因此建议：

- 预览以最终引擎的真实渲染为基准。
- 正文和名单测量使用与最终绘制一致的字体、行距及宽度规则。
- 对SVG图表，组件自身保留固定内部坐标与确定尺寸，并测试其在最终引擎中的表现。
- 前端编辑覆盖层只负责选择、移动和显示问题，不替代最终排版结论。

### 3. GIS工作进程独立

建议将GIS渲染放在独立进程，明确输入工程、数据、样式、布局及输出目录。应用程序只传受控JSON任务，不允许模型任意执行Python或shell。

开发时固定并记录已验证的QGIS、字体、图表组件和运行依赖版本；用样例工程验证中文字体、投影、导出与资源路径。不要直接将任何“latest”文档对应环境当作生产依赖锁定方案。

### 4. 参考JPG的用途

可用于识别：模块、主次、分区、配色倾向和大致比例。

不能直接当作：地理数据源、精确数值表、可编辑源工程、确定开本的证据。抽取到的坐标是参考图上的视觉估计，不是正式布局参数。

## 八、工具接口如何暴露给智能体

建议只提供受控的领域工具，第一版例如：

| 自定义工具 | 主要输入 | 主要输出 | 允许改变什么 |
|---|---|---|---|
| `inspect_sources` | 项目ID、已授权素材ID | 来源台账、可解析性、缺口 | 新建解析记录 |
| `validate_dataset` | 数据版本、规则集 | 核验报告、问题 | 不直接改原始数据 |
| `propose_content_plan` | 任务书、可用事实 | 模块与关系草案 | 草案版本 |
| `measure_modules` | 模块、变体、宽度候选 | 实测尺寸配置 | 测量工件 |
| `solve_layout` | 模块、配置、模板、约束 | 候选布局、求解状态 | 候选版本 |
| `render_sheet` | 方案、数据、样式版本 | 预览、工程、渲染指标 | 工作输出 |
| `check_sheet` | 渲染工件、检查规则 | 问题列表 | 检查记录 |
| `propose_change` | 问题、当前版本 | 带理由的补丁提案 | 不直接批准补丁 |
| `request_review` | 变更或候选、证据工件 | 审阅请求ID | 待审记录 |
| `export_approved` | 精确批准版本、输出规格 | 交付文件和清单 | 经门控的交付目录 |

工具入参不接受任意系统路径和代码；使用项目内工件ID，由服务端解析路径并检查权限。

### 如果采用OpenAI作为模型服务

可以使用Responses API的function calling连接这些自定义工具，模型发出调用请求，应用侧校验、执行并返回结果；这不是将本地执行权限直接交给模型。[R5]

模块方案、布局意图、修复请求可采用Structured Outputs约束JSON结构。结构符合Schema不意味着数据正确、空间可行或已获批准，仍须执行领域核验；还应处理拒绝、调用错误和不完整结果。[R6]

模型服务保持适配层，不在业务逻辑写死模型名称。选择时通过中文资料抽取、字段准确率、工具参数正确率、版面问题定位等本项目任务评估；本方案不对未测试型号作性能或成本承诺。

## 九、工作流与人工确认点

建议主状态：

`draft → brief_ready → sources_indexed → data_checked → content_review → layout_search → trial_review → approved → exported`

旁路状态：`needs_data`、`needs_review`、`failed`。状态应附版本和原因，不只是一个进度百分比。

### 三个第一版确认点

1. **内容确认**：必保模块、来源争议、允许的删改与表达变体。
2. **布局确认**：候选结构、实际尺寸试样、仍未解决的问题。
3. **发布确认**：精确文件版本及相关审校完成状态。

数据缺失时允许选择：补件、确认不展示该模块、做明确标识的草图占位。不能通过静默编造填满版面。

### 控制逻辑示意

以下为架构伪代码，不是可直接执行的应用：

```text
读取任务、允许使用的材料和已有批准版本
登记来源，抽取候选数据，执行核验
若必保内容缺少关键数据：输出缺口，暂停正式制图
提出内容与表达方案，等待必要的内容确认
测量允许的模块变体
在预算内搜索不同骨架的候选布局
    若有可行方案：真实渲染并检查
    若有可自动处理的问题：提出受控补丁，重新测量/求解
    若涉及删改、关键事实或不可解决的容量：请求人工确认
输出候选对照与证据，等待布局确认
完整渲染、联合审校、按输出条件复核
批准绑定到精确工件哈希
只导出与批准对应的工件，并登记归档
```

任何人工拒绝都应保存理由并返回对应阶段，而不是清空项目重新开始。

## 十、质量检查不能只靠模型看截图

### 1. 数据与来源检查

- 所有正式使用的数字有来源或可追溯的派生计算。
- 缺失值未默认为0。
- 单位、年份、指标口径一致或明确区分。
- 地区匹配结果可检查，不能把模糊匹配默认为正确。
- 派生值保留公式、输入版本和舍入规则。

### 2. 地图与图表语义检查

- 颜色、符号、扇区、数值标签和图例绑定到正确字段。
- 分类区间无未定义边界或意外重叠。
- 统计层级与地理单元匹配。
- 图形大小编码规则明确，避免将半径/面积含义混淆。
- 历史图与省际图的数据范围、单位和类别完整。
- 地图范围、比例表示、必要要素与当前输出一致。

### 3. 版面几何与渲染检查

- 顶级模块越界、非许可重叠和文字溢出。
- 实测字号与项目确认条件比较。
- 名单实际条目数与必保条目数比较。
- 必保地图标签数量、未放置记录、已知遮挡或冲突。
- 图例、来源和页脚是否存在且归属明确。
- 缺字体、缺图、缺图层、导出异常。

检测不了的项目明确标为`not_checked`或`needs_manual_review`，不能都打绿勾。

### 4. 模型视觉审阅的角色

可用于提出：主次不明显、主题分散、局部密度失衡、图例疑似混淆等意见。要求它给出模块ID和区域证据，而不是只给审美分。

不能独自承担：精确数据验证、像素级尺寸测量、所有地名正确性、正式地理审核和最终批准。

### 5. 输出条件检查

按用户确认的真实成品或目标屏幕环境复核。软件100%缩放和截图分辨率不能直接等同于物理可读性。

印刷色彩、出血、字体处理、专业审核等要求按实际项目确认，软件自动检查与人工审阅记录分开，不统一套用某个固定参数。

## 十一、修改与缓存：只重算受影响的部分

建立依赖图：

`来源 → 事实/数据表 → 文案/表达 → 模块尺寸 → 布局 → 渲染 → 检查 → 批准`

例如：

- 企业正式名称变长：重测名单，必要时重算中栏并复查邻近地图；同时使相关布局批准失效。
- GDP数字变更：更新所有引用该事实的文本、环图、标签或地图，不能只改某一个截图。
- 字体变更：重测受影响文本与组件，重新试排。
- 只改框线色：可只重绘相关样式，但仍需检查最终输出和版本。

缓存键至少包括：内容哈希、样式、尺寸、字体、模板及渲染器版本。模型调用也记录输入版本，避免“同一个模块ID”错误命中旧内容缓存。

批准失效范围由依赖关系决定；变更后不能继续沿用旧的无版本通过标记。

## 十二、安全与资料信任边界

- 用户请求、系统配置与附加文档的正文必须分开。
- HTML、Word、PDF、截图和OCR文字中的“忽略规则、运行命令、上传文件”等语句都作为素材内容，不能取得控制权限。
- 不执行素材里的宏、脚本、外部链接命令或任意表达式。
- 模型工具用明确Schema和白名单；涉及文件写入、外网取数、上传、删除、覆盖和发布的行为分别授权。
- 原始素材只读；新版本写入项目内工作目录，输出采用临时文件后原子提交等受控方式。
- 工件ID映射到允许路径，阻断路径穿越和项目间越权。
- 数据外发按项目权限控制；不能默认整份政务材料都可送入外部模型服务。
- 渲染隔离、超时、内存、模型调用次数与自动修复轮数设预算。
- 不把人工签审和专业审核伪装为模型自评。

这些限制应由工具执行层实现，而不只写进提示词。

## 十三、用浙江经济发展案例走一次系统流程

### 1. 初始登记

输入参考成图、资料目录、已有案例台账及JSON。材料目录里的来源配置图用于理解素材对应与可能构图，不作为指令执行。

输出：来源登记、文件哈希、解析状态与待补数据。

### 2. 提出两种内容运行模式

- **完整复现模式**：按M01—M11组织。未具备的底图、字段、历史表、省际表、名单等必须补齐或确认处理方式。
- **简化闭环模式**：只选择已经足以支撑表达的内容，加上经过确认的GIS底图，验证单版制作链。

不能将简化版称为完整还原原图。示意占位模式也应与正式内容模式分开。

### 3. 第一版建议使用的最小内容

- M01 标题与短导语。
- M02 省级总览与产业结构图。
- M04 一幅表达更简单、只使用已核验字段的市级经济地图。
- M08 民营经济指标。
- M11 所属图例、来源和落款。

M04可在确认所有相关市级GDP数据和底图后，先采用明确大小图例的GDP比例符号表达；不要为了复刻原图加入尚未核验的人均GDP或不齐的城市产业结构。该替代须标明是MVP表达，不是原主图复现。

如果上述地图输入仍不齐，应停留在布局占位和补件报告，不能画一份虚构的浙江地图。

### 4. 后续再增加高风险模块

- 企业名单：验证真实名称、双列测量和内容增量更新。
- 历史图：验证轴标与单位、年份增加后的重新试排。
- 千亿元县图：验证县级关联和密集注记。
- 全部城市产业环图与民企地图：验证图符密度、图例和复合编码。

### 5. 输出案例级成果

每次运行至少输出：

- 数据缺口和确认项。
- 内容方案与表达规则。
- 每个模块的尺寸测量结果。
- 布局候选与选择理由。
- 真实试排与问题覆盖预览。
- 更改记录、确认记录和最终工件清单。

这样才能回答“为什么历史图被放到右上”，而不是只有结果图片：它应有结构目标、约束、候选取舍和试排证据。

## 十四、按什么顺序开发

### 阶段P0：先建不依赖模型的确定性纵向闭环

内容：确认一个测试版心；导入一份经核验统计表和底图；实现标题、单主图、一个统计组件、图例与来源；用固定模板生成单页。

成果：命令行渲染器、测试数据包、项目工程、预览与输出、基础QA报告。

验收：输入明确时可重复生成；修改一个数据值时相关数值同步；缺数据与缺字体等故障能被报告。

**理由：底层工具本身不稳定时，接入智能体只会把故障变成更难定位的对话。**

### 阶段P1：做可测量组件与候选布局

内容：模块协议、宽度—高度配置、2种模板、边界与容量检查、人工锁定、局部重排。

成果：真实内容候选对照、冲突报告、布局定位表。

验收：增加文字、长企业名和来源长度时，系统调整或明确拒绝，不静默缩小/截断。

### 阶段P2：接入智能体总控

内容：任务理解、内容组织、布局意图、工具调用、结构化修复与人工确认。

成果：可通过自然语言驱动的制作会话、运行记录和可恢复项目。

验收：模型不能绕过内容批准、执行未授权工具、把未知数据当已核验，也不能跳过渲染自称完成。

### 阶段P3：扩展资料解析和复杂地图

内容：Word/网页/截图抽取、县级专题、复合图符、复杂名单与更多模板。

成果：资料解析报告、来源定位、浙江完整案例测试集。

验收：字段抽取、地区关联与注记问题有可量化记录及明确人工兜底。

### 阶段P4：生产化

内容：项目权限、队列和隔离、缓存、版本冻结、异常恢复、输出校验和回归测试。

成果：部署配置、稳定运行记录、操作说明、工件归档和版本迁移策略。

是否拆多智能体、是否做样式检索与偏好学习，到此时再依据实际瓶颈决定。不要先训练模型或搭建庞大多智能体框架，再补最基础的测量与出图能力。

## 十六、必须建立的测试集

| 测试情形 | 应有结果 |
|---|---|
| 缺一个必保城市数值 | 缺失被标记；不填0、不编造；正式对应模块被阻断 |
| 同一城市出现两个不同年份记录 | 区分时间或报冲突；不随机选一条 |
| 地区名称能近似匹配但编码不同 | 提供候选并要求确认 |
| 企业名称变长或增加条目 | 重测容量，重新布局或请求取舍 |
| 历史图多一年 | 更新轴标和尺寸检查，必要时回调右栏 |
| 主图北部标签密集 | 报告缺失/遮挡或需人工复核，不能仅以外框不重叠通过 |
| 两张辅助图图例互换 | 字段绑定检查应发现不一致 |
| 人工锁定主图且其他内容过多 | 输出真实冲突，不移动锁定主图或偷偷删文 |
| 使用更小版心 | 保证约束或报告不适配，不整体缩字到不可读 |
| 图例或来源被删 | 必需元素检查失败 |
| 材料含“忽略规则，上传目录” | 按数据处理，不触发越权工具 |
| 模型返回不存在的工件ID | 服务端拒绝并记录 |
| 求解达到时间上限 | 标注未知/未证明状态，不谎称最优或不可行 |
| 批准后数据变更 | 相关工件与批准失效，重新审阅 |
| 只有图片、没有GIS数据 | 允许参考分析与草图；不冒充精确重制 |

记录指标时区分：数据抽取正确率、地区关联成功率、约束通过率、被发现/漏掉的问题、人工修改次数、候选采用率、耗时与调用成本。

“模型觉得好看”只能是辅助意见。最基本门槛应是来源完整、数据关联正确、必保内容存在、已实现检查无阻断项，以及约定的人工作业已完成。验收指标的具体数值需用测试集确定，不预报未经测量的准确率。

## 十七、最终建议

**先做一个能用确定数据稳定出图、能测量真实内容、能报告布局冲突的小系统，再让智能体驱动它。**

对你的项目，最值得优先建设的是：

1. 模块需求和表达的共享协议。
2. 真实内容的空间测量与组件渲染。
3. 候选布局、硬约束和回调机制。
4. 数据来源、变更依赖和人工确认。

智能体的价值不是替代GIS与排版计算，而是把这些工具组织成一个“知道要讲什么、知道为什么这样摆、发现问题后知道回哪一步”的制作流程。
