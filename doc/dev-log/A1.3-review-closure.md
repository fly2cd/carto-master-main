## 实施详情

### check 步骤重构
- **删除** Manifest 生成（移到 review），不保留后向兼容
- **新增** `_classify_check_failure()`：根据 report.results 中的 check 标签分类失败类型
- **next_step** 从 `deliver` 改为 `review`
- **签名** 不再需要 `recipient_id/destination/idempotency_key`

### review 步骤（新增）
- **审图审批**：G2 票据校验，签名覆盖 check report 摘要
- **Manifest 生成**（从 check 迁移）：调用 `FinalMapCheckService.build_manifest()`
- **deliver 恢复路径**：当 deliver 处于 waiting_approval 时，review 可重入校验 report+manifest（A1.3：G3 后提交不确定时可查状态）
- **next_step** → deliver

### 失败分类
| 分类 | 触发条件 | 恢复路径 |
|------|----------|----------|
| DESIGN_ISSUE | appearance/template/layout 检查失败 | → revise → compile |
| RENDER_ISSUE | render/output/artifact/export 检查失败 | → re-render |
| DATA_ISSUE | data/source/input/encoding 检查失败 | → re-prepare |
| MANIFEST_ISSUE | 清单一致性检查失败 | → review 重新生成 |

### 状态转移更新
```
render → check(pending) → 自动终检
  ├─ failed(DESIGN_ISSUE) → revise
  ├─ failed(RENDER_ISSUE) → retry render
  └─ passed → review(waiting_approval) → 审图审批
                ├─ denied → 回退到 revise/freeze
                └─ approved → deliver(waiting_approval) → G3 → 交付
```

## 关键设计决策

1. **Manifest 归属 review**：自动终检只产生报告，Manifest 在审图通过后生成——确保"终检通过≠可交付"，审图是交付的前置条件
2. **deliver 恢复走 review**：G3 后提交不确定时，通过 review 重入校验（不重复消费 G3 批准）
3. **失败分类嵌入 error.classification**：step-receipt schema 明确支持，下游可据此自动路由恢复路径
4. **check 签名简化**：不再需要 recipient/destination/idempotency_key（这些属于交付语义，应在 review 中提供）
