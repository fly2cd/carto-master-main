# A3.1 专题核心重构：实施与验收记录

日期：2026-11-13（Asia/Shanghai）

状态：四步核心实现已落地；受限工程能力，不等同于真实业务试点或生产准入。

## 一、目标和范围

按四个步骤实施：统一业务接口 → 数据与语义绑定 → 有限专题表达 → 共享工作流验收。

这不是“在旧栅格流程外加一个矢量开关”。本次删除几何类型的版本推断、旧请求 encoding 入口、页面标题等于任务 goal 的约束，以及成品审查挪用 G2 的做法；让设计选择显式进入请求、简报、计划、候选和锁。

保留合理的已有能力，不保留兼容分支。运行入口仍唯一位于 `skills/carto-agent/`，没有新增第二套场景状态机。

> 工程验证使用临时目录内生成的合成数据、真实本地 GIS/渲染依赖和测试签名。它不能替代实际业务数据核验、真实审批或生产准入。`production_enabled` 保持 false。

## 二、四步交付

### A3.1-a：统一接口与责任

- 请求显式声明 `geometry`、`map_title`、各面板 `design`。
- 能力档案声明 `template_geometry` 与 `renderer_id`。`@3.0.0` / `@4.0.0` 只是已登记模板资产身份，不充当类型判断。
- 矢量模板声明支持的表达集合，依赖锁绑定集合；本次选择的表达由 design 决定。
- MapBrief 绑定完整请求。修订先生成完整新 MapBrief，再验证新 G1；直接批准提案摘要不能推进。
- 审批回执的 subject_id 必须匹配请求中独立审批人的 approver_subject_id，而不是操作者；拒绝操作者自批。模板 T1/TP 和地图 G1/G2/G3 均执行此边界。
- G1/G2 的真实回执保存为内容寻址、不可变快照，锁引用实际存在的文件；用户原始回执文件删除不破坏审计，冻结快照篡改会使锁校验失败。
- G2 仍只负责冻结整体候选和预览。成品审查使用独立 `approve-product-review / validation-report` 签署记录；ProductReview 先落盘，再生成含 review_ref 的 Manifest，最后申请 G3。

### A3.1-b：数据与业务语义

- `attribute_join` 支持明确字符串键的一对一 CSV 连接：冻结几何与表格字节，保留字段选择、行匹配和提取摘要证据。
- 解析复用 A2 CSV 提取器。重复键、匹配不全、覆盖已有字段、非有限数值、来源摘要漂移与缺少 join 权限均拒绝。
- `measurement` 和 `unit` 必须明确。密度/比率可声明分母字段及比例因子，程序执行计算并验证分母，不按字段名猜含义。
- 准备数据中的实际属性进入事实摘要、计划和渲染；不是仅增加一份描述性元数据。
- 补齐接入处发现的 A2 普通素材证据问题：素材字节、提取与采用记录持久化，data-facts 真正落盘，候选重验事实与快照摘要；同一材料重复准备保持稳定。

### A3.1-c：有限专题表达

| 表达 | 当前执行规则 | 重要边界 |
|---|---|---|
| 已分类栅格 | 显式选择 categorical、读取 ready 合同 | 配色仍来自准备合同，未实现任意连续栅格分级 |
| 矢量类别 | 单一符号或明确类别/标签/符号 | 不补缺类别、不猜字段、不自动删类 |
| 分级设色 | 面数据；等距或手工断点；密度/比率/归一化指标 | 原始总量不能冒充合适的面设色度量；分母、断点和符号数检查失败即停 |
| 比例符号 | 点数据总量；半径按数值平方根推导，使面积成比例 | 明确零值与越界策略；不通过钳位伪造比例关系 |

MapPlan v4 保存每个视图的设计、源引用、表达目录引用、实际 encoding 和统计结果。候选编译会重算验证它们；渲染器只消费闭合后的计划与场景，不再选择表达。

模板是能力和复用资源，不是本次业务决策的来源。当前仍显式选择已登记模板；自动找模板、无模板项目设计、任意布局属于后续范围。

### A3.1-d：共享工作流与恢复

```text
intake → brief → G1 → compile → preview → G2 → freeze
                           ↑      │
                           └─ revision-brief → 新 G1 → revise
freeze → render → check → review → DeliveryManifest → G3 → deliver
```

- 新设计使用 `revisions/rN/` 不可变目录；请求、简报、计划、候选、预览均有各自版本路径，旧步骤引用不因切换设计而失效。
- 状态事务原子切换输入指纹；修订中断可针对同一暂存提案恢复，预算不会重复计费，冲突提案不覆盖。
- 修订不能引入原允许能力集合以外的操作，例如没有 classify 权限时，不能通过改 design 偷偷启动分级。
- `revise` 返回新的 request_path。后续命令使用新路径；旧请求和旧 G2 不能推进新设计。
- 冻结后修改设计使用新运行，不就地修改旧锁。普通 retry 不是修订接口。
- nonce 精确核对回执、运行和批准对象；相同事务可恢复，跨对象/运行/回执复用拒绝。地图审批增加执行环境匹配。
- ProductReview 不可变、重试稳定，交付验证该审查记录与最终报告/运行/项目的绑定。
- 终检发现输出篡改时，由检查服务生成失败报告并推进 failed/check；不能由加载器提前抛错而把工作流留在 pending/check。

### 覆盖的验收责任

验收覆盖：

1. 类别、密度分级和总量比例符号真正到达渲染器。
2. 固定断点下改变 CSV 数值，实际 PNG 像素变化，不只比较文件摘要。
3. 分母无效、语义不匹配、缺失/越界/孤立记录和越权连接拒绝。
4. 修改后的完整 MapBrief 才能取得 G1，旧 G2 拒绝新预览。
5. 修订中断恢复、累计两次修订和预算耗尽、全部旧产物不覆盖。
6. 成品 review 不能使用 G2，审查证据进入 Manifest，中断可恢复、篡改拒绝。
7. 普通素材重复准备稳定，原文件变化不破坏已冻结版本，冻结快照被篡改会拒绝。
8. 栅格单图、多图和共享图例回归；矢量模板四种表达 × 六种网格共 24 组真实样张验证及发布。
9. 独立审批人、禁止新增未授权分级操作、真实审批快照和篡改拒绝。
