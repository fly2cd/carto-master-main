## 实施阶段详情

### 阶段 1：持久化累计预算 ✅

- `BudgetStore`：JSON 文件持久化（`work_root/.budget-state.json`）
- 原子写入（`atomic_json`），Schema 验证
- `load(defaults=...)` 支持自定义限额
- `save(budget)` 持久化当前计数器
- 集成到 `MapGenerationWorkflow.__init__()`，所有步骤可用

### 阶段 2：设计修订提案 Schema + 校验器 ✅

- `design-revision-proposal.schema.json`：
  - 6 个 required 字段：schema_version、proposal_id、run_id、parent_revision、changes、justification
  - changes 对象：可选 goal、layout_parameters、cartography，1-8 个变更项
  - additionalProperties: false，拒绝未知变更类型
- 校验器：由 SchemaRegistry 统一验证

### 阶段 3：revise() 工作流步骤 ✅

- 入参：`request_path`、`proposal_path`、`approval_path`、`approval_key`
- 入口步骤：compile 或 preview
- 执行流程：
  1. 加载并验证修订提案 Schema
  2. 检查预算（消费 revisions 计数）
  3. 验证 G1 审批票据（签名覆盖提案摘要）
  4. 应用变更到请求（goal/layout_parameters → 更新 generate-request.yaml；cartography → _design_overrides）
  5. 重新生成 brief（revision+1、purpose 更新）
  6. 版本化旧候选产物到 `candidates/v{n}/`
  7. 持久化修订提案到 `revisions/proposal-r{n}.yaml`
  8. 完成步骤：succeeded → next_step="compile"
  9. 保存预算状态
- 出参：state、receipt、proposal_id、revision、changed_fields

### 阶段 4：CLI + 测试 ✅

- CLI：`carto generate-map revise <request> --proposal <proposal.yaml> --approval <approval.yaml>`
- 测试：16 个测试全部通过

## 关键设计决策

1. **修订提案独立审批**：revise 步骤验证 G1 票据，签名覆盖 proposal 摘要；compile 步骤重新 G1 审批再生效的 brief
2. **候选版本化**：修订时将旧候选移到 `candidates/v{n}/`，保留追溯链
3. **预算持久化**：BudgetStore 使用原子 JSON 写入，跨 CLI 重启不丢失
4. **cartography 变更**：作为 `_design_overrides` 存储在请求中，compile 时由场景编译器读取
5. **修订次数受预算控制**：max_revisions 默认 2，超出后 `EXECUTION_BUDGET_EXCEEDED`
