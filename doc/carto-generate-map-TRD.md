| 版本 | 1.2 |
| 日期 | 2026-09-11 |

本版在三类业务场景方案基础上，补齐 MCP 工具接入、领域知识供给和按需数据准备子智能体。基线明确为“单主智能体 + 确定性工作流”，可在受控委派模式下扩展一个数据子智能体，不要求全面多智能体化。相比模板创建 TRD 的首个洪涝验证样例，本路由扩大了业务验收范围；对应模板和公共内核能力仍须实际实现并验证，不能仅凭本版声明为已支持。政务专题的十个方向目前只明确七项，另三项作为业务目录待确认项，不虚构名称或宣称已覆盖。

本文独立定义地图生成的完整生命周期，不把生成流程写成创建模板流程的后处理步骤。模板契约、规则检查器、包完整性和适配器接口复用创建模板 TRD 的公共定义；本路由拥有自己的入口、状态、审批、数据快照、项目计划、实例锁和交付事务。

文中的目录、Schema、命令和服务接口均为拟实现设计，不代表当前仓库已经提供可执行功能。本次只新增本文，不修改其他设计文档。旧领域稿中的 `map_lock.yaml`、未版本化路径等示意，以两份 TRD 的正式协议为准。

## 一、设计结论

采用“单主智能体 + 独立生成编排 + 共享确定性内核 + 隔离 GIS 渲染”的模块化单体方案。知识和工具是必要的业务支撑；MCP 是可替换的接入协议，在线知识检索和子智能体则按任务需要使用：

```text
用户请求、行程文字及可选业务数据
  → 基于知识证据的顶层路由与场景意图初判
  → 通过受控工具能力检查来源、完善意图与就绪判断
  → 制图简报与模板选择确认
  → 统一数据准备接口〔固定流程或受控数据子智能体〕
  → 场景规划与统一 MapPlan
  → 候选快照与预览验证
  → 必要审批并冻结 MapSpecLock
  → 正式渲染与成品检查
  → 授权范围内交付
```

模型负责理解需求、提出表达方式和解释取舍；程序负责数据统计、空间计算、契约执行、版本固定和交付门禁。地图中的数值、地理关系与证据不能由模型凭空补齐。

保留以下设计约束：

- `MapStyle` 统一称“制图表达规范”，`MapScenario` 统一称“制图场景方案”。
- MapScenario 六契约在生成阶段只读消费，不因每次制图而改写。
- 有模板、部分模板、无模板共用一套流程，不产生“快速但不校验”的旁路。
- 小型机器契约确认后一次解析，大资产、说明上下文和渲染器按需加载。
- 不引入通用表达式执行器、动态加载图或独立的微服务编排平台。
- 不把模块、MCP Server 或 QGIS 工作进程等同于智能体；复杂数据任务可受控委派，数值与空间计算仍由注册工具执行。
- 知识依据须验证来源、版本和适用性；检索结果不自动成为执行规则，MCP 工具也不自动取得额外权限。
- 首期覆盖政务专题制图、应急测绘制图和领导调研用图；场景负责业务理解，任务负责能力选择，模板负责制图规则。
- 首期正式输出为 QGIS 印刷 PDF/PNG；图册、Web 和移动端按能力及证据逐步开放。

## 二、路由边界与独立性

### 2.1 入口判定

| 请求 | 归属 | 原因 |
|---|---|---|
| 用业务数据绘制一张或一组新地图 | `generate-map` | 交付具体地图成果 |
| 从需求、样例或工程提炼可复用模板 | `create-template` | 交付稳定规则包 |
| 保留现有 QGIS/ArcGIS 工程并修改原生对象 | `edit-native-map` | 交付保留工程语义的修改结果 |
| 新增地图表达、符号或标准条目 | `curate-catalog` | 交付受治理的目录项 |
| 将已经生成的 Web 包部署到公网服务 | 外部部署流程 | 属于对外发布，不是地图生成的隐式副作用 |

给定原生工程时区分“参考其内容重新制图”与“保留工程并编辑”。前者可在本路由中按受支持格式只读提取材料；后者交给编辑路由。原生工程不是已注册模板，不能直接把它作为模板包绕过 Schema 和完整性校验。

只给主题、没有地理数据时，可以形成数据需求清单。只有在用户已授权数据来源、访问范围和成本时才执行检索或下载；不能用模型生成的数值冒充业务观测数据。

### 2.2 独立什么、共享什么

| 内容 | 本路由拥有 | 共享边界 |
|---|---|---|
| 用户目标与确认 | 当前任务的制图简报、模板选择和授权 | 复用审批验签、身份与权限机制 |
| 数据 | 真实数据访问、快照、转换链及质量判断 | 复用字段、空间与表达的类型定义 |
| 规划 | 地图清单、具体字段、范围、断点、目标和说明 | 复用契约编译、所有权和检查器 |
| 执行 | 候选快照、预览、冻结、正式渲染和修复 | 复用适配器接口与工作进程 |
| 交付 | 地图成果包、成品验证、目的地与回执 | 复用摘要、持久化及幂等工具 |
| 模板治理 | 不拥有模板版本发布权 | 仓库模块只读发现和安装精确版本 |

不能自动调用 `create-template publish` 来修复地图任务，也不能修改已安装模板、共享标准或目录项。发现模板缺陷时返回明确诊断；如需新模板版本，由用户另行发起创建任务，完成后重新确认选择。

### 2.3 首期业务范围与能力边界

| 业务场景 | 首期覆盖 | 必需制图能力 | 不隐含的能力 |
|---|---|---|---|
| 政务专题制图 | 行政区划、经济发展、科技创新、现代产业、对外开放、文旅融合、交通运输等方向 | 行政边界与驻地标注、统计专题、分类点位、线网层级、经批准的指标比较 | 自动编造指标、未知统计口径或无数据的综合评价 |
| 应急测绘制图 | 地质滑坡、洪涝灾害、森林火灾 | 已核验灾害点/范围、态势要素、应急资源表达及有明确口径的叠加统计 | 从影像自动提取灾害范围、洪涝模拟、火势/滑坡预测 |
| 领导调研用图 | 基于行程描述绘制调研地点、顺序和路线 | 行程提取、地点消歧、路线来源识别、点线符号、序号和名称标注 | 未授权地点查询、擅自优化访问顺序或将直线当实际道路 |

政务专题目标为十个方向，目前明确七项；其余三项须由业务确认后登记。未明确方向不是有效注册 ID，不创建三个空模板充数。首期可以分批上线已验证方向，宣称覆盖全部十项前必须补齐名称、代表任务、数据前提和验收案例。

首期仍以 QGIS PDF/PNG 为正式交付。局部矢量分级设色与比例符号只是其中两项能力，不能替代行政区划、灾害成果表达和调研点线标注的验收。无模板模式复用同一平台基线和注册能力，不另开无约束流程。

应急首期优先将合法取得且已核验的调查、监测和分析成果制成地图，不把制图生成扩展为遥感解译、预测或测绘生产分析。如果确需这些分析，必须显式增加输入、注册算法、精度门槛和专业审核，未具备能力时返回不支持。

调研路线的必需形态由任务合同确定：已有路线可直接表达；示意连线只在用户同意时使用并显式标识；要求沿道路计算时必须有获准的路网、算法和约束，缺失不能以示意线静默替代。首期以本地可信地名/POI 库、已提供路线及获准示意线建立闭环，路网计算按能力声明开放。

不以截图替代真实地图，不承诺仅凭图片恢复准确地理坐标，不默认启动付费服务或公开发布，不建立无锁生产模式。

### 2.4 顶层路由、业务意图与模板的区别

| 层次 | 回答的问题 | 基数与用途 |
|---|---|---|
| 顶层路由 | 生成地图、创建模板还是编辑原生工程？ | 单次任务唯一，当前为 `generate-map` |
| 主业务场景 `business_scene` | 这张地图主要服务什么工作？ | 每个原子地图任务一个，决定规划策略 |
| 主题/灾种标签 | 涉及哪些政务方向或灾害？ | 可多选，用于理解、检索与适用性检查 |
| 制图任务 `map_tasks` | 具体需要做哪些表达或空间操作？ | 可组合，只选择已注册能力 |
| MapScenario | 采用哪套可复用制图合同？ | 由任务与数据前提检索，G1 后消费正文 |

三个场景 ID 固定为 `government_thematic`、`emergency_mapping`、`leadership_visit`。它们是业务配置，不是新的顶层路由，也不是第五类模板，更不为每类新增一套审批、锁和渲染流程。

主题目录首批采用 `administrative_division/economic_development/technology_innovation/modern_industry/opening_up/culture_tourism/transportation` 七个 ID；灾种采用 `landslide/flood/forest_fire`。标签允许共现，不与场景形成完全互斥的分类树。

例如“科技园、港口和洪涝安置点调研线路”主场景是调研，主题可以有科技创新和对外开放，灾种可以有洪涝。若原文只有“受灾安置点”，灾种应保持未知而非自动推定为洪涝。若只标注安置点而未表达灾情，不自动要求洪涝分析；若叠加灾情范围，则必须加载该任务适用的时效、来源和专业检查，不能因主场景不是应急而豁免。

### 2.5 场景意图解析与程序分派

首期采用“大模型结构化提取 + 版本化场景目录 + 程序规则校验”，不建设通用智能体路由器或强依赖向量检索平台。

```text
读取用户目标与已授权输入摘要
  → 提取业务用途、主题、任务、对象、地域、时间及证据
  → 对照场景/任务目录校验合法组合
  → 区分意图歧义、缺输入、缺授权和不支持能力
  → 检索模板摘要并形成 MapBrief
  → G1 确认后派发固定场景规划策略
```

IntentResolver 可通过 DomainKnowledgeService 读取已获准的术语、场景和实体依据，再由模型输出 `MapIntentProposal`，程序校验后持久化 `MapIntent`。每项关键结论带用户语句或来源/知识证据引用；用户修订优先于已失效的旧推断，但不能覆盖安全和专业底线。

确定性判定遵循：先看明确用途与预期成果，再看任务动作和所需对象，最后用主题词辅助。用户明确要求行程点线图时不能因出现“洪涝”转成灾害预测；只写“交通运输”也不能判断是在画路网、客运量还是调研路线。

意图解析与就绪程度分开：

- `intent_status`：`resolved/needs_clarification/unsupported`，表示任务含义是否明确且属于注册任务范围。
- `readiness_status`：`ready/not_ready/unsupported`，表示当前具备执行条件还是缺输入/权限/能力。
- `pending_requirements`：同时列出缺失信息、地点歧义、许可、算法或数据要求及其必须解决的阶段。

意图明确但缺淹没范围属于缺数据；任务是预测火势而首期没有模型属于能力不支持。能解释一句话不代表该任务已注册：目录没有该任务时 intent_status=unsupported；已注册任务因当前部署缺工具而不可执行时 readiness_status=unsupported。二者不能都模糊地写为“请完善需求”。

不以大模型自报置信度大于固定阈值作为执行依据。只有用途和任务一致、当前阶段关键字段完整、证据可追溯、能力可用且获得授权，才可前进；未知或相互冲突的输入允许拒识，不强制归入三个场景之一。

### 2.6 必需信息、消歧与阶段条件

| 场景 | G1 前必须足以确认的信息 | G1 后、冻结前必须解决的信息 |
|---|---|---|
| 政务专题 | 地域/行政层级、指标含义、时点与单位口径、表达目标、数据来源或获准获取方案 | 实际字段、行政版本匹配、统计有效性、分类与比较口径 |
| 应急测绘 | 灾种、事件阶段、任务类型、观测/预测性质、事件时间、来源与用途 | 真实灾情点/范围、时效及精度、可信级别、统计与专业审查 |
| 领导调研 | 行程/地点原文、可用于消歧的地域、查询授权；含线路时再确认顺序和路线形态 | 唯一地点与坐标证据；含线路时补齐具体路线、相应交通约束与点线对应；保密要求始终生效 |

只有影响语义、流程或权限的关键歧义触发确认，例如实际道路路线还是示意线、已有灾情表达还是预测、总量还是增速。字号或普通图例位置在授权范围内使用默认，不逐项打断。

允许文字行程先进入 G1，再按获准来源取得坐标。若用户写“明天”或省略地域，解析必须结合可信请求时间、时区与项目范围，保留原文和推导依据；歧义不能靠坐标猜测解决。具体地点选择无法证明唯一时，在相关执行前发起必要消歧。

### 2.7 跨场景请求与复合成果

单张地图、一个主要用途时使用“主场景 + 辅助主题/任务”。一张调研图叠加受灾范围，仍由调研策略组织，灾害叠加任务的全部适用约束同时生效。选定 MapScenario 必须允许这些图层与任务，不兼容时报告，不合并两份场景契约。

请求同时要求经济发展图、灾害态势图和调研行程图时，在 G1 前提出任务拆分，确认后生成多个子项目/运行。每个子任务有自己的 MapIntent、MapPlan、模板组合、G2、锁和交付证据；每个运行仍最多选一个 MapScenario。

批次可使用 `<batch-root>/tasks/<task-id>/carto/`，批次记录只保存子任务 ID、必需性、批准范围和回执引用，不定义第四套制图生命周期，也不创建跨多个模板的“混合锁”。同一编排器可依序执行，无需多个智能体。

批次 G1 可以一次展示全部子任务，但批准记录必须逐项绑定子任务简报摘要。聚合交付只有全部必需子任务完成才可成功；共享数据以只读快照引用，缓存与权限仍隔离。首期提供类型化任务集合和汇总记录即可，不引入任意任务图。

## 三、领域模型与决策来源

| 对象 | 文件或表示 | 作用 |
|---|---|---|
| GenerateRequest | `request.yaml` | 用户原始目标、来源引用、输出与授权边界 |
| MapIntent | `intent/map-intent.yaml` | 经校验的业务场景、主题/灾种、任务、证据与阶段就绪要求 |
| SourceManifest | `sources/source-manifest.yaml` | 来源证据、权限、时效和格式，不保存明文密钥 |
| KnowledgeEvidence | `knowledge/evidence/<evidence-id>/` | 采用的术语、标准或案例依据及其来源、版本、适用性 |
| DataPreparationTask | `runs/<run-id>/data-preparation/<task-id>/task.yaml` | 批准的数据要求、允许来源/操作、预算与验收条件 |
| PreparedDataBundle | 同目录的 `bundle.yaml` | 数据快照、语义、处理链、工具回执、质量证据及未决项 |
| DatasetSnapshot | `data/snapshots/<snapshot-id>/` 或受控版本 URI | 本次实际读取的数据版本 |
| MapBrief | `brief/map-brief.yaml` | 绑定 MapIntent 修订的业务合同、来源计划、目标、模板与委托范围 |
| MapPlan | `plan/map-plan.yaml` | 可修改的实例决策与未决项 |
| MapDesignSpec | `plan/map-design-spec.md` | 从计划生成的解释、来源和审查说明 |
| ResolvedSnapshot | `candidates/<candidate-id>/resolved-map.yaml` | 可执行但尚未冻结的确定性参数 |
| ValidationEvidence | `reports/<validation-id>/` | 针对内容、数据和环境的检查证据 |
| MapSpecLock | `locks/<lock-id>/map-spec-lock.yaml` | 不可变实例执行权威 |
| RenderPackage | `runs/<run-id>/render/<target-id>/` | 引擎专属中间产物，不拥有业务决策 |
| DeliveryManifest | `deliveries/<delivery-id>/manifest.json` | 成果文件、摘要、来源、限制和交付记录 |

模板的六份契约与这些运行产物不是同一计数维度。每次地图生成无需创建六份新的模板契约；实例字段归 MapPlan，冻结值归 MapSpecLock。

执行来源顺序是“适用的专业与平台约束 + 唯一分段所有者 + 当前任务的有效决定”，不是把所有 YAML 或 Markdown 混合后交给模型自行选择。人读说明不作为机器参数解析入口。

## 四、模块架构与代码组织

### 4.1 在五模块内扩展

沿用创建模板 TRD 的五模块架构，不再新增一套同名编译器或规则引擎：

| 模块 | 本路由的扩展职责 |
|---|---|
| `workflow` | 独立生成流程、意图分派、知识查询编排、统一数据准备服务、按需委派、简报与审批 |
| `compiler` | 组合模板或项目分段、解析绑定与变换、构造候选快照及实例锁 |
| `validation` | 真实数据预检、空间与表达检查、预览验证、成品检查 |
| `adapters` | ToolGateway 的本地/API/MCP 适配、能力探测、候选/正式快照编译与受控渲染 |
| `repository` | 模板发现/安装、知识来源与证据存储、成果存储；三者使用独立权限和语义 |

`IntentResolver`、`TaskDispatcher`、`DomainKnowledgeService`、`DataPreparationService`、`ToolGateway`、`MapPlanner` 等是五模块内的职责对象，不要求独立部署。IntentResolver 提取并校验意图，TaskDispatcher 根据批准任务查固定策略表；默认无独立推理上下文。只有显式启用 DataPreparationAgent 后，该子任务才具有受限的独立上下文与工具选择循环，见第 4.5、6.5 节。

```text
主制图智能体 + GenerateMapWorkflow
  ├─ IntentResolver / MapPlanner ↔ DomainKnowledgeService
  ├─ BriefBuilder / ApprovalGate
  ├─ DataPreparationService
  │    ├─ 固定流程〔默认〕
  │    └─ DataPreparationAgent〔按需〕
  │         └─ 知识查询 + 受控工具选择
  ├─ ToolGateway → 本地工具 / HTTP API / MCP
  ├─ TemplateRepository + ContractCompiler
  ├─ Validator ↔ AdapterWorker
  ├─ LockBuilder
  └─ DeliveryService
```

所有阶段经类型化应用接口运行。模型提案只能进入暂存计划，不直接运行任意 SQL、Shell、GIS 表达式或签发审批。

### 4.3 轻量场景意图目录

`policies/intent-profiles.yaml` 是受信平台配置，不是模板包。它定义场景用途、正反例提示、任务词汇、阶段必填信息和固定策略键，不保存分类阈值、符号语义或地图几何。三份场景规划说明只写差异，不复制生成步骤和门禁。

目录示意：

```yaml
schema_version: 1
catalog_version: 1.0.0
profiles:
  government_thematic:
    strategy_key: government-thematic
    primary_tasks:
      - administrative_map
      - statistical_thematic
      - facility_distribution
      - network_map
    brief_required: [geographic_scope, topic, temporal_scope, map_purpose]
  emergency_mapping:
    strategy_key: emergency-mapping
    primary_tasks: [hazard_result_map, exposure_overlay]
    brief_required: [hazard_types, event_phase, data_nature, temporal_scope, map_purpose]
  leadership_visit:
    strategy_key: leadership-visit
    primary_tasks: [itinerary_map, stop_annotation]
    brief_required: [itinerary_text, geographic_scope]
task_requirements:
  itinerary_map:
    before_brief: [stop_names, route_requirement]
    before_freeze: [resolved_stops, route_geometry, route_provenance]
    operations_by_route_mode:
      provided_geometry: [route-reference@1]
      road_network: [road-route@1]
      schematic: [schematic-route@1]
  stop_annotation:
    before_freeze: [resolved_stops, label_fields]
```

片段省略了其他任务要求，生产目录必须覆盖全部声明任务，不以缺字段表示“无需检查”。路线需求和访问顺序仅对含线路的任务必需，纯地点标注不承担求路义务。`profile_ref` 使用场景 ID 与目录版本组合，并另存有效条目摘要。`strategy_key` 和操作 ID 必须映射到受信注册表，不拼接可执行路径、不运行表达式，也不允许模板重写平台目录。

`primary_tasks` 用于主用途匹配，不代表只允许这些任务；辅助任务使用受控兼容表组合。所有已选任务的前提取并集，不能仅执行主场景检查。专业规则与数值阈值仍由业务契约和检查器拥有，目录只引用其注册 ID，避免产生第二份规则权威。

正式支持由“目录声明 + 工具能力 + 数据前提 + 验收证据”共同决定，填写配置并不代表已实现。目录的十方向目标和七个已确认标签分别记录，不给待确认方向分配虚假有效 ID。

同一业务意图可匹配多个 MapScenario，模板候选仍只从已注册索引的摘要获得；目录不绑定唯一模板路径。G1 后用实际模板契约验证兼容性，前置摘要判断不能代替契约。

### 4.4 MapIntent 持久化协议

以下片段对应明确提到“洪涝安置点”的调研描述；灾种未知时不能填入推测值。

```yaml
schema_version: 1
revision: 1
top_route: generate-map
business_scene: leadership_visit
theme_tags: [technology_innovation, opening_up]
hazard_types: [flood]
map_tasks: [itinerary_map, stop_annotation]
intent_status: resolved
readiness_status: not_ready
profile_ref: leadership_visit@1.0.0
itinerary:
  order_policy: as_provided
  route_mode: null
pending_requirements:
  - code: route_mode_confirmation
    due_before: brief_approval
    repair_owner: user
  - code: resolve_stop_entities
    due_before: freeze
    repair_owner: place-resolver
evidence:
  - field: business_scene
    source_ref: request:segment-001
    basis: 用户要求按行程顺序标注调研地和线路
```

该示例说明任务已识别，但路线形态仍须在 G1 前明确、坐标可在授权后解析。`intent_status=resolved` 不代表全部字段都已可执行；阶段门禁使用 `pending_requirements.due_before` 判断，不要求简报前已有完整坐标，也不允许带冻结前缺项进入 G2。

请求中的 `scene_hint` 是可选提示，不能跳过证据与能力校验。MapIntent 保存修订号、实际目录版本与摘要、解析器版本、来源证据、候选冲突和所选任务；MapBrief 绑定其批准修订。G1 后地点解析等事实补全可形成新修订，在批准范围内通过程序兼容检查关联原批准；改变主用途、任务或路线形态须重新确认，不能重写已批准修订。

### 4.5 单主智能体基线与按需数据子智能体

当前基线是“单主智能体 + 确定性工作流 + 专业工具”，不是多智能体系统。拆分模块、启用多个 MCP Server、并行 GIS 工作进程或拆分多个地图运行，都不自动增加智能体角色。

只有数据准备需要独立的上下文、依据检索、候选比较和有界工具选择时，才启用一个 DataPreparationAgent。此时属于受控主从式协作；不能既宣称已经独立委派，又继续把所有任务视为纯单智能体执行。

| 主体 | 拥有的职责 | 不拥有的权限 |
|---|---|---|
| 主制图智能体 | 业务意图、地图方案、用户沟通、数据需求、有效候选选择与整体协调 | 不能绕过程序门禁或代用户签发审批 |
| 数据准备子智能体 | 在批准范围内查找/比较数据、核对语义、提出处理方案、调用允许工具、交回证据 | 不能改用途、路线形态、访问顺序、模板硬约束或发布成果 |
| 数据与 GIS 工具 | 执行具体查询、统计、空间处理和渲染 | 不自行扩大任务、不决定业务含义 |
| 编译器与校验器 | 类型/契约校验、确定性计算、结果与证据检查 | 不把模型自评当作通过证明 |
| 审批系统 | 根据主体权限和批准政策签发回执 | 不由任意智能体伪造 |

首期不拆成“数据获取智能体”和“数据分析智能体”两个角色。获取与处理经常相互反馈，统一以“交付适用于当前地图的数据包”为边界，减少无效交接。数值和空间计算始终交给工具；子智能体负责判断和协调，不自由编造计算结果、SQL、Shell 或未注册 GIS 算法。

启用条件、交接合同和恢复规则由第 6.5 节拥有。该委派不增加顶层路由、模板类型或 MapScenario 的六份业务契约。

### 4.6 ToolGateway 与 MCP 接入

#### 4.6.1 保持能力依赖，避免协议耦合

主流程依赖“地点解析、指标查询、空间叠加”等版本化能力，不直接绑定某个服务商的 MCP 工具名。ToolGateway 将内部能力映射到本地函数、GIS 工作进程、企业 HTTP API 或 MCP；MCP 可连接本地进程，也可连接远程服务。

对 MCP 协议保持弱耦合是有意的工程选择，不代表工具能力可有可无。数据、地点或路径所需能力缺失时仍须阻断。采用 MCP 也不改变契约、确认、惰性加载和实例锁边界。

```text
invoke(capability_id, typed_input, execution_context) -> ToolResult
```

`execution_context` 由宿主构造，包含项目/租户、有效主体、授权动作、预算、取消标识和追踪 ID，不能由模型填写身份或权限。ToolResult 返回类型化输出、来源/时间/版本、产物引用、诊断和调用回执，不将未校验自由文本直接用于执行计划。

#### 4.6.2 能力绑定示例

```yaml
schema_version: 1
capability_id: place-resolve@1
input_schema: place-query@1
output_schema: resolved-place-candidates@1
backend:
  kind: mcp
  server_ref: approved-place-server
  tool_name: resolve_place
  tool_schema_digest: sha256:<digest>
authorization_policy: project-approved-geocoding
effect_class: external_read
timeout_seconds: 20
retry_policy: bounded-read-only
```

示例是受信平台绑定，不是模板可以提交的执行指令。`server_ref` 指向部署配置，凭据由凭据服务注入。参数和结果适配器负责字段、单位、CRS、轴顺序和错误映射；只改变协议形式，不能改变业务语义。

平台可以发现服务工具清单，但发现不等于获准调用。新增服务、工具绑定和 Schema 变更须通过受控注册与兼容检查。不能仅依赖工具自报的“只读”提示决定权限，也不能让服务器返回的工具描述改写系统门禁。

#### 4.6.3 调用、重试与可复现性

每次调用依序执行：能力查表 → 身份与范围校验 → 输入 Schema 和预算检查 → 调用 → 输出语义校验 → 固定产物/数据快照 → 写调用回执。大型结果保存为受控产物引用，模型只接收必要摘要。

回执至少包含能力及绑定版本、服务/工具标识、输入摘要、脱敏参数引用、输出摘要、实际数据版本、执行时间、主体授权引用和重试记录。外部调用结果被采用前，仍须执行字段、单位、坐标、完整性与来源检查。

只对明确允许且可安全重试的调用有限重试。带外部写入、发送或发布副作用的能力要有独立授权及幂等策略；超时后先查询结果，不能盲目重复。取消需传播到客户端/任务句柄；远端无法取消时保留未完成状态，拒绝晚到结果影响已关闭运行，并持续核对可能的外部副作用。

工具 Schema 不变不证明底层算法或数据不变。用于生产执行的服务要提供足够的版本/结果证据；必要时物化输出快照。无法证明处理语义或固定结果时不能声称可重放。适配器版本、绑定、输入和采用结果进入锁或其不可变引用，后续重放可复用已固定产物，不要求再次访问远端服务。

### 4.7 DomainKnowledgeService 与知识治理

#### 4.7.1 知识是业务依赖，在线检索不是每步必需

模板和静态配置已承载部分专业知识，但不足以覆盖指标解释、地方规则、实体别名和例外判断。DomainKnowledgeService 为意图、绑定、规划与审核提供证据；它是逻辑职责，不要求独立微服务。

必须区别知识、业务数据和执行规则：

| 类别 | 示例 | 访问与使用方式 |
|---|---|---|
| 术语/指标知识 | GDP 增速、研发投入强度的定义及口径 | 结构化字典与证据查询 |
| 规范/标准知识 | 符号含义、辖区、有效期、精度要求 | 版本化条款与适用性检索 |
| 实体知识 | 机构简称、曾用名、园区关系、地名别名 | 稳定实体 ID 与可信关系查询 |
| 方法与案例 | 分级设色的适用条件、常见误用 | 带来源的文档与案例检索，通常为参考 |
| 业务事实数据 | 某年 GDP 数值、当前火点、地点坐标、道路状态 | 结构化服务或地理数据查询并固定快照 |
| 已执行规则 | 不可降低的质量基线、模板约束、注册检查器 | 确定性加载和执行，不依赖检索排名 |

不能把所有数值、坐标和动态状态塞入向量库，让模型凭相似度输出事实。首期采用“结构化字典 + 带元数据的文档检索 + 受控实体查询”即可，向量检索和知识图谱按证据需求扩展，不作为所有任务的必需基础设施。

已固定且仍获准使用的知识证据可本地复用，冻结后的渲染不依赖在线知识服务可用性。但当前权限、失效或撤销政策仍须检查。

#### 4.7.2 知识接口与证据

```text
lookup_or_search(query, applicability, access_context) -> KnowledgeEvidence[]
```

查询先应用租户/项目权限、地域、有效时间、来源类型和语义对象等过滤，再做精确查询或文本检索；向量召回可作为补充，不替代权威判断。KnowledgeEvidence 至少保存来源 ID、版本、发布机构、条款/字段定位、内容摘要、适用范围、检索时间、许可、关联决策和冲突状态。

```yaml
evidence_id: knowledge-001
source_ref: approved-indicator-dictionary
source_version: "2025.1"
locator: indicators.gdp_growth
content_digest: sha256:<digest>
authority_class: official_dictionary
applicability:
  jurisdiction_ref: approved-city-id
  valid_at: "2025-12-31"
used_by: plan:indicator-binding
adoption_status: candidate
```

元数据由受控来源目录核验，不能因为检索结果自己声称“官方”就提升权威。示例不意味着某份实际字典已经存在。保留足够的原文与限定条件，使采用结论可核查；敏感或版权受限内容保留受控版本引用与获准摘录，不能随成果整库分发。

#### 4.7.3 从检索到执行的边界

知识采用流程是“获取依据 → 核验来源与版本 → 判断时间/地域/对象适用性 → 检查冲突 → 形成有效决定或引用已审查规则”。相似度最高的文本不自动成为强制规范，案例也不能覆盖法规或用户已确认事实。

适用强制规则应通过注册基线和标准适用性清单确定，不能只依赖语义检索的前若干条结果。新发现的专业义务尚未机器化时，进入指定人工审核；需要新增契约或检查器时走受控治理，不在本次运行让模型动态编译/安装规则。知识不足、冲突或过期时保留待决项，不以模型记忆补齐。

G1 前允许检索获准的通用术语、标准与实体元数据，以便理解任务；确认限制针对候选模板正文，不是禁止一切领域知识。但不得把未确认模板正文投进知识库再检索出来，也不能绕过数据获取授权查询敏感行程地点。

G1 后使用相关完整专业依据完成绑定和规划；采用的证据版本、具体决定及引用进入 MapPlan，冻结时固定到锁。知识证据和数据包在被固定后不可原地更改；采用状态、纠错或内容更新以新记录/新修订表达，避免摘要指向可变文件。未采用的候选检索结果可保留在受控诊断记录中，不参与执行摘要或影响已冻结决定。

#### 4.7.4 来源维护、冲突与降级

每类知识有指定维护者、来源信任级别、版本和更新/撤销规则，记录批准人及变更原因。缓存和检索结果按权限隔离，撤销或失效不能只靠缓存到期处理。

来源冲突按适用范围与明确权威处理，不能平均或拼接两套统计口径。已批准的等价来源切换可以记录后使用，语义不同、版本变化或缺少权威依据则返回上游；服务不可用时只复用仍有效的固定证据，不自动改用互联网相似文本。

场景目录解释任务，知识服务提供依据，契约决定可执行边界，校验器证明本次结果是否满足要求。四者各有所有者，不复制同一强制规则形成多重权威。

```text
│  └─ resolved-map.yaml
├─ locks/<lock-id>/
│  └─ map-spec-lock.yaml
├─ output/<lock-id>/<target-id>/<attempt-id>/
├─ reports/<validation-id>/
├─ deliveries/<delivery-id>/
│  ├─ manifest.json
│  └─ receipt.json
├─ runs/<run-id>/
│  ├─ approvals/
│  ├─ data-preparation/<task-id>/
│  │  ├─ task.yaml
│  │  ├─ bundle.yaml
│  │  └─ receipts/                  # 工具回执与受控委派记录
│  ├─ revisions/
│  ├─ previews/<candidate-id>/
│  ├─ render/
│  ├─ steps/
│  └─ run-state.json
└─ run-state.json                    # 本地最新运行指针/摘要
```

项目 ID 标识长期业务工作区；run ID 标识一次生成或修订尝试；lock ID 标识不可变执行输入；delivery ID 标识一次授权交付。四者不能混用。

根级 MapPlan 是当前工作副本，每次修改归档带摘要的修订版本。每个运行的输入引用固定到具体修订，不能靠“读取最新文件”恢复。首期一个项目只允许一个活动写者，采用项目锁及修订号比较；跨项目可以并发。共享模式以数据库作业记录为权威，文件状态是其可重建视图。

已有锁、候选、数据快照、验证证据和成功成果不覆盖。失败尝试使用独立目录；清理由保留政策执行，不能在失败恢复时删除用户数据或历史可追溯结果。

## 六、请求、数据接入与快照

### 6.1 请求模型

以下是字段结构示例，不是完整 Schema：

```yaml
schema_version: 1
project_id: flood-risk-daily
intent: 制作城市洪涝风险研判图
scene_hint: emergency_mapping
hazard_types: [flood]
audience: 城市应急指挥中心
decision_goal: 查看风险空间分布与避难场所容量
execution_mode: production
temporal_scope:
  observation_at: "2026-09-11T08:00:00+08:00"
  timezone: Asia/Shanghai
sources:
  - id: risk-source
    uri: "file:///D:/carto-input/daily/risk.gpkg"
    layer: risk_regions
  - id: shelter-source
    uri: "file:///D:/carto-input/daily/shelters.gpkg"
    layer: shelters
outputs:
  - id: print-a3
    required: true
    formats: [pdf, png]
delivery:
  mode: local
  destination_ref: project-output
constraints:
  allow_network_acquisition: false
  allow_data_redistribution: false
```

文件 URI 是输入标识，工具在权限检查后解析。禁止把来源文本中的路径、URL 或指令直接当作新的访问授权。

### 6.2 接入阶段的允许操作

确认模板之前先完成文本级意图初判，再按任务做与模板无关的数据可用性检查：来源存在性、访问权限、格式、字段、记录数、原始 CRS、观测时间、许可和敏感等级。小样本可用于诊断，但最终分级和正式质量结论必须来自本次完整数据或明确批准的统计算法。

深度处理或大量网络读取须满足来源授权和预算。具备敏感信息的数据默认不完整注入模型上下文；模型接收类型、分布和错误摘要，需要行级样本时脱敏并记录理由。

文字行程是合法的一等输入，`sources` 可暂为空；请求 Schema 要求有行程文字、可消歧地域及拟获取来源/权限，而不是伪造空 GeoJSON。基础接入保存原文和必要附件摘要，G1 前不擅自调用外部地理编码或路网服务。

G1 批准后，计划阶段通过 DataPreparationService 先执行已授权的数据准备：地点查询、路线读取或注册路网计算，将返回结果保存为带来源版本、时间和许可的快照，再进入普通绑定与编译。该行为属于上游数据准备，不允许正式渲染器临时联网补点或重算路线。无法获得唯一地点时保留候选与证据，发起必要消歧或返回阻断。

### 6.3 快照一致性

| 数据来源 | 可接受的版本固定方式 | 不足以证明一致性的方式 |
|---|---|---|
| 本地文件 | 一致性复制后校验摘要，或受控不可变文件 | 只记录路径或修改时间 |
| GeoPackage 等数据库文件 | 关闭写入后的副本或数据库备份接口的一致性快照 | 活跃写入时直接复制主文件而忽略 WAL |
| 数据库服务 | 事务一致性查询、固定快照标识及结果摘要，必要时物化 | 在不同时间重跑同一 SQL |
| 对象存储 | 不可变对象版本加摘要 | 可被覆盖的裸 URL |
| 分页 API / 瓦片服务 | 快照令牌或完整受控物化，记录分页/瓦片清单与摘要 | 把未验证 ETag 当作全量内容哈希 |

多个来源无法提供同一事务快照时，声明可接受的时间差并验证。非空输入不能因查询分页失败而悄悄变成不完整数据集。

快照记录源 CRS、字段定义、单位、观测时间、获取时间、查询参数摘要、记录数、空间范围、内容摘要和来源许可。查询涉及凭据时只保存连接标识与脱敏参数。

数据不能合法复制时，可以引用企业受控不可变版本和访问凭据标识，但执行前仍须验证可读性与版本。若无法锁定来源，不得声称可复现；生产模式要求补充快照能力或退出正式交付。Fixture 不能回填缺失的业务数据。

### 6.4 实时数据边界

首期每次运行取一个固定快照，不实现“渲染时持续读取最新数据”。后续实时地图应把一次更新视为新的数据修订和运行，明确更新频率、缓存、可用性与时间提示；不能在同一不可变锁中替换数据。

### 6.5 统一数据准备接口与受控委派

#### 6.5.1 先建立职责边界，再选择执行方式

```text
prepare_data(approved_requirements, execution_context) -> PreparedDataBundle
```

DataPreparationService 统一拥有任务持久化、权限/预算、执行选择、工具回执和结果验收。它位于生成流程内部，不是新的顶层路由。主流程只消费标准数据包，不依赖内部采用固定流程还是子智能体。

| 数据任务 | 首期默认方式 | 原因 |
|---|---|---|
| 已给定文件、字段和明确变换 | deterministic | 没有必要新增独立推理角色 |
| 已知 Join、换算、重投影、裁剪或叠加 | deterministic | 程序计算更稳定、可检查 |
| 多个获准来源需要比较语义与适用性 | agent_assisted，部署启用时 | 需要迭代查询、证据比较和方案建议 |
| 地点别名、多候选、元数据不完整 | agent_assisted，或主智能体按同一接口处理 | 存在受控的语义判断 |
| 未注册的预测或专业分析 | unsupported | 增加智能体不等于获得分析能力 |

`data-preparation-policy.yaml` 定义允许方式及触发条件。首期固定流程是基线；只有子智能体运行时、工具绑定和验收均已实现，才开放 `agent_assisted`。模式选择及理由记录在任务回执中，不以主观置信度或“步骤较多”直接启动。

默认在 G1 之后委派；G1 前只进行已有授权覆盖的来源诊断和通用知识查询，不把未来可能获得的授权提前授予子智能体。

#### 6.5.2 输入合同

主制图智能体提出数据需求，编排器将它绑定到有效 G1 后生成任务：

```yaml
schema_version: 1
task_id: prepare-001
run_id: run-001
mode: agent_assisted
approval_ref: approval:<g1-id>
intent_ref: intent:<digest>
requirements:
  roles: [risk_regions, shelters]
  geographic_scope_ref: scope:<digest>
  temporal_scope_ref: time:<digest>
  required_quality_ref: policy:<digest>
allowed_source_refs:
  - approved-risk-dataset
  - approved-shelter-directory
allowed_capabilities:
  - dataset-query@1
  - convert-unit@1
  - spatial-overlay@1
knowledge_scope_ref: approved-emergency-knowledge
budget:
  max_tool_calls: 20
  max_iterations: 5
  timeout_seconds: 300
output_scope: project-data-staging
```

此例是结构示意，角色应引用完整的字段语义、单位、CRS/精度、时效与验收要求，工具 ID 必须实际注册。预算值是示例而非统一生产阈值；成本、外部调用和并发配额还受平台上限限制。

任务不可携带可任意提权的凭据、工具路径或自由执行代码。实际权限是“原主体权限 ∩ G1 批准范围 ∩ 任务允许集合 ∩ 平台政策”，委派不能扩大任何一项。更换源、方法或费用超界时返回 NeedDecision，不由子智能体自己批准。

#### 6.5.3 有界执行与独立验收

固定流程和子智能体共用来源快照、ToolGateway、知识服务和注册计算工具。子智能体可以比较候选、提出变换、调用许可能力、评估错误后采取下一步，但不能修改模板、MapPlan 已确认业务字段、锁或交付目录。

执行循环受任务预算约束：检查尚缺要求 → 查询依据或调用允许工具 → 保存观察/产物引用 → 更新候选数据包 → 验证；完成、缺决策、能力不支持、预算耗尽或取消时结束。首期不递归创建子智能体，不把获取和分析拆成相互无界调用的角色。

子智能体交回候选 PreparedDataBundle，DataPreparationService 调用独立的确定性校验器验收。需要专业人工判断的事项仍进入门禁；子智能体声明“已准备好”不能替代验收。

#### 6.5.4 输出合同与采用规则

数据包至少包含：

- 任务、批准需求及模式引用。
- 固定的数据快照和派生数据引用及摘要。
- 字段、单位、时间、CRS、几何、范围与精度说明。
- 每个来源和已采用知识依据的版本、许可和适用性。
- 处理操作、输入参数、输入输出摘要及工具调用回执。
- 质量报告、异常、缺失、未决项和替代方案。
- 对哪些数据角色已满足、未满足及其原因的明确说明。

```yaml
schema_version: 1
task_id: prepare-001
requirements_digest: sha256:<digest>
preparation_status: prepared
datasets:
  - role: risk_regions
    snapshot_ref: dataset:<digest>
  - role: shelters
    snapshot_ref: dataset:<digest>
metadata_refs: [metadata:<digest>]
transformation_refs: []
knowledge_evidence_refs: [knowledge:<digest>]
tool_receipt_refs: [tool-call:<digest>]
validation:
  status: passed
  report_ref: validation:<digest>
unresolved: []
```

上述 passed 由服务根据真实校验结果写入，不接受模型直接签发。`preparation_status` 使用 `prepared/needs_input/unsupported/failed`；prepared 仍需检验报告有效、必需角色完整和 unresolved 无阻断项才可被 MapPlan 采用。

主流程通过类型化接口采用数据包，不拼接子智能体对话作为执行输入。需要变更指标、数据时间、地点选择或访问顺序时，按原所有权由主智能体或用户决定并形成新批准任务，不能“修好数据”后掩盖业务变化。

#### 6.5.5 恢复、取消与三类场景应用

任务使用原 run ID 下的 task ID，不另造业务审批生命周期；首期每个数据准备任务最多启用一个子智能体，不允许两个写者同时改同一候选数据包。独立子上下文只保存最小需求、相关规则、来源和已提交观察，不继承全部聊天或其他项目秘密。任务文件、工具回执和产物是恢复依据，不依赖保存隐式推理过程。

固定需求、许可和输入指纹未变时复用已验证结果；知识、来源、工具绑定或政策发生相关变化时重新验收。取消同时约束子智能体循环和工具任务，晚到结果只能留作受控诊断，不能重新打开已关闭任务。发布/外部副作用按第 4.6 节独立核对。

政务侧重点是指标与行政口径核验，应急侧重点是时效、精度和数据性质，调研侧重点是地点消歧与路线证据。三者共享数据准备合同，输出质量不因是否使用子智能体而改变。

## 七、制图简报、确认与自动执行

### 7.1 简报内容

MapBrief 在接入摘要基础上确定：

- 绑定的 MapIntent 修订、主业务场景、主题/灾种、制图任务及解释证据。
- 面向谁、回答什么问题、核心指标与明确不作出的结论。
- 地域、行政区版本、时间基准、最小空间单位及隐私限制。
- 数据来源和真实/模拟性质，时效、缺失及允许转换。
- 地图或图幅数量、输出目标、必需格式、主要标注与署名。
- 模板模式及每个 kind 的精确候选版本，或明确自由设计。
- 允许系统自动决定的字段、参数范围、回退和性能预算。
- 可使用的知识来源、工具能力/服务绑定、数据准备方式及委派上限；对子智能体不增加任何源访问或发布权限。
- 场景专有决定：政务指标口径；应急事件阶段与观测/推断/预测性质；调研顺序、路线形态及地点/路网查询范围。
- 输出目的地、可分发内容及是否需要专业复核。

简报是业务沟通合同，不提前写死所有坐标和渲染参数；模板正文确认后才读取，避免候选设计反向决定尚未确认的业务目标。

### 7.2 三个门禁

| 门禁 | 时间 | 确认对象 | 默认行为 |
|---|---|---|---|
| G1 制图合同 | 读取所选模板正文前 | 意图及简报摘要、任务集合、数据获取范围、路线形态、模板选择与委托范围 | 显式确认或验证已有授权 |
| G2 实例冻结 | 预览与验证通过后 | 候选参数、数据包、已采用知识/工具证据、预览摘要与剩余风险 | 人工确认；在 G1 委托范围内可由政策评估器批准 |
| G3 成果交付 | 成品检查后 | 成果摘要、目的地、权限、许可和合规 | 所有运行必做鉴权；需要时追加人工发布审批 |

G2 的自动批准不等于省略门禁。只有预先批准的类型化政策能够证明候选完全在授权范围内且门禁通过时才可签发回执；涉及语义变化、标准冲突、未批准数据源或无法判断的专业风险必须阻断。生产 Schema 不允许演示参数降低门禁；`demonstration` 必须带醒目标识、隔离目的地，不能通过改一个模式字段升级为生产结果。

用户要求“直接执行、不要询问”只允许在已有权限和委托范围内自动继续，不授予任意外部下载、数据泄露或公共发布权。非交互任务无法获得必需授权时返回结构化阻断原因，不伪造确认。本条描述未来产品行为，不要求当前文档写作增加确认步骤。

### 7.3 审批证据

复用共享审批机制，至少绑定身份、认证来源、动作、目标对象摘要、项目、环境、授权范围、有效期、防重放 ID。哈希不是批准证据，模型不能签发审批回执。

G1 固定业务边界和场景任务，G2 固定含地点/路线证据的候选内容，G3 固定成果与目的地。不同阶段的批准不得互相替代。新的同权威决定可以替换旧业务决定，但要保留修订、重新验证并生成新锁。

## 八、模板消费、无模板模式与惰性加载

### 8.1 三种输入形态，共用同一流程

| 形态 | 规则来源 | 生成侧行为 |
|---|---|---|
| 场景模板，可搭配其他类型 | MapScenario 六契约和显式同类型覆盖 | 解析所有权并实例化 |
| 只有 Brand / Style / Layout | 已选模板负责自己的分段，其他分段由项目定义 | 校验项目规则完整性，不补造场景模板 |
| 不选模板 | 已确认简报、项目分段、平台基线和注册表达 | 生成当前项目 MapPlan，不创建或发布模板包 |

先根据已解析用途、任务和数据前提检索模板摘要，不直接把“经济发展”等主题映射为一份模板。场景意图目录可以在 G1 前读取，候选模板正文仍禁止提前读取。

同一运行每个 kind 最多一个精确版本。显式 Brand、Style、Layout 对应分段整段替换场景内置分段，不逐字段混搭。没有模板时也必须具有完整数据含义、空间策略、表达绑定、交付参数与质量检查，不能让“自由设计”变成无约束渲染。

用户可以在契约允许的范围内选择算法、色阶或版式变量；不能把修改模板硬约束包装成普通项目覆盖。需要真正修改模板时退出到独立创建任务，保留本次失败和待决项。

### 8.2 六契约如何在生成时被消费

| 场景文件 | 消费阶段 | 对当前地图的约束 |
|---|---|---|
| `scenario.yaml` | 规划 | 场景目的、必需角色、内置身份/表达/版式及替换边界 |
| `data.schema.yaml` | 数据绑定及预检 | 字段语义、单位、几何、时效、Join 与缺失策略 |
| `spatial-behavior.yaml` | 空间规划及处理 | CRS、量测、适用范围、概化和误差预算 |
| `portrayal.yaml` | 表达规划及编译 | 图层依赖、编码、符号、标签、图例和尺度样式 |
| `delivery.yaml` | 目标规划及交付 | 正式目标、输出参数、图册和交互义务 |
| `quality-gates.yaml` | 预检、预览、成品检查 | 基线与已注册检查器及其允许参数 |

这些文件的名称、边界和规则标签以创建模板 TRD 第九至十二节为公共权威；本路由只增加真实数据和当前实例决策，不重新定义另一套模板契约格式。

### 8.3 确认后的加载算法

1. 对候选模板，G1 前只读取索引/注册表摘要和 Manifest；通用知识查询按第 4.7 节的权限与阶段规则执行，不能借知识检索读取未确认模板正文。
2. G1 固定选择后，将精确版本及依赖安装到项目，校验摘要、发布状态和安全政策。
3. 一次解析所有选中包的小型机器契约及固定规则依赖。
4. 确定有效所有者、标准适用性、正式目标与平台最低基线。
5. 向规划器提供本次完整有效约束和必要解释，不把所有包正文全部塞入上下文。
6. 原型、字体、Logo、符号按已批准引用加载；只启动实际目标的适配器与确有调用需要的工具后端。未启用数据子智能体时不加载其角色上下文。
7. 目标、模板或决策修订时重新编译，不依靠动态触发器反复收敛。

安装时为校验读取文件字节，不等于模型阅读全部内容或启动所有渲染模块。模板发布时的 Fixture 验证证据只证明模板能力，不证明当前业务数据、环境和地图成果合格。

标准和安全规则在相关决策前必须生效；符号图像可以延迟读取。加载失败、文件越界或摘要不符直接阻断，不使用缓存外旧版本或相似模板替代。没有正式支持证据的目标不能在生产任务中临时启用。

## 九、MapPlan 与规划算法

### 9.1 计划骨架

```yaml
schema_version: 1
project_id: flood-risk-daily
revision: 1
brief_ref: brief:<digest>
intent_ref: intent:<approved-or-compatible-revision-digest>
business_scene: emergency_mapping
theme_tags: []
hazard_types: [flood]
map_tasks: [hazard_result_map]
profile_ref: emergency_mapping@1.0.0
template_selection:
  mode: scenario
  packages:
    - kind: map-scenario
      id: urban-flood-risk
      version: 1.0.0
      digest: sha256:<digest>
dataset_refs: []
prepared_data_refs: []
knowledge_evidence_refs: []
tool_binding_refs: []
ownership: {}
bindings: {}
processing: []
views: []
spatial: {}
portrayal: {}
targets: {}
validation_policy_ref: carto-print@1.0.0
decisions: []
open_issues: []
```

此处空集合是说明结构；可执行候选必须补齐实际字段且不得有未解决的阻断项。计划使用稳定的 `view_id/layer_id/role_id/target_id`，不能用数组位置或显示标题作为长期引用。

`decisions` 记录选择值、来源与理由，来源采用 `fact/decision/suggested/derived`。模型建议在被合法采用前不能变成“观测事实”。

### 9.2 确定性规划步骤

1. 校验意图、G1 与目录版本，选择唯一主场景策略；按任务读取适用知识依据、生成批准数据要求，经 DataPreparationService 获得验证后的数据包。
2. 解析模板或项目分段与任务约束，按语义和类型匹配数据角色，列出冲突和无法证明的候选。
3. 注册必要的数据转换与空间操作，生成有版本的处理计划。
4. 为每个视图明确要回答的问题、数据子集、比较关系和目标。
5. 依据量纲与任务选择已注册 Map Encoding，计算完整数据统计。
6. 解出实际范围、尺度、CRS、分类、色板、符号和图层顺序。
7. 完成布局槽位、标注、图例、来源及不确定性说明。
8. 协商目标能力与预算，生成无未决参数的候选快照。
9. 执行静态检查后渲染预览，以证据驱动计划修订。

“解出”指已实现的类型化算法和约束检查，不构建通用约束求解器。冲突无法按规则解决时返回拥有该决定的层，不平均混合两套规则。

### 9.3 模型与程序的决策分工

意图阶段先输出并校验 `MapIntentProposal`；规划阶段再输出类型化 `PlanProposal`，包含地图目的、建议编码、布局候选和解释。编排器先校验 proposal Schema，再通过已注册工具计算实际统计和空间结果，最后合成 MapPlan；不能让模型直接写入一个自称已验证的执行锁。

数据字典、标准规则、模板约束和工具结果使用可追溯引用。领域知识检索与采用遵循第 4.7 节，不把语义相关文本直接提升为规则。模型上下文保留本次需要的完整约束，不仅保留摘要结论；请求只包含必要字段和脱敏样本。模型不可用时可保存已完成决定并恢复；对于已有完整批准计划的运行，确定性渲染和交付不必依赖模型在线。

### 9.4 地图清单与多图关系

每个视图至少声明用途、数据过滤、空间范围策略、编码引用、布局引用、必需信息、所属目标和比较组。图册或小倍图还需要稳定顺序、系列 ID、共同单位、分类口径和范围策略。

并列地图不能默认分别计算 Jenks 后继续共享同一个图例。比较组必须选择并记录：

- 同一批数据联合计算断点；
- 引用固定的行业或业务阈值；
- 保留各自断点并明确显示不同图例及不可直接比较的限制。

图层组织关系、计算依赖、绘制顺序和遮罩关系采用明确类型。计算依赖做环检测；绘制顺序按稳定规则确定，不能因数据库返回顺序变化而改变。

### 9.5 三类场景规划策略

#### 9.5.1 政务专题制图

先明确地图目的，再选择指标和表达，不能看到“经济发展”就自动绑定 GDP 总量。

| 主题 | 代表任务 | 关键约束 |
|---|---|---|
| 行政区划 | 层级边界、驻地与名称表达 | 权威边界版本、行政代码、名称时点与层级 |
| 经济发展 | 总量、增速或结构专题 | 指标定义、单位、年份、现价/不变价及比较口径 |
| 科技创新 | 创新平台、企业、研发指标 | 设施分类、地点唯一性、指标统计单位 |
| 现代产业 | 园区、企业、产业分类分布 | 分类体系、点面对象区别、规模字段含义 |
| 对外开放 | 港口、通道、开放平台及相关指标 | 节点与线路来源、流量/规模与方向的真实含义 |
| 文旅融合 | 景区、文化资源、旅游线路 | 资源等级及日期、地点与线路证据 |
| 交通运输 | 路网分级、枢纽或运输指标 | 路段等级、节点、方向/通行含义和统计口径 |

这些是任务选择参考，不强制一个方向只有一种地图表达。指标地图按数据契约绑定，行政区划图不必产生分类断点；设施分布图不必有连续数值；线网图不能被强制套入面分级设色。

跨主题单图按任务集合组合；跨年度比较检查行政区划变更与统计口径，不能只按名称 Join。无法确认总量还是增速时返回语义消歧，而非模型任选一个指标。

#### 9.5.2 应急测绘制图

至少记录 `hazard_types`、`event_phase`、`data_nature` 和任务目的。`event_phase` 使用 `preparedness/response/recovery`；数据性质使用 `observed/inferred/predicted/simulated`。同图多个图层性质不同须逐层标记，不能以全图一个标签掩盖预测与观测差异。

| 灾种 | 首期输入与表达 | 必须阻止的误判 |
|---|---|---|
| 地质滑坡 | 已核验滑坡点、调查边界、影响区和应急设施 | 把点自动扩展为滑坡体或预测危险范围 |
| 洪涝灾害 | 已有淹没范围、水位/风险指标、受影响对象与避难点 | 将降雨量当淹没范围，将容量点当实际服务覆盖 |
| 森林火灾 | 已有火点、过火范围、监测时间与周边资源 | 将火点连线作为火场边界或直接推断未来蔓延 |

`hazard_result_map` 表达已有调查、监测或分析成果；`exposure_overlay` 使用注册空间操作计算相交数量/面积，必须明确边界点、重复要素、统计单位及数据时点。专业分析尚未实现时返回能力缺失，不能把结果生成责任转交给大模型。

调研图中的灾情辅助层同样执行数据性质、时效和专业符号检查；只出现“安置点”字样而没有灾情表达任务时，不自动加载无关的灾害模拟能力。

#### 9.5.3 领导调研用图

固定执行“行程提取 → 地点解析 → 路线来源处理 → 点线与序号生成 → 版面核验”，细化为：

1. 从原文提取调研日期、地点、明确的先后/时间窗口、停靠与途经关系；保留证据片段。
2. 用获准的地名/POI 数据匹配稳定实体 ID，核对行政区、别名、单位全名及坐标来源；不同门址或入口点不能仅按中心点猜测。
3. 记录每个地点的候选、选择依据、来源版本、CRS 与适合当前比例尺的定位精度；不能从文本置信度推导位置精度。
4. 依 `route_mode` 执行获准路径处理，保留行程顺序；算法只求相邻已排序地点间的路线，不默认重排整段行程。
5. 生成地点序号、名称、类别、线条和方向标记，核对停靠点与路线顺序、连接和可见性。
6. 对行程时间、联系人、敏感设施、途经和访问地点进行分发分级，不向未获准外部服务发送行程。

| `route_mode` | 执行规则 | 失败处理 |
|---|---|---|
| `provided_geometry` | 读取用户提供的线数据/轨迹，保留路线身份与方向，检查与站点对应 | 路线与行程不符时消歧，不自动重新规划 |
| `road_network` | 指定路网快照、交通方式、通行限制、代价和算法版本，逐段求路 | 地点未定、缺路网或不可达时报告，禁止连直线补齐 |
| `schematic` | 经 G1 明确允许后，生成表达访问关系的示意线 | 必须标注“行程示意，非实际道路路线”，不能承诺里程/到达时间 |

“地点已解析”和“路线已求出”分别检查。仅需调研地标注时可只选 `stop_annotation`，不强制生成路线；只有 `itinerary_map` 激活后才要求路线来源、几何和顺序核验。

路网计算结果也只是基于指定快照与约束的规划路线，不等于现场道路实时可通行，更不等于已批准的安保路线。需要封路、实时路况或专门保障信息时增加明确数据与权限，不能从普通地图推断。

### 9.6 任务能力分派与共享结果

TaskDispatcher 对批准的 `map_tasks` 查固定能力表，选择受信操作；工具调用统一通过 ToolGateway，数据准备结果通过 PreparedDataBundle 交接。地点查询和路网操作遵循第十章同样的输入摘要、版本、权限、预算和输出快照协议。首期不接受模型指定函数名或任意执行图。

场景策略只负责把任务具体化，输出仍是同一 MapPlan 的 `bindings/processing/views/spatial/portrayal/targets`，以及可选的 `itinerary` 或 `hazard_context` 分段。模板/场景策略/专业约束冲突时，按唯一所有权检查并报告；不能因为某场景“更紧急”而降低规则强度。

## 十、数据绑定与受控处理

### 10.1 绑定是语义匹配，不是列名猜测

```yaml
bindings:
  risk_regions:
    snapshot_ref: risk-snapshot-001
    layer: risk_regions
    geometry_column: geom
    key_field: region_code
    fields:
      region_id: {source_field: region_code}
      risk_rate:
        source_field: flood_rate_pct
        source_unit: percent
        target_unit: percent
        conversion: identity
    evidence_ref: metadata:risk-dictionary-v1
```

匹配至少检查概念、单位、类型、几何、主键、时间和空间统计口径；缺少字典时可通过知识服务检索获准来源，但无依据不能视为匹配。`risk` 这样的列名不能证明它表示风险率，范围看起来像百分数也不能替代数据字典。

允许系统在 G1 明确授权范围内采用唯一可证明绑定；多候选、语义缺失或风险率与容量混淆属于阻断问题。模型置信度不能替代证据。

### 10.2 数据预检

- 主键非空与唯一、几何类型、字段类型、缺失和异常值。
- Join 的键规范化、基数、重复处理、未匹配数量与空间分布。
- 分子分母时点、空间单元和单位一致；分母为零、缺失或负值分别处理。
- 观测时效、来源时间差与任务时间基准。
- 地理覆盖率、有效要素数、非空裁剪结果、敏感字段及发布权限。
- 数值范围、离群值、精度、统计分布及与元数据的一致性。

覆盖率等阈值来自契约和批准政策，而非通用固定数字。未匹配地区应保留为无数据或报错，不能通过内连接静默删去；预检应记录过滤前后计数和原因。

### 10.3 处理操作注册表

复用受信实现的有限操作，不允许模型提交任意代码：

```yaml
processing:
  - id: convert-risk-unit
    operation: convert-unit@1
    input_ref: risk-snapshot-001
    params:
      field: flood_probability
      from: ratio
      to: percent
    output_ref: risk-percent-001
```

常见操作包括单位换算、显式 Join、筛选、按定义聚合、裁剪、重投影、受限几何修复和概化；调研场景还包括受控地点检索、已有路线读取、获准示意线生成，以及能力声明内的路网计算。每个操作记录版本、输入摘要、类型化参数、输出摘要、记录数变化和误差报告。

比例转百分数通常乘以 100，但只在源单位已确认时执行。聚合风险率不能简单求和或无条件平均，应按指标定义使用分子分母重算或获准权重。空间裁剪改变展示范围不自动改变统计分母；若统计范围变化，必须重新计算并说明口径。

需要未知分析算法时返回 `ANALYSIS_CAPABILITY_MISSING`，不能临时让模型发明算法并继续生产。派生数据写入不可变版本，不修改源快照。

## 十一、空间参考、尺度与误差

### 11.1 CRS 分工

| CRS | 用途 | 锁中保存 |
|---|---|---|
| 源 CRS | 解释原始坐标 | CRS 标识、轴顺序、单位和来源 |
| 分析/量测 CRS 或测地模型 | 面积、距离、缓冲、聚合 | 操作方法、参数及误差预算 |
| 显示 CRS | 地图视觉投影 | 每个目标/地图框的 CRS、旋转和范围 |

CRS 缺失、轴顺序未知或坐标单位矛盾时不能仅根据包围盒猜测后生产。需要用户或可信元数据确认；诊断建议不等于绑定事实。

坐标转换记录实际转换操作、精度、PROJ/GDAL 版本、所需格网和坐标历元（适用时）。转换格网缺失时不得未经许可采用低精度替代；输出限制须能追溯。

### 11.2 范围、比例尺与图框

按数据或批准边界确定范围，记录缓冲、裁剪、留白、图框尺寸和真实尺度。实际地理范围、目标图框尺寸、固定比例尺三者可能互相冲突；应明确哪项为绑定条件，再推导其他参数。不能为填满版面而裁掉必需区域。

比例尺使用实际地图框与量测方法计算；地理坐标显示或变形显著时说明局部比例尺的适用性。指北针应区分真北、网格北和地图旋转，是否必需由用途确定。跨反经线与极区仅在能力声明内支持，否则给出明确的拒绝或改投影建议。

### 11.3 概化与空间有效性

概化、聚合和拓扑约束遵循空间契约；符号尺寸与标注密度遵循表达契约，共用明确尺度键。任何位移或面积阈值带物理单位及换算依据。

无效几何修复须报告原始问题、修复方法、要素及面积变化。行政区裂隙、重叠、岛屿丢失、窄通道断裂不能因渲染成功而视为合格。数据超出适用尺度时阻断或按已批准的细节层级切换，不能仅缩放符号掩盖不适用数据。

## 十二、表达、标注与布局实现

### 12.1 表达选择与分类

Map Encoding 根据量纲、空间支持单元和沟通目标选择。分级设色通常用于可比较的率、密度或标准化指标；绝对量是否适合该表达由明确语义检查判断，不能把行政单元面积造成的视觉偏差当作事实。

分类结果由程序计算并冻结：

- 字段与单位、过滤条件、标准化和异常值策略。
- 算法及版本、请求类别数与实际类别数。
- 边界值、区间开闭、并列值、不足唯一值和舍入策略。
- 对应颜色、符号和无数据编码。

图例显示文字可以按指定精度格式化，但必须与真实分界对应；格式化后标签重合须提高精度或修订分类，不可改变渲染断点。空数据、单一值或全部缺失必须触发明确策略，不能照常绘制五级图例。

### 12.2 符号与不确定性

容量比例符号按面积映射，半径由面积推导；记录最小可见尺寸、上限及采用裁切或变换后的说明。零、负值和空值分别定义，不把空值画成零。

品牌色只影响身份分段或语义允许的视觉选择，不覆盖适用的预警色和标准符号。风险估计、预测、观测及模拟数据采用清楚的标题、图例和来源说明。缺少不确定性数据时不能凭空生成置信区间。

### 12.3 标签、图例与版面

- 标签记录文本字段、单位格式、语言、字形覆盖、优先级、避让与禁止遮挡对象。
- 布局检查地图框、标题、图例、附图、比例尺、来源及版权区域的容量。
- 图例从实际图层和编码编译，不由模型独立抄写另一份数值。
- 附图需标明与主图的范围关系和独立尺度。
- 必需信息无法容纳时允许提出扩大版面或分图方案，但改变已确认数量/目标需回到 G1。
- 自动检测碰撞、截断、低对比和最小字号，必要人工复核空间叙事与专业风险。

模型可以提出布局候选，最终坐标和规则必须写入候选快照。正式渲染器不得在冻结后随机重新选择版面。若使用引擎自动标注，锁定其规则、数据顺序、版本和随机种子；对被确认要求精确保留的位置，锁定最终位置或可复现的布局结果。

## 十三、候选预览、规则检查与修复

### 13.1 候选快照

计划无未决硬条件后由编译器生成 `ResolvedSnapshot`。候选含全部执行参数、实际数据/资产摘要、目标清单和环境指纹，不含尚待模型决定的自由文本指令。

预览的输入是该快照，不是可随时改变的当前 MapPlan。预览报告以 `candidate_id + execution_digest + environment_digest` 绑定。输出应显式带“预览”标识，且不能被成果发现接口误认为正式交付。

### 13.2 分阶段检查

| 阶段 | 主要检查 | 失败返回 |
|---|---|---|
| 数据接入 | 意图/任务合法性、知识适用性、阶段必填项、工具/来源权限、完整性与时效 | intake |
| 计划编译 | 场景任务兼容、地点/路线就绪、Schema、所有权、绑定、空间/编码语义与目标能力 | plan 或 brief |
| 候选预览 | 地理/数值结果、布局、图例、标签、可读性与目标预算 | plan |
| 冻结 | 候选与证据摘要、审批有效性、待决项为空 | preview 或 G2 |
| 正式成品 | 导出结构、完整性、锁一致性、视觉及法律标注 | render 或新计划 |
| 交付 | 最终成果摘要、目的地授权、许可与发布政策 | G3 或 deliver |

任务检查至少包括 `intent.task-consistency`、`administrative.version-match`、`hazard.source-nature`、`hazard.timestamp`、`place.unique-resolution`、`route.geometry-kind`、`route.order-consistency`，以及 `knowledge.applicability`、`tool.binding-integrity`、`data.bundle-acceptance`。这些是拟注册检查 ID，须由版本化平台实现并根据任务适用；不是在场景配置里放入任意检查表达式。

沿用六种规则语义及 `blocker/error/warning/info` 结果，不建立新的优先级层级。检查器来自受信注册表；模板和模型不能把必需错误降为警告。无法完成的必需检查应失败，`not_applicable` 只用于确实不适用。

### 13.3 预览验证要求

低分辨率预览用于快速讨论，不足以证明印刷级标签和细线合格。G2 前的最终候选检查应使用目标尺寸与实际标签布局，必要时对全幅或关键区域按正式 DPI 检查；检查资源不足应报告，不能伪称与正式结果等价。

必须覆盖所有必需视图和目标，不仅首张图。数据分布可能导致的边界情形用项目数据检查；模板 Fixture 回归可以补充，但不能替代实际图面检查。

### 13.4 有界修复

局部参数在 G1 委托范围内可自动修订，记录原因并生成新候选；每次改变导致旧候选证据失效。自动修复次数和总预算由平台限制，预算耗尽返回诊断和待决项，不无限重试。

修复分层：

- 数据缺陷返回接入或绑定层。
- 投影、分类和全图风格返回计划层。
- 已确认目标、数据源或业务结论变化返回 G1。
- 单次渲染进程崩溃且输入不变，可重试同一候选或锁。
- 专业人工复核未通过必须保留意见，不能由模型宣布已解决。

## 十四、实例锁设计与冻结算法

### 14.1 锁结构

```yaml
schema_version: 1
lock_id: lock-001
project_id: flood-risk-daily
run_id: run-001
candidate_ref: candidate-003
execution_digest: sha256:<resolved-execution-digest>
execution:
  intent_ref: intent:<resolved-revision-digest>
  profile_refs: []
  business_scene: emergency_mapping
  map_tasks: [hazard_result_map]
  template_refs: []
  dependency_refs: []
  policy_refs: []
  dataset_refs: []
  prepared_data_refs: []
  knowledge_evidence_refs: []
  tool_binding_refs: []
  transformation_refs: []
  ownership: {}
  shared_semantics: {}
  views: []
  targets: {}
  resolved_assets: []
  environment: {}
evidence:
  preflight_ref: validation:<digest>
  preview_ref: validation:<digest>
approvals:
  brief_ref: approval:<id>
  freeze_ref: approval:<id>
```

该片段只说明骨架。正式 Schema 要求所有适用分段完整；例中的空集合不能直接用于生产。

`shared_semantics` 保存字段含义、实际编码、标准、共同口径和数据关系；`targets` 保存各目标显示 CRS、纸张/视口、DPI、字体、标注和引擎参数。每个视图绑定对应范围、图层与目标。

锁另保存有效 MapIntent 修订、场景目录/策略版本、全部任务和适用检查引用，以及已采用知识的版本/条款摘要、数据包和工具能力绑定引用。来源获取/预处理的工具回执在锁前固定；正式渲染中新产生的调用回执写入运行证据，不回写锁。未采用的检索候选、完整对话和秘密不进入执行输入。

应急任务逐层保留事件阶段、数据性质及观测时点；调研任务保留已解析实体、坐标来源与精度、访问顺序、路线形态、路网/算法/约束和示意标识。这些值随候选冻结，渲染器不能重新消歧地点或改变路线。

### 14.2 摘要与审批避免循环

区分两个摘要：

1. `execution_digest`：对规范化的执行参数及其固定引用计算，不包含审批、验证结果、时间戳和摘要字段自身。
2. 锁文件摘要：对最终不可变锁文件计算，保存在步骤回执与交付清单中，不写入文件自身。

候选预览和 G2 审批都绑定同一 `execution_digest` 及独立的证据摘要。冻结后加入审批引用，不改变执行参数；正式渲染记录锁文件摘要和执行摘要，不能把两者混为一个哈希。

规范化协议须版本化：固定 UTF-8、键排序、数值/空值表示、UTC 时间和列表语义；不允许 NaN/Infinity 或含义不明的浮点表示。真实几何、栅格和资产通过稳定产物摘要引用，不把大体积二进制塞进锁。

### 14.3 冻结步骤

1. 验证 G1 与有效意图修订兼容，所有任务的冻结前条件已满足，候选无待决硬条件。
2. 重新校验候选、数据包、采用知识、工具绑定、依赖、环境与所有验证证据的摘要及适用性，确保没有未解决的数据子任务。
3. 验证 G2 授权范围、主体和候选/证据摘要一致。
4. 用候选的同一执行参数生成锁，不在冻结时重新运行模型或重新计算断点。
5. 在新锁目录内完整写入并持久化，校验后原子提交运行引用。
6. 将渲染输入指向精确 lock ID，不指向“latest”计划。

冻结不保证无限期可重放：需要同时保留引用数据、字体、转换格网、引擎和依赖。数据访问依法到期或撤回时，记录无法重放的原因并遵守保留政策，不能为复现而违法留存。

### 14.4 锁后变化

模板、数据、范围、分类、标签、资源或环境实质变化必须产生新候选和新锁。相同输入下的暂时性进程错误可在新 attempt 目录重试旧锁；引擎升级不属于无影响重试。

当前安全或法律撤销可以阻止旧锁继续执行，即使它曾经有效。旧锁不能被“修补”，应保留不可执行原因和新版本关系。

## 十五、正式渲染与多目标处理

### 15.1 统一适配器协议

复用创建模板 TRD 的接口：

```text
capabilities(environment) -> AdapterCapabilities
compile(resolved_snapshot, target_id) -> RenderPackage
render(render_package, resource_bindings, limits) -> RenderArtifacts + Diagnostics
```

正式调用的 `resolved_snapshot` 来自实例锁的执行分段；适配器只做实现映射，不再访问可变 MapPlan 作决定。编译和执行开始前验证环境及资源指纹，文件变动须失败。

执行器从只读快照或受控版本来源取数据；限制 CPU、内存、临时盘、时限、输出体积、并发和网络。多租户或不可信工程使用操作系统沙箱/容器，独立进程本身不等于安全沙箱。

### 15.2 目标分工与成熟度

| 目标 | 参数与检查重点 | 实施范围 |
|---|---|---|
| 印刷/报告嵌入图 | 物理尺寸、DPI、字体、图例、裁剪、边界及署名 | 首期 QGIS PDF/PNG |
| 图册 | 图幅索引、相邻关系、奇偶页装订边、统一口径与系列顺序 | 后续；首期不以多个 PDF 冒充完整图册能力 |
| Web | 响应布局、缩放、瓦片、图层状态、交互、资源预算和无障碍 | 第二适配器通过验证后 |
| 移动端 | 安全区、触控、横竖屏、弱网、离线、定位权限及个人隐私 | 后续专项验证 |
| 可编辑工程 | 引用数据、字体、样式可用性和路径可移植性 | 可选能力，单独验证与授权 |

Web 导出的应用/样式/瓦片包不自动部署到互联网。不同目标可采用不同显示 CRS 与标签密度，但必须保持锁定的共享语义；语义差异须在合同允许范围内明确披露。

### 15.3 多目标一致性与失败

每个目标独立记录 `target_id/required/status/attempt_id`。所有必需目标通过成品检查才可将运行标记成功。G1 明确为可选的目标可以失败，但交付清单必须列明缺失与原因，不能宣称全部完成。

如果新政策要求删除某个必需目标，须修订简报和锁；不能把失败目标临时改成可选。不同目标可并行执行，但共享只读锁、数据和资源；并发不能改变图幅排序、分类或源数据。

### 15.4 成品检查

检查正式导出物，而不是只相信适配器退出码：

- 文件可打开、格式正确、页数/视图数与清单一致、必需图层存在。
- 地图范围、投影标识、图例、单位、时间和来源与锁一致。
- 字体无缺字或未报告替换，文字/线条在目标尺寸下可读。
- 无数据区、符号面积、图层遮挡和标签与预览语义一致。
- 实际 DPI、尺寸、颜色能力、嵌入资源和外链满足交付契约。
- 元数据、附件和可编辑工程中不泄露未授权字段或路径。

对 PDF 等含时间戳的格式采用内容与视觉容差检查，不以字节不同直接判定语义失败。若正式结果与已批准预览实质不一致，不能只修报告；定位环境漂移或计划缺陷，修复并重新验证。

## 十六、成果包、交付与公开发布边界

### 16.1 成果清单

交付清单是成果记录，不是模板 Manifest。至少包含：

```json
{
  "schema_version": 1,
  "delivery_id": "delivery-001",
  "project_id": "flood-risk-daily",
  "run_id": "run-001",
  "lock_id": "lock-001",
  "lock_digest": "sha256:<digest>",
  "execution_digest": "sha256:<digest>",
  "artifacts": [
    {
      "target_id": "print-a3",
      "view_id": "risk-overview",
      "format": "pdf",
      "path": "artifacts/risk-overview.pdf",
      "digest": "sha256:<digest>"
    }
  ],
  "validation_refs": ["validation:<digest>"],
  "missing_optional_targets": [],
  "data_redistributed": false,
  "limitations": [],
  "destination_ref": "project-output"
}
```

外部用户交付包可包含地图、说明、来源摘要、许可与获准的简化报告。完整锁、连接信息和内部审计证据通常只在受控工作区保留，不能无条件随地图对外分发。

地图图像本身也可能泄露敏感位置；“未附带原始数据”不意味着可公开发布。可编辑工程可能携带整个属性表和隐藏图层，需要专门脱敏、数据分发授权和可移植性检查。

### 16.2 交付事务

`deliver` 与创建模板的 `publish` 是不同操作：

1. 校验 G3 权限、目的地、全部必需成果、有效成品报告和许可。
2. 把成果及获准说明复制到唯一交付暂存区或不可变对象位置。
3. 逐文件验摘要并完成持久化，生成不含自身摘要的交付文件清单。
4. 计算清单摘要，原子提交交付记录；只有已提交记录可被发现。
5. 返回回执；通知和下载链接生成按幂等事件重试，不重复交付文件。

本地模式使用允许根下的新 delivery 目录与原子可见记录；共享模式先持久化对象，再事务提交注册记录。失败遗留对象不可见；不能把多个文件独立复制成功误认为整包提交成功。

幂等键绑定项目、锁、目标集合和目的地。相同键同内容返回已有回执，同键不同内容拒绝。修改目的地是新的交付动作，需重新鉴权；旧成果不可覆盖。

### 16.3 对外发布与撤回

默认 `delivery.mode=local`，表示在项目允许位置生成可领取成果。向云存储、外部报告系统或公开地图服务推送需要明确目标和权限；公网服务部署属于外部受控工作流，本路由最多提供部署包和验证信息。

发现错误时保留旧锁与成果证据，在交付记录标记撤回/替代并生成新版本。已经下载的文件无法保证远程删除，应按制度通知受影响对象，不承诺“撤回即消除所有副本”。

## 十七、状态、恢复、修订与缓存

### 17.1 简化状态

沿用共享作业状态字段，但本路由拥有自己的步骤集合：

```yaml
route: generate-map
run_id: run-001
intent_revision: 2
business_scene: emergency_mapping
status: running
step: preview
attempt: 1
plan_revision: 3
candidate_id: candidate-003
lock_id: null
input_fingerprint: sha256:<digest>
last_receipt: steps/plan.json
```

`status` 为 `pending/running/waiting_approval/failed/succeeded/cancelled`；`step` 为 `intake/brief/plan/preview/freeze/render/check/deliver`。

不存在独立的“模板已注册”或“模板已发布”生成状态。成功意味着契约要求的地图已验证并完成授权交付，不是仅生成了 MapSpecLock。

### 17.2 完整步骤与恢复点

| 步骤 | 入口条件 | 输出 | 允许恢复 |
|---|---|---|---|
| intake | 有用户目标/行程文字及读取本次输入的权限 | 意图初判、输入清单、已有数据快照和阶段缺项 | 输入及目录版本不变时复用 |
| brief | 用途明确、G1 必需信息齐全；可包含待获准获取的数据 | MapIntent 引用、MapBrief、G1 回执 | 简报、意图与模板候选摘要仍匹配 |
| plan | G1 有效，选择固定场景策略 | 验证后的数据包、采用知识与工具证据、MapPlan 及候选参数 | 输入、授权、知识/工具及意图/策略指纹匹配 |
| preview | 候选静态检查通过 | 预览、质量证据 | 候选与环境不变 |
| freeze | 预览通过且 G2 有效 | 不可变锁 | 查询既有提交，避免重复 |
| render | 锁与依赖仍可执行 | 各目标正式成果 | 重试失败 attempt |
| check | 正式成果存在 | 成品报告 | 成果摘要与环境匹配 |
| deliver | 成品通过且 G3 授权 | 成果包和交付回执 | 按幂等键查提交结果 |

每步回执记录输入/输出摘要、工具版本、起止时间、错误和重试。恢复不依赖上一次聊天上下文；先检查磁盘或数据库中的权威记录。状态文件被手动改为成功不能绕过证据检查。

### 17.3 修改影响

| 改动 | 最早重做 | 审批影响 |
|---|---|---|
| 主场景、任务、路线形态、访问顺序、受众、指标定义、数据源、地域或必需目标 | brief，必要时 intake | G1 重新确认 |
| 同授权来源的新日期快照 | intake | 只有预批准的时间窗口政策覆盖时可自动通过 G1 |
| 契约允许的分类、色板或标签调整 | plan | 新候选、新 G2 |
| 已采用知识、数据包、工具绑定/方法、字体、底图、引擎或 PROJ 环境改变 | plan/preview，超出授权时 brief | 重新验证；影响执行结果形成新锁 |
| 同环境暂时性渲染失败 | render | 不改锁；保留有效授权 |
| 输出目的地或分发对象改变 | deliver | G3 重新鉴权或审批 |

锁后的修订建立新运行，引用上一锁作为 lineage，不在原运行偷偷替换输入。并发请求依据计划修订号或作业版本比较交换，防止最后写入覆盖。

### 17.4 缓存与取消

缓存键包括租户/权限边界、输入及依赖摘要、操作参数、相关工具/政策版本和目标。授权变更时重新鉴权，不因缓存命中跨租户返回数据或绕过源访问撤销。

场景目录、策略版本或有效任务改变时，意图与计划缓存失效并复查审批适用性；与当前任务无关的目录变更不自动改写旧锁。知识和数据子任务缓存还须匹配采用证据、工具绑定、批准要求及访问权限，不能只按问题文本相似度复用。首期采用整体计划重编译与按确定性处理操作缓存，不建设通用细粒度失效调度器。最终渲染缓存还需锁及环境指纹一致，数据时效要求在当前运行重新判断。

取消需停止子进程树、数据子智能体循环与后续步骤，并释放锁；远程工具取消或副作用不确定时按调用协议核对。提交过程中收到取消，应先确定交付事务是否已提交；不能把已经交付的外部效果说成从未发生。保留失败或取消产物供诊断，按保留期清理。

```text
carto_map.py cancel <project> --run <run-id>
```

`run` 顺序编排可执行步骤，使用请求指定的有效政策或可信回执。缺审批时持久化 `waiting_approval` 并立即返回，不让 CLI 占用终端无限等待。`confirm` 验证授权后，`resume` 继续；无人值守场景通过批准的政策评估器处理 G1/G2/G3，不接受不受信的“自签通过”。

`interpret` 可初始化运行并解析本次明确提供的文本/附件，只输出意图、证据和阶段缺项，不读取候选模板正文或擅自查询外部地点。`intake` 内置同一解析器并补充来源检查，不要求用户重复调用；意图解析是 intake/brief 的内部工作，不增加新作业状态。

`--scene` 与请求中的 `scene_hint` 都只能使用三个注册 ID，互相矛盾时返回参数冲突；提示与请求真实目的不兼容时返回意图冲突，不能强制分派后绕过检查。状态输出增加意图修订、主场景、任务和待决要求。缺信息但尚无授权动作可执行时使用 `status=pending` 与明确 `required_action`，只有等待批准才使用 `waiting_approval`，二者均可返回码 3。

`intake` 可初始化新项目与运行，目录必须位于配置允许根内；已有项目必须显式新建运行或恢复，不能覆盖。细粒度命令与 `run` 调用同一应用层逻辑，没有第二套跳过门禁的实现。

`prepare-data` 只在有效 G1 下执行；`plan` 内置调用相同数据准备服务，不要求重复运行。`auto` 按受信政策选择实现，不代表可以自行增加来源或智能体权限。MCP 绑定和知识来源通过部署治理维护，不提供让模型绕过网关直接调用任意服务的 CLI。

`revise` 接收类型化变更，如 `set-classification`、`set-label-policy`、`replace-source`、`resolve-place`、`set-route-mode`，校验权限与影响范围后应用，不直接接受任意代码或越界 JSON 路径修改安全字段。

### 18.2 输出与返回码

所有命令支持 `--json`，stdout 输出结构化结果，stderr 输出诊断；进度不能污染 JSON。`--help` 无写入。`deliver --dry-run` 只验证并预告，不创建正式交付或代替审批。

建议返回码：

- `0`：本次命令成功；完整运行是否完成仍查看 `status`。
- `2`：请求或参数不合法。
- `3`：等待授权或必需决策。
- `4`：契约、数据或成品验证失败。
- `5`：暂时性基础设施错误。
- `6`：权限、安全或合规阻断。
- `7`：已取消。

```json
{
  "route": "generate-map",
  "run_id": "run-001",
  "status": "waiting_approval",
  "step": "freeze",
  "candidate_id": "candidate-003",
  "business_scene": "emergency_mapping",
  "intent_status": "resolved",
  "readiness_status": "ready",
  "map_tasks": ["hazard_result_map"],
  "required_action": "approve-freeze",
  "execution_digest": "sha256:<digest>",
  "evidence_ref": "reports/val-003",
  "retry_from": "freeze"
}
```

### 18.3 服务化映射

应用接口至少提供 `interpret/submit/status/approve/prepare_data/revise/cancel/resume/deliver`，共享同一工作流。多成果请求可携带类型化 `tasks` 集合，经 G1 确认拆分后分配子运行；批次汇总引用每个子运行的状态和交付回执，不把多个结果压成同一 MapPlan。异步提交返回 run ID，审批绑定精确候选或交付对象，所有写操作携带幂等键和项目修订号。

共享部署通过受信身份传递租户、项目权限、配额和 trace ID。数据库作业队列应有租约、心跳、超时接管和过期写者 fencing，避免同一运行被两个 worker 同时提交；首期本地可用单写者锁，不必引入分布式队列。

## 十九、错误模型与企业安全

### 19.1 错误与修复

| 错误码 | 含义 | 修复层 |
|---|---|---|
| `REQUEST_AMBIGUOUS` | 业务目标或路由边界不明确 | brief |
| `INTENT_CONFLICT` | 场景提示、证据与任务目的不一致 | intake/brief |
| `INTENT_UNSUPPORTED` | 请求不在注册业务/任务范围内 | brief |
| `KNOWLEDGE_UNAVAILABLE` | 所需权威依据缺失或无有效可用版本 | 知识服务 / 业务所有者 |
| `KNOWLEDGE_CONFLICT` | 采用依据在口径、版本或适用性上冲突 | plan / 专业审核 |
| `TOOL_BINDING_DRIFT` | MCP/API/本地能力绑定或 Schema 与固定版本不符 | 工具平台 / 新计划 |
| `TOOL_AUTHORIZATION_DENIED` | 调用超出主体、G1、任务或平台权限 | 对应审批所有者 |
| `DATA_PREPARATION_BUDGET_EXCEEDED` | 固定流程或子智能体超出准备预算 | 数据准备服务 / 上游 |
| `DATA_BUNDLE_INVALID` | 子任务产物不满足要求或证据无效 | 数据准备服务 |
| `INPUT_REQUIRED` | 意图已识别但缺少当前阶段必要信息 | 对应信息所有者 |
| `PLACE_AMBIGUOUS` | 地点无法唯一识别或坐标证据不足 | plan / 地点消歧 |
| `ROUTE_SOURCE_MISSING` | 缺少所要求的路线或获准路网 | plan |
| `ROUTE_UNREACHABLE` | 指定路网与约束下站点不可达 | plan / 业务决策 |
| `DATA_ACCESS_DENIED` | 没有读取来源权限 | intake / 权限所有者 |
| `DATA_SNAPSHOT_UNSTABLE` | 无法固定一致版本 | intake |
| `DATA_SEMANTICS_UNKNOWN` | 字段含义或单位无法证明 | plan / 数据所有者 |
| `DATA_STALE` | 超出批准时效 | intake |
| `BINDING_AMBIGUOUS` | 存在多个不能消歧的绑定 | plan |
| `CRS_UNRESOLVED` | CRS、轴或精度无法确认 | plan / 数据所有者 |
| `ANALYSIS_CAPABILITY_MISSING` | 缺少已批准处理算法 | plan |
| `TEMPLATE_INCOMPATIBLE` | 模板与数据/目标冲突 | brief / 独立模板任务 |
| `CONSTRAINT_CONFLICT` | 适用约束无可行组合 | 对应所有者 |
| `APPROVAL_INVALID` | 批准人与对象/权限不匹配 | 对应 G1/G2/G3 |
| `VALIDATION_STALE` | 候选、成果或环境摘要变化 | preview/check |
| `LOCK_INPUT_DRIFT` | 执行时固定输入变化 | 新计划或恢复正确资源 |
| `RENDER_TIMEOUT` | 工作进程超时 | render |
| `REQUIRED_TARGET_FAILED` | 必需目标不完整 | render/check |
| `DELIVERY_FORBIDDEN` | 目的地或分发内容未授权 | deliver |
| `DELIVERY_COMMIT_UNKNOWN` | 超时导致提交结果未知 | 按幂等键查询 |

错误响应包含 `code/message/run_id/step/artifact/evidence_ref/repair_owner/retry_from/retryable`。规则失败另含 `check_id/strength/result_severity`。诊断要解释影响，例如“3 个地区无匹配风险率”，不能仅输出一个工具退出码。

### 19.2 数据与执行安全

- 验证允许根、路径规范化、junction/符号链接、归档越界和输出目标；不允许模板控制任意路径。
- 拒绝脚本化 SVG/HTML、XML 外部实体、恶意压缩包、数据库/表达式注入。
- 数据库操作使用参数化查询和受限连接身份，不运行模型自由拼接的 SQL。
- MCP 服务描述、知识检索片段和子智能体回复均是不自动可信的输入；不能改变工具白名单、审批主体、文件权限或任务范围。
- 知识库访问控制在检索前与结果输出时执行；引用、缓存和日志不得泄漏其他租户的文档标题、内容或实体关系。
- 数据子智能体只获得任务最小上下文和短期受限执行身份，不继承主智能体全部凭据，也不得递归委派。
- 来源文本及元数据是待分析数据，不是改变路由、访问密钥或关闭门禁的指令。
- 地名/POI 查询请求最小化，不把整份领导行程、姓名、时间与敏感站点发给外部服务；缓存、检索日志和路线快照按同等敏感级别保护。
- 日志、锁和成果不包含密码、签名 URL、数据库连接秘密或未脱敏内部路径。
- 外部模型收到的数据须符合组织策略，优先使用聚合统计、最小字段和脱敏样本。
- 底图、地理编码、瓦片与字体服务遵守访问成本、缓存及分发许可。
- 输出细粒度位置、轨迹、敏感设施或人员分布时检查地理隐私；空间聚合不自动保证匿名性。

### 19.3 专业与发布合规

根据地图使用地区、数据级别和发布渠道加载适用的行政界线、敏感地理信息、地图审查、测绘资质或保密要求。模板通过检查不替代当前成果的法定审核。

系统不能把“城市洪涝研判图”自动表述为官方预警，也不能从容量点位图推断避难场所实际可达或覆盖人数。需要网络、时间或服务能力分析时，应明确增加数据与注册算法，超出授权则停止在表达已有事实。

## 二十、可观测性、性能与运行治理

### 20.1 审计链

使用 project、run、candidate、lock、validation 和 delivery 六类稳定 ID 连接证据，记录：

- 任务、意图证据、场景目录/策略版本、场景与任务判定、缺项及消歧过程。
- 简报及委托范围的各次修订。
- 来源权限、快照及实际处理输入输出摘要。
- 模型提案、程序采用的决定及依据。
- 采用/拒绝的知识证据及理由、来源适用性、工具能力绑定和调用回执。
- 数据准备模式、委派需求摘要、子任务工具/预算使用、验证与采用结果；不以保存隐式推理过程作为审计要求。
- 模板和标准版本、所有权结果、被拒绝的覆盖。
- 审批、预览、正式检查、交付及撤回。
- 引擎环境、超时、重试、缓存命中和资源峰值。

模型名称/版本及提示配置可记录用于解释提案来源，但最终复现依赖固定锁和确定性参数，不要求重新生成相同的模型文本。敏感输入不能直接写进普通审计日志。

### 20.2 预算与可用性

G1 或平台配置明确地图数量、要素规模、输出体积、处理/渲染时限、内存与磁盘、并发和允许外部费用。超过预算应返回容量诊断或获得新的授权，不静默抽样数据、减少图幅或降低必需输出质量。

指标至少包括数据读取/处理/预览/渲染耗时、失败率、等待审批时长、队列时长、资源峰值、成品缺口及交付错误；新增知识引用正确性/冲突率、MCP 调用失败与超时、数据准备预算和首轮验收通过率。增加子智能体的收益以复杂任务成功率、错误率、成本和延迟共同评估，不以工具调用次数多作为智能程度指标。等待人工审批不计入纯计算 SLA，但计入端到端业务时长。

### 20.3 生产门槛

上线前配置身份权限、作业隔离、数据与成果保留期、告警、备份、恢复目标、负责人和事故流程。至少完成一次包含数据、锁、环境、证据与交付记录的恢复演练。

模板注册表、项目数据与成果存储有不同访问边界，不因共用 repository 模块而使用相同凭据。单用户本地可先用文件和操作系统权限；共享服务必须完成租户隔离、数据库事务、可信审计及工作进程配额。

已完成运行可回放，但仍要检查当前授权和安全撤销。备份不是数据永久保留授权；删除或到期遵守政策并保留必要的非敏感审计摘要。

## 二十一、测试与验收标准

### 21.1 测试矩阵

| 层级 | 必测内容 |
|---|---|
| 路由与生命周期 | 生成/模板/原生编辑分流；无模板也不能绕过门禁 |
| 场景意图 | 三场景及跨主题请求、用途与关键词冲突、缺字段拒识、显式提示冲突、附件注入 |
| 场景任务 | 主用途与辅助任务组合、意图已识别但未就绪、目录变更与审批失效、复合请求拆分 |
| 政务方向 | 七个已明确方向各有代表案例；三项待确认不得误报覆盖；统计口径与行政版本 |
| 应急灾种 | 滑坡/洪涝/森林火灾，事件阶段与图层性质，观测表达和预测请求边界 |
| 调研行程 | 纯文字输入、同名地点、顺序固定、入口点差异、三种路线形态、不可达和信息泄露 |
| Schema 与类型 | 合法与非法请求、计划、候选、锁、交付清单 |
| 数据接入 | 文件变化、活跃数据库、分页中断、快照过期、访问撤销 |
| MCP/工具网关 | 本地/API/MCP 输出语义一致，绑定变更、凭据隔离、伪只读、超时重试、取消及晚到结果 |
| 知识治理 | 指标与标准精确查询、完整限定条件、来源冲突/失效、无证据拒绝、检索前权限过滤 |
| 知识边界 | G1 前可查获准术语但不可召回未确认模板正文，检索排名不能漏执行强制规则 |
| 数据子任务 | 两种模式同一输入输出合同、子智能体越权/自报通过被拒绝、预算终止、恢复和跨租户隔离 |
| 绑定与统计 | 同名异义字段、单位转换、分母为零、重复主键、Join 缺口 |
| 空间 | CRS 缺失、轴顺序、转换格网缺失、无效几何、范围与尺度冲突 |
| 表达 | 并列值、空集合、单一值、边界开闭、无数据、比例符号面积 |
| 模板组合 | 六契约消费、同类整段替换、标准冲突、正式目标不可随意扩展 |
| 惰性加载 | G1 前正文不读；确认后相关约束完整；未用适配器不启动 |
| 快照与审批 | 审批绑定候选，冻结不重算，锁后篡改被拒绝 |
| 渲染与成品 | 目标尺寸/字体/图例/遮挡/导出结构，预览与正式语义一致 |
| 交付 | 必需目标失败不交付、敏感内容泄露、幂等重试、提交超时查询 |
| 恢复与隔离 | 取消、worker 崩溃、磁盘满、并发旧写者、跨租户缓存泄露 |

评测集包含各场景的正例、相似负例、跨主题例、关键缺项和超范围任务，按项目/措辞来源划分训练与评测，防止仅靠重复模板得高分。分别度量主场景判定、任务集合准确性、关键字段完整性、应拒识而误执行率、澄清负担，以及错误地点/假道路等高风险错误。阈值由真实验收集和风险政策确定，不使用模型自报置信度作为合格标准。

测试固定时间与随机种子，隔离合成数据和业务数据。算法正确性使用可计算结果，而非只看生成图片；视觉回归需要容差与专业评审，不能以像素相同替代空间语义。

### 21.2 完成定义

一次地图生成只有同时满足以下条件才算完成：

1. MapIntent 的主场景、任务与证据一致，阶段缺项已解决，简报与模板选择有有效授权。
2. 真实数据或明确模拟数据的来源、语义、版本和访问范围可证明。
3. 计划无未决硬条件，全部主/辅助任务的字段、空间、表达、地点/路线和交付约束成立；采用知识有适用证据，数据包通过独立验收，工具调用可追溯。
4. 所有必需视图完成预览验证，G2 有效，实例锁不可变。
5. 正式渲染使用同一执行摘要和固定环境，成品检查通过。
6. 所有必需目标和格式齐全，缺失的可选目标已披露。
7. 无 `blocker/error`，警告有处置，必需人工/法定审查完成。
8. 成果包、说明、许可和限制符合目的地要求，G3 通过。
9. 交付记录已原子提交，回执可查询，失败重试不产生覆盖或重复副作用。
10. 审计链、恢复资料和保留策略满足生产要求。

仅冻结锁、仅输出一张 PNG、只通过模板 Fixture、或准备好待审批成果，都不是完整完成。

| GM-P6 行业与规模 | 专业标准扩展、数据库/瓦片连接器、多租户规模优化 | 按行业和部署目标验收 |

实施阶段统一使用 `GM-P0`～`GM-P6`；G1/G2/G3 只表示运行审批门禁，两者不得混用。

首期不必同时支持全部数据源和专业分析，但不能再只以洪涝分级设色示例代表三类业务。最小能力包含 GeoPackage/GeoJSON 与行程文字接入、可信地点解析、行政区划和分类点位/线网表达、统计专题、已核验灾害成果、已有路线/获准示意线及 QGIS PDF/PNG。路网计算独立声明支持范围，不可用时明确阻断相应请求。快照、权限、锁一致性、专业语义及恢复治理均在生产前完成。首期不强制全面多智能体化：先交付数据准备接口和固定流程，再用真实复杂案例验证可选子智能体的收益；未启用委派不影响简单任务的生产闭环。

### 23.7 失败与恢复验证

- 将风险字段错误绑定到容量：绑定/单位检查失败，不进入冻结。

- PDF 成功但必需 PNG 失败：运行不能成功交付，修复 PNG 或重新确认输出合同。
- 交付提交后客户端超时：用幂等键查询已有 delivery，返回同一回执，不复制第二份成果。

| 输入 | 应判定的任务或问题 | 预期行为 |

复合任务验收要求每个子运行最多一个 MapScenario，任一必需子成果失败时批次不能成功；不得复用另一子任务的审批来冻结不同的候选。

### 23.11 MCP、知识与数据子智能体的联合运行示例

以政务经济专题为例：用户要求比较区县 GDP 增速，已经批准两个企业数据来源，但两个来源的字段命名不同，其中一份元数据只写“增长率”。

1. 主制图智能体经 DomainKnowledgeService 查询获准指标字典，得到 GDP 增速的定义、单位、年份口径和适用范围；不把任何实际地区数值从案例文档中抄作业务数据。
2. G1 确认指标、两个来源、允许查询与处理能力和预算。主流程生成 DataPreparationTask；任务有多来源语义核对需求，且部署已启用对应政策，选择 `agent_assisted`。
3. 数据子智能体通过知识服务核对口径，并通过 ToolGateway 调用注册的 `dataset-query@1`。某个查询由企业 MCP 工具实现，另一个可以是本地连接器；返回值都转换成同一结构化数据与元数据协议。
4. 若不能证明“增长率”就是要求的 GDP 增速，子任务返回 needs_input 和差异证据，不自行把两个字段视为等价。若已证明一致，则使用允许的 Join/单位处理工具生成快照与质量报告。
5. 子智能体提交候选 PreparedDataBundle，服务检查来源权限、快照、单位、行政代码匹配、处理链和检查器报告。主流程只采用通过验收的数据角色与证据。
6. MapPlan 记录采用的知识、数据包和工具绑定；预览、G2 与冻结仍由同一主流程完成。正式 QGIS 渲染读取固定输入，不再次让子智能体重新选择来源。

若输入本来就是已确认字段和口径的单个 GeoPackage，相同接口使用 deterministic 模式即可，不启动子智能体、不强行调用 MCP。若现有固定知识证据有效，也不要求重复在线检索。

该联合验收至少验证：工具切换不改变业务语义、知识冲突不被静默拼接、子智能体无法扩大来源和权限、模型自报成功不能通过数据验收、远程结果固定后可在许可内离线重放。源访问撤回或强制标准更新时，即使旧数据包存在也必须按当前政策重新判断可执行性。

上述例子共同验证：领域知识辅助理解与专业判断，MCP 等方式接入工具和数据，数据准备服务交付可验证产物，契约约束执行，实例锁与校验保障结果。模板创建与地图生成共享协议和工具能力，但不共享审批结果或混用生命周期。
